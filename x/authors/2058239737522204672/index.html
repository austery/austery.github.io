哇，这篇文章写得真好！想搞懂 Agent、Harness和 Post Train到底怎么连起来，一定要读这篇最终指南，我认真读了一遍，收获很大 《The ultimate guide to multi-harness RL》讲了一个很实际的问题：同一个模型，为什么放进 不同的 Harness, Claude Code、Codex、OpenCode，表现会差这么多？又该怎么训练，让它在不同框架里都能更好地完成任务？ 看完你能搞懂这几件事： 1/ 模型、Agent、Harness、RL 环境到底是什么关系。 Harness 就是模型外面负责组织上下文、执行工具、控制任务流程的那层程序。它改变了模型能看到什么、能做什么，也就改变了最终表现 为什么只在一个框架里训练，换个框架就可能出问题。 模型可能记住了某套工具名称、参数格式和重试规则。换个地方，连工具都调用不对，原本会做的任务也做不好 2/ 怎么让真实的 Agent 框架接上 RL 训练。 文章把 OpenEnv、Harbor、TRL 怎么配合讲得很细：任务在哪里跑，模型生成的数据怎么记录，最后怎样变成训练样本。连“为什么不能只存聊天文本，还要保留原始 token 和生成概率”这种容易忽略的细节都解释了。 3/ 怎样同时训练“做对”和“少走弯路”。 奖励怎么设计，怎样鼓励模型做对任务又少调用工具，以及模仿大模型的 SFT 和根据自身尝试学习的 RL，在这组实验里有什么区别。 文中有个很直观的实验结果：在 SmolDataEnvs 数据分析测试中，2.6B 的小模型经过四种框架联合 RL 训练，平均任务成功率从 42.2% 提升到 54.2%；在训练前后都做对的任务上，工具调用减少了约 31%。 我最喜欢的是它的讲法：先把概念讲明白，再用交互图一步步展示一次任务怎么跑完、数据怎么送进训练，后面还有代码和实验对照。想把 Agent 和 RL 真正串起来理解，这篇很值得收藏慢慢看

Post-training 一个很实际的目标，就是让小模型在某个特定场景，把业务做好、做便宜。 这是我相当看好的方向。 那硅谷工业界已经在做什么？了解这些，对我们选方向、做项目都有指导意义。这次挑了 6 家我觉得很值得关注的公司 它们代表了后训练及相关工具的几条前沿方向，业务有重叠，但各有侧重。 1. Thinking Machines Lab / Tinker：把训练基础设施交给平台 你自己写训练逻辑，Tinker 通过 API 帮你完成计算、更新模型和保存进度，省掉管理 GPU 集群的工作。比如 Glean 用它训练了专门负责找资料的 Waldo，再把资料交给大模型组织答案。 官网：https://t.co/eYez2wKnnb Glean 案例：https://t.co/mtzNRX1x4n 2. Fireworks AI：把训练到上线的工程流程接起来 它把模型训练和上线运行放在同一个平台，还提供接入 coding agent 的工具，帮你研究训练方法、估成本、启动实验和排查失败。适合希望把训练、调试和部署连起来的团队。 官网：https://t.co/JN2HVA2jwB 训练 Agent Skills：https://t.co/zSdTmGwt29 3. Prime Intellect：让模型在任务里反复尝试、打分、学习 你提供任务、可调用的工具和评分规则，它把模型尝试、评测和强化学习训练的过程跑起来。比如 Ramp 用它训练 FastAsk，专门学习在财务表格里找对单元格、调用 Python 算数，供主 agent 使用。 官网：https://t.co/zR6ypAWyXb Ramp 案例：https://t.co/mbG4WNK70u 4. Osmosis：工程师和客户一起把模型练出来 如果你连训练目标、reward 怎么设计都拿不准，它会派工程师和你一起把业务问题变成训练任务，再完成训练和上线。它提供的是 平台加专业人员交付，客户买到的也包括训练经验。 官网：https://t.co/LPsBaFpytz 5. Bespoke Labs：给 AI 搭接近真实工作的训练环境 它给模型实验室和企业搭建包含真实代码库、微服务、多步骤工作流的训练环境，让 agent 有地方练习实际工作。它更关注 模型拿什么练、怎么验收，这些环境和配套基础设施就是它提供的产品。 官网：https://t.co/kV3DIljqii 6. Weco：让 AI 自动改方案、跑实验、比较结果 你给它代码和衡量效果的评测脚本，它用大模型加树搜索，反复修改、测试，继续尝试更有希望的方案。它自动化的是 做实验这件事，改进对象可以是 prompt、算法或训练代码，未必需要训练模型权重。 官网：https://t.co/11s9v7JEZU 工作方式：https://t.co/io1nWTSQog 我觉得对个人和小团队的启示很直接：先找到自己懂的具体场景，把“怎样才算做好”定义清楚，再借这些工具验证，能不能做得更好、更便宜

我非常推荐大家收藏斯坦福今年秋季这门课：MS&E 319：Efficient Generative Language Models（高效生成式语言模型） 这门课会从预训练一路讲到推理和后训练。（我最喜欢的部分）课程资料和录屏后面会同步上传 我很喜欢它的出发点：模型越做越大，但预算总有上限。给定一个具体想实现的效果，手里的算力又有限，训练目标怎么定、模型架构怎么选、推理怎么跑，才能把钱花得更值，避免所有任务都用最贵的模型 GPT6 “再买点 GPU”当然是一种办法，也是现在市场的主流 有关于 MoE、attention与 KV Cache 压缩、量化、投机解码，以及 LoRA、RLHF、DPO、蒸馏，都会涉及。这门课把平时分散看到的这些技术，放回同一个问题里理解：它到底省了哪部分计算、显存或时间，又付出了什么代价？ 比如，同样是想降低模型的使用成本，有的办法让每次只调用一部分参数，有的减少需要存储和搬运的数据，有的加快生成答案。先把各自解决的问题分清楚，才知道手里的任务适合用哪一种，哪些方法还能配合起来用。 我自己看 AI 公司，也很关心这一层：同样一笔预算，能不能训练出更好的模型，或者服务更多用户。把这些技术背后的取舍弄懂，再看模型发布和成本变化，判断会具体很多。 这门课有一定门槛，感兴趣的一定要关注

的制造、堆叠和测试，仍然要靠供应链完成。 开始深入对内存墙的定义，这是一个重要转变真正值得存储股东留意的，是客户$NVDA 看完这篇，你可以带走三件事： 看懂 NVHBM 是一种什么样的技术？ 到底搬了哪块电路，以及它和 zHBM 有什么不同。 分清这件事情带来的 出货增长、市场份额和毛利润，避免把行业热闹当成每家公司都受益 理解 散热、测试和良率，为什么可能成为下一轮客户愿意付钱的能力。 我的判断：HBM 的重要性没有下降，但利润会更取决于厂商实际承担了什么工作，以及能把它做得多好，会存在重新分配 01｜先拆开 HBM：数据究竟怎么送到 GPU？ 先记住两个指标。容量，是能放多少数据；带宽，是每秒能搬多少数据。 内存装得更大，并不等于每秒能送得更快。 GPU 负责计算。模型参数、计算过程中的临时数据，需要从内存送进去。数据送得不够快，计算电路就得等，这就是“内存墙”的一部分。 HBM 的办法，是把多层很薄的 DRAM 芯片叠起来，用密集的通路传数据。DRAM 就是计算时使用的工作内存。 从上往下拆，一摞 HBM 主要能看到： DRAM 层：保存数据。 底座芯片（base die）：承接连接、测试和相应的逻辑功能。 封装连接结构：把这一摞内存接到计算芯片。 图 1｜HBM 在 GPU 旁边。中介层位于两者下方，承担横向连接；它不是竖着夹在两块芯片之间的一堵墙。图中层数和间距仅为示意。 还差两块电路。内存控制器安排什么时候读写、怎样调度；PHY 接口电路负责真正收发电信号。 标准 HBM 系统中，计算芯片一侧有控制器和接口，内存一侧也需要相应接口。传输要求越高，接口的面积、功耗和信号质量就越需要精打细算。 计算芯片的面积很贵。分给内存管理和连接的面积增加，就会与计算、缓存等功能争夺空间。 于是工程师开始问：能不能把一部分功能，搬到 HBM 的底座里？ 02｜NVHBM：控制器搬家，设计分工也跟着变 英伟达的做法，是把自己设计的内存控制器放进 HBM 底座，并重新优化两边的连接方式。 这里搬的是电路功能。内存仍然可以放在计算芯片旁边 图 2｜标准 HBM 与 NVHBM 的简化对比。绿色区域突出控制器的位置变化；计算芯片仍需通信电路。此图不代表完整的 NVIDIA 电路布局。 对比标准 HBM4E，英伟达披露的方案指标包括： 每摞内存带宽，最高增加 30%。 HBM 功耗，最高降低 15%。 为主计算芯片释放更多可用于计算的面积。 NVIDIA 技术说明 美光在 2025 年 9 月的财报演示中也表达过预期：带定制底座的 HBM4E，毛利率有望高于标准产品。这是当时的产品预期，不是已经披露的 NVHBM 合同利润。美光 FY25 Q4 现在，平台提供共同方案，客户有机会少做一部分重复设计，供应商之间也更容易比较。 图纸趋同之后，谁能持续交出合格产品，谁才有继续谈价的底气。 “共同方案”不会让三家的制造能力瞬间一样。良率，也就是最终合格产品的比例，仍然可能差很多；功耗、可靠性、交付和成本也不会自动拉平。 所以我的判断是：独有设计带来的溢价可能承压，制造能力的重要性会上升。 这还不能推导出 HBM 立即变成低利润产品，更不能推导出定制设计收入全部消失。 03｜行业多卖三成，一家公司也可能几乎没多赚 一家内存厂的 HBM 毛利润，可以先拆成一条简单的关系： 行业出货量 × 厂商份额 × 每摞毛利润。 这是理解竞争的入口。NVHBM 可能影响份额，也可能影响单位收益； 现实里的最新参照，是 Counterpoint 9 月 1 日公布的二季度 HBM 收入份额：海力士 50%、三星 33%、美光 18%。数字四舍五入后相加为 101%。Counterpoint 份额 这里有两个不能跳过的区别：这是收入份额，不是摞数份额；这是二季度数据，早于 8 月 26 日 NVHBM 公布，不能拿它证明 NVHBM 已经造成份额变化。 对海力士，要看领先优势能否守住；对三星和美光，要看能否通过验证、拿到新增订单。追赶者有机会，不等于追赶者一定赢。 04｜云厂商自己做芯片，英伟达仍可能有生意 公告里一个很有意思的细节是：首个 NVHBM 合作者，是亚马逊的 Annapurna Labs，也就是参与开发 Trainium 的团队。NVIDIA 公告 一家云公司自己设计计算芯片，并不意味着它要把内存、互连、服务器和机柜也全部重做一遍。 英伟达的 NVLink Fusion，就是让客户自研芯片接入其互连和机柜级系统的一套合作体系。NVHBM 又把合作范围延伸到了内存。 图 4｜自研计算芯片、内存与互连、机柜是不同层次的工作。客户可以选择合作，也可以自己做；图中为通用系统概念，不对应某款 Trainium 服务器。 亚马逊此前已宣布从 Trainium4 开始支持 NVLink Fusion。这与“Trainium4 已经批量采用 NVHBM”是两件事，不能混读 你品一下这个商业关系：客户即使自己设计计算芯片，周围的连接和系统能力，仍然可能来自英伟达。 对内存厂来说，客户也会有不同选择： 采用平台共同方案：普通 HBM 进行更深的独立定制：NVHBM，或者其他类似产品 05｜再往前一步：内存从旁边，叠到计算芯片上方 NVHBM 调整的是控制器与接口分工。另一条更远的路线，直接改变内存和计算芯片的位置。 三星在 FMS 2026 展示的 zHBM，把内存从处理器旁边搬到上方。技术资料也把这一大类方向称为 Memory-on-Logic，直译就是“内存在上，逻辑芯片在下”。三星 zHBM 图 5｜并排布局的数据要经过横向连接；上下布局探索更短、更密的垂直通路。右图是架构方向，不是 NVHBM 的另一种写法，也不是已经确认量产的产品。 这个变化不只是“多叠几层”。传统 HBM 本来就有很多层内存；新方向进一步把内存与负责计算的逻辑芯片叠到一起。 距离缩短，有机会降低传输开销、提高连接密度。但是否真的更划算，还得把散热、供电、测试和报废一起算。 三星特别强调，自己同时具备内存、晶圆代工和先进封装能力。这让它有机会承接更多环节，却不保证每个环节都能赚钱。 06｜混合铜键合：两块芯片怎样贴得更紧？ 三星在这块儿有自己独到的知识积累。提到两项支撑技术：混合铜键合，以及把多个晶圆结合成整体的多晶圆键合。三星 zHBM 先看连接处。传统微凸点连接，要通过很小的焊料连接点把芯片接起来，层与层之间会留出相应的高度。 混合键合则让铜点对铜点、绝缘层对绝缘层精密对准并结合。两种材料一起完成结合，所以叫“混合”。NIST 混合键合 图 6｜连接界面的放大概念图。右侧铜点嵌在平整的绝缘层内，连接处不用传统焊球；并不意味着整颗封装的所有位置都不再需要焊料。 这听起来像“贴得紧一点”，实际很难。表面不够平、残留一粒污染物、位置对不准，都可能影响连接质量。 也正因为如此，能做出展示样品，和能每天稳定大量生产，是两道不同的门槛。 07｜三星和海力士，都在推进这个方向 三星的 zHBM 是一个明确的上下集成方向。9 月 1 日 SEMICON Taiwan 前期论坛的相关报道，又补充了时间线。 按 TrendForce 汇总的报道，三星 HBM5 量产预期约在 2028 年；zHBM 的推出则被放在 2029 年以后。这些是路线图与报道口径，不能写成已兑现的交付承诺。三星路线图报道 SK 海力士在 4 月的台积电技术研讨会上，展示了标准 HBM、定制 HBM、HBF，以及 3D 堆叠 DRAM on Logic 等方向。 它希望从“供应商”走向参与架构设计的“创作者”。这里的 HBF 是高带宽闪存方向，之前我们也聊到过。海力士技术研讨会 图 7｜不同公司的节点与应用方向并列展示，不代表同一产品依次升级。HBM5 在不同厂商和研究机构的时间表里也可能不同。 按 Hot Chips 2026 的现场报道，海力士认为混合键合赶不上 HBM4E，最早要看 HBM5，并展示了 20 层的混合键合样品。Counterpoint 对大规模采用的估计在 2029—2030 年。Hot Chips 报道 08｜NVHBM 改了规则，三家内存厂和台积电怎么赚钱？ 英伟达对 NVHBM 的安排，有一句话特别值得存储股东留意：建立一套共同实现方案，由多家内存厂商供货，减少客户适配和验证不同供应商的工作。NVIDIA 公告 这意味着，客户有机会获得更多采购选择。我的判断是，三家内存厂仍然能靠制造、堆叠和交付赚钱，但独有设计能留下多少溢价、客户更容易换供应商之后还能赚多少，需要重新算。 三星：机会在于进入更多采购名单 假如过去客户已经围绕某家供应商做了大量适配，即使三星愿意供货，客户也未必愿意重新投入开发和验证。 NVHBM 的共同方案，有机会减少其中一部分重复工作。对希望争取更多订单的厂商，这是一个值得重视的入口。 但共同方案只能减少适配负担，不能替三星解决良率、功耗和可靠性问题。客户更容易比较供应商，也就更容易比较谁做得不够好 所以，对三星我会看：有没有通过具体客户的验证，拿到了多少采购份额，以及这些订单能不能在合格率和成本达标的情况下交出去 SK 海力士：要证明客户有得选，仍然愿意选自己 海力士是现有 HBM 市场的领先者。Counterpoint 的二季度收入份额仍将它列在第一位。Counterpoint 数据 NVHBM 对领先者提出的问题是：如果客户适配第二家、第三家供应商变得更容易，原有订单还能守住多少？ 这不意味着海力士的经验失去价值。相同的方案，交给不同工厂，合格率、交付稳定性和成本仍然可能不同 如果海力士能让客户少遇到坏件、少耽误整机交付，即使客户拥有其他选择，也可能继续优先采购它的产品。 它要守住的，是“用了以后更省心、更划算”的优势，以及这种优势能支撑的价格。 美光：多拿订单的机会，要和每摞少赚的压力一起算 对美光来说，共同方案同样可能减少进入新客户体系的适配工作。但这件事有两面。 一面是，新客户采用 NVHBM 后，美光有机会争取更多订单；另一面是，多家供应商提供可比较的产品，客户谈价时也会更有底气。 所以，美光的受益逻辑要算的是：新增销量带来的毛利润，能否超过价格压力和扩产投入带来的成本 如果多卖了不少，但每摞赚得更少，还需要投入更多设备和研发，收入增长就未必能等比例变成股东回报。 台积电：关键是 NVHBM 的底座由谁制造 NVHBM 把英伟达设计的内存控制器放进 HBM 底座。这里必须分清：谁设计电路，和谁把电路制造出来，是两份工作。NVIDIA 技术说明 如果具体产品采用台积电的逻辑工艺制造底座，台积电就可能承接相应的晶圆代工业务。美光此前已披露标准和定制 HBM4E 底座与台积电合作，但这不能直接当作全部 NVHBM 订单的归属证明。美光 FY25 Q4 对台积电，要继续看具体产品采用什么工艺、底座面积多大、出货多少，以及最终承担哪些制造环节。 09｜接下来，哪些信号会真正改变我的判断？ NVHBM 已经把方向摆出来了：英伟达进一步参与内存方案的定义，希望让客户更容易采用多家供应商的产品。 接下来，我会沿着这条线，追到实际订单和利润。 第一，多家供货，到底有没有落地？ 我要看哪家内存厂通过了具体客户的验证，什么时候开始量产交付，以及客户有没有真的把订单分给第二家、第三家。 如果共同方案推出了，实际供货仍集中在少数厂商手里，就说明制造和验证的门槛依然很高。原有供应商的优势，也可能比预想中更牢。 第二，客户更容易换供应商之后，价格怎么谈？ 如果厂商为了争取订单，需要给出更低的价格，就要看良率提升、成本下降和销量增长，能不能补回来。 同样是多卖一摞 HBM，留下多少毛利润，比“多卖了”本身更重要。 第三，NVHBM 有没有带来新的客户和需求？ 我要看自研 AI 芯片的客户，是否因为接入更方便，真正采用了 NVHBM，并扩大部署。 这里要分清两种增长：一种是客户原本就要买这些内存，只是换了方案或供应商；另一种是新方案让更多项目能够落地，带来了额外采购。 前一种主要改变订单分配，后一种才可能扩大整体市场。两者对三家内存厂的意义不同。 第四，为了拿到这些订单，厂商先付出了多少？ 开发、验证、设备和产能都要投入。订单增长得快，如果前期花钱更多、量产爬坡更慢，现金回报也可能晚于收入增长。 所以我会把新增毛利润和新增投入放在一起看。客户愿意采购，只是这门生意的开始；能否收回投入，才决定它值不值得做。 第五，可靠性优势，能不能变成客户愿意付的钱？ 如果一家厂商能让客户少遇到故障、减少返工、按时完成整机交付，这种能力就有价值。 但价值最终以什么形式兑现，还要看合同：是更高的售价、更稳定的采购份额，还是更长的合作关系？供应商又承担了多少保修和赔偿责任？
