  • 模型越聪明，越容易在代码里的一行旧注释上内耗 yage.ai 2026-11-11
    文章探讨了模型越聪明反而越容易在代码中的旧注释上产生内耗的问题。研究发现，在模型能力增强后，模型倾向于将旧的TODO注释视为需要解决的任务线索，从而引发不必要的代码搜索和修改，导致计算资源消耗增加。文章分析了人类工程师和大型模型在阅读源码时的视角差异，以及模型在强化学习中对“遇到阻碍时主动搜集线索”的奖励机制。文章提出了两条规矩来解决这个问题：一是为模型设定执行边界，明确源码中的TODO和FIXME注释属于只读历史背景，禁止在无明确要求下进行跨文件搜索或修改；二是建议人类工程师将注释中包含的保命警告和待办事项彻底分家，使用不同的标记（如WARNING: 或 NOTE: 和 TODO:），以实现对假便签的清理。

    高盛和苹果等大型机构正在重新评估AI编程工具的使用权限和算力配额。此前，公司曾尝试允许业务人员使用AI工具（如Claude Code）直接生成原型，但最终收回了权限，将高权限工具和充足算力分配给具备代码审计能力的工程师和量化策略师。这种分工模式旨在解决业务人员快速原型生成与工程团队验证、审计和线上故障排查之间的效率和风险问题。同时，苹果正在根据岗位价值对不同团队设置差异化的算力配额，以实现资源分配的精简和成本控制。
  • 把 AI 扔进真实工位连干 8 小时后，比跑分更管用的六个工程教训 yage.ai 2026-11-07
    文章通过对独立研究机构 GDPx 真实工作环境评测报告的分析，指出在真实工作环境中，大型语言模型（LLM）的实际表现与跑分分数存在巨大差异。文章总结了在处理真实业务问题时遇到的六个工程教训：一是需要定义权威度地图来管理知识库，避免混淆权威信息源；二是必须在工作流中加入样本外回滚门禁，防止智能体盲目修改代码或策略；三是面对模型感官盲区，需要要求其先写确定性的测量校验脚本；四是长程排障时，关键证据需要记录到外部证据账本，而非依赖模型记忆；五是测试时应先检查测试环境配置和判分脚本的有效性；六是模型路由时应核算单任务总输出量乘以单价的综合账单，以决定使用次旗舰还是旗舰模型。

  • 连模拟器都算不出的新药，Claude 是怎么靠换题、修 Bug 和当项目经理做出来的？ yage.ai 2026-10-29

  • 自建大模型：多卡为什么卡，以及为什么还是比 API 贵 yage.ai 2026-10-16
    文章讨论了自建多卡大模型推理的性能瓶颈和成本问题。核心观点是，多卡并行时，性能受限于任务调度（routing）机制，即如何平衡缓存亲和性（cache affinity）和负载均衡（load balancing）。个人玩家在缺乏底层调度器和实时状态监控的情况下，难以实现最优的资源分配，导致资源利用率低，最终自建的单位成本（按token计费）往往高于使用云端API。
