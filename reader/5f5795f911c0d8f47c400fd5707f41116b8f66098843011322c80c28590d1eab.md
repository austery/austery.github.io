### 智能商业：从“人机协同”迈向“自主购物”

在数字经济的新纪元中，**智能商业**（Agentic Commerce：AI 代理辅助或代替人类进行决策和交易的商业模式）正在重新定义消费者的购物旅程。当前，在主流 AI 助手（如 ChatGPT 和 Google Gemini）的所有用户会话中，有高达 45% 的交互与购物直接相关。虽然目前的生态仍处于**人机协同**（Human-in-the-loop）阶段，但行业的终极愿景是实现完全的**自主购物**（Autonomous Shopping）。在这一图景下，消费者只需向其个人代理表达消费意图，代理便会自动寻找商家、沟通谈判、核对会员权益、自动讲价并最终安全地完成支付与交付。

### 告别浏览器模拟：基于 API 协议的标准直连

早期的智能购物自动化尝试主要依赖浏览器插件（如 Cloud Chrome 插件或 Atlas）来模拟人类行为——读取 DOM 树、截屏并尝试自动填写表单。然而，由于商家端的工程团队通常会部署严密的防爬虫与防欺诈机制，AI 模拟浏览器的行为往往会触发安全警报，从而直接卡死在支付环节。
为了打破这一僵局，行业开始推行标准化的商业协议。Google 推出了**通用商业协议**（Universal Commerce Protocol: UCP），而 OpenAI 则主导了 **ACP**（Agentic Commerce Protocol）。这些协议规定了标准的通信接口，使 AI 代理能够绕过浏览器，直接调用商家的结账 API。随着微软在英国支持通过 Copilot 购买雷朋眼镜，Meta 推广其 Meta Shop，以及 Grok 与 GoPuff 的联手，智能商业正从一个脆弱的技术方案演变为到 2030 年预计达 650 亿美元的标准化庞大产业。

### 解析智能商业技术栈：MCP, A2A, 与 AP2

智能商业的落地依赖于一整套协议栈的协同工作：
*   **模型上下文协议**（Model Context Protocol: MCP）：AI 代理发现并调用外部工具的标准。通过 MCP 工具调用，代理得以执行具体的商品检索、折扣计算和结账会话创建。
*   **代理间通信**（Agent-to-Agent: A2A）：规范不同实体代理（如消费者的“买方代理”与商家的“卖方代理”）之间如何进行对话和任务委派。
*   **商品数据饲料**（Product Feed: 包含商品规格、价格与库存等信息的结构化数据源）：由于多商家实时查询会导致极高的延迟与计算负担，当前的 UCP 与 ACP 均要求商家将 Feed 提前推送给大模型厂商进行索引，从而加速离线检索与商品排行。
*   **智能支付协议**（Agentic Payment Protocol: AP2）：作为 UCP 的重要安全延伸，AP2 规范了自主交易中的授权机制。它能够明确代理获得了谁的授权、允许购买何种商品、最大单次/累计交易额度，并提供撤销授权的 URL，从而保证了支付链条的安全受控。

### 实战演练与评估（Evals）：告别“打地鼠”的无序开发

在基于橘色虎斑猫 Ginny 的烘焙店代理演示中，通过整合 Cerebras 推理平台，实现了每秒 3000 个 Token 的低延迟交易体验。用户代理与商家代理通过 A2A 标准握手，利用 MCP 调用商品检索，并在没有跳转浏览器的情况下，完成了结账与 AP2 的支付授权。
在此过程中，我们得到的最大启示是：**缺少评估（Evals）的 AI 交互开发，完全是一场痛苦的“打地鼠”（Whack-a-mole）游戏**。以 Chipotle 智能代理为例，如果不对大模型的系统提示词与输入输出设置严格的边界评估，用户很容易通过各种提示词注入将商家的点单客服当成免费的编程助手来白嫖云端算力。此外，代理还可能会在没有防备的情况下泄漏内部优惠码，甚至泄漏其他正在结账的用户的敏感信息。为了确保安全上产，团队必须构建全方位的评估框架，覆盖**行为评估**、**协议一致性**以及**延迟基准测试**，并在此基础上推荐引入“大模型作为裁判”（LLM-as-a-judge）的质量监控体系。
