### 业务定制与工作流架构设计

**[Speaker 1]**: 刚才你提到的你在公司搭的这个自动化流程里边，这个框架能稍微展开一下？这个框架你指的具体是什么？

**[Speaker 0]**: 框架的话基本上也是一个流程嘛。先是跟公司相关的业务了解到他们这个业务具体在做些什么，他们有些什么东西想要把它自动化，然后根据这个方面需要自动化的内容呢可能采用不同的架构。说得比较 engineering 一点的话，考虑怎么样把这个数据和相关的数据 knowledge 以怎样的方式把它保存下来，然后尝试寻找整个流程过程当中是否有那种 standard operation，然后把它可能转化成类似于 skill 或者一系列的 skill 的这种方式。然后最后的话可能要建立相关的一些 evaluation 的一些标准，然后来把这些东西最后有个闭环，然后让它可以至少迭代几次再输出给用户，而不是说一个 feed-forward 的一个系统。然后另外的话可能就是一些数据接口啊、信息安全也是要考虑的。

**[Speaker 1]**: 就你说那个 evaluation 那个环节，因为我看你发的那个视频里边你有三个框架，就是怎么样去充分的去自动化 AI 的这个流程，然后给他设置一些成功的标准，然后最终有一些验证还有 evaluation 的这个步骤需要有。这个过程中有多少是你自己去设定这个标准，然后有多少是 AI 自动帮你去设定的这个标准？就大概他这个比例是什么样的，或者有没有一个具体的例子可以举一下？

**[Speaker 0]**: 这个标准基本上都是跟行业专家一起设计的，跟行业专家一起讨论，然后交流清楚你要做的这件事情。首先我们自己得非常熟悉要做的这件事情。一般这件事情做出来呢，就是比如说我非常熟悉 AI 的架构，我知道怎么把这个事情用 AI 来搭出来，但做这件事情呢一般肯定是配上专门做这个事情的专业人士，他知道这个事情现在就是怎么评估的，或者他的 deliverable 有哪些要求，然后是跟他一起讨论，然后定下来这个事情什么东西比较重要，应该看哪些内容，然后什么东西可能并没有那么重要。在我了解清楚之后呢，我用语言把这个表达出来，然后再通过 AI 呢把这个东西以比较好的方式融进到这个 evaluation 的这一个环节当中。当然融进去的这个过程当中呢，可能就是我跟 AI 相互之间几轮的一些确认。

**[Speaker 2]**: 嗯，你提到这个里面有一点很有意思，就是那些专家，就是他们自己不会去找 AI 去搭这个架构吗？还是说就是一定要……就感觉你已经是公司里的 AI 小能手了，大家都会来找你来做这么一件事？

**[Speaker 0]**: 对对啊，现在是这样子。因为他们知道 AI 很好用，但他们只能用一些市面上已有的一些 AI 工具。但是对于很多公司业务来说的话，既然能够很深入的定制，为什么一定要用通用的方式呢？因为可以很深入的定制的话，它的优化的空间就会大很多。

**[Speaker 2]**: 嗯，石同学能跟听众介绍一下，就是你说的定制大概是用 AI……就是怎么使用 AI？你是怎么使用 AI 的？

**[Speaker 0]**: 定制的话，我的意思可能指的就是根据我们现在已有的业务线，然后根据我们的实际情况、实际输入、实际的知识内容、实际的一些感兴趣的内容，然后来建立 AI 的这么一个工作流程或者是这么 AI 的相关的系统来配合我们工作，或者来帮助我们、代替我们做一部分我们觉得现在可能不太愿意做或者是比较繁琐的一些工作，或者是我们觉得 AI 特别适合做的一些工作。这样的话我们可以把时间可以放到其他的内容上。因为它每个公司都是有它的历史积累出来的各种各样的一些价值观也好、评估方式也好，然后他们自己的局限也好，然后内容的输入输出的这些接口啊和人员啊都是不一样的，很难去找一个通用平台。以前的话就得学习这个通用平台，然后来调用这个通用平台的一定的能力，然后来帮助我们做一些工作，但现在可以手搓一个比较适合我们的。

### 复杂任务的拆解与闭环：以 3D 动画与 Loop 为例

**[Speaker 2]**: 可能我想就是站在很多人的角度来说吧，就是比如很多人使用 AI 就是有一些 UI 这么一个网页对吧，大概每天就是通过对话的方式。石同学是比较高级的玩家，你是通过怎样的一个手段去用你的 AI 让他定制化呢？你能举一个具体一点的例子，比如就拿可能你视频中来说，我比如想做一个比如说 3D 的动画，你会怎么去处理这么一件事？怎么拆解怎么动手？

**[Speaker 0]**: 一般来说的话，做 3D 动画吧，这个这个我还没做过，但如果我打算做的话我可能会这么来切入吧。首先我想要了解这个 3D 动画它的输入输出到底是些什么，我们已经有哪些素材，一般是什么样类型的素材，然后最后的输出期望一个什么样的……什么样的一个输出的方式。然后搞清楚这个之后呢，下一步呢就是说我可能会去看一下现在开源的市面上已经有哪些比较好用的一些流程或者 skill 或者一些相关的一些开源项目，大概了解到市面上已经做成一个什么样子的情况了，然后当然也可以看看有没有可以借鉴的东西、可以借鉴的方式。然后的话可能就是如果对一些比较简单的内容，如果市面上已经很成熟的方式的话可能直接就可以用了，然后可能只要稍稍调整一下输入输出，这样的话就能达到我们想要的这个最后的一个视频的内容了。然后如果社区里面的方案并不太满意的话，就可以找到哪些部分不太满意，然后这些部分不太满意的地方是否可以用一些流程把这个东西把它拆解到一系列的小的工作，然后让这些小的工作让 AI 可以比较好的高质量的完成，然后再通过一些类似于 skills 或者是其他的方式把这些被分解后的一块一块小工作给整合起来。然后最后一般来说我都是愿意给他做一个闭环的，就肯定要加一个 evaluator 或者是一个方式来评估这个东西做的怎么样。可能这个 evaluator 在各个阶段可能都会有一些小的闭环，这样保证它的输入输出会比较可靠一点，而不是我每次都是让人工来把这个 loop 给 close，特别烦。现在不是市面上很火的一个概念叫那个 loop engineering 嘛，它这个东西呢也是类似的概念，但它已经提供给用户一个比较好的……差不多是算参考设计吧。它是一个类似于一些 AI agent 一些架构，可以通过那些架构来完成一些比较重要的一些功能，比如说是 memory management 吧，然后做一些 subagent 啊。subagent 的话就是 context management 比较好。然后还有 skills 当然是已经说了很多遍了，就是它是一个比较好的承接一个 standard operation process 的一个载体。然后它提供了一个标准设计，差不多就是一个参考的一个架构，然后我们只要把我们想要的内容选择适合的架构，然后让这个架构里面的那些 element 做一些专门的工作，然后就可以把这个东西给拼出来。大概是这么一个想法吧，一个比较粗略的也是边说边想。

**[Speaker 1]**: 嗯，比如去找市面上开源的工具，应该不是你去搜，而是你告诉 AI，你是给他放权让他去随意去找对吧？

**[Speaker 0]**: 一般来说的话，我都是在开源社区搜嘛，然后一般就是 GitHub 的 community 里面搜嘛，然后大概就能看到了。那些几百 K star 的一些项目啊，现在有很多项目它都是做成一个 hub 一样的东西，它可以把一系列相关的功能的一些 skill 啊他们可能全部把它集结起来了。比较有名的可能有他们专门做那个 Go-to-Market marketing 的一个 skill 的一个 hub，那里面有一大堆各种各样 marketing 各方面的那个 skill。可能最有名的是 everything-claude-code 吧，它里面的 skill 的库就更全面了。各式各样它的网页里面可以看到各种工作各种类型它都有专门的 skill。就跟那个黑客帝国里面那个 Neo 拔插几个硬盘就能学会各种各样的武功一样。现在这个 skill 的市场已经非常丰富，很多工作其实都已经被打磨的非常好了。

### 交互模式选择：Agent Mode 与 Plan Mode

**[Speaker 1]**: 那回到刚才咱们说的第一个问题，就比如说像卢米提到的想做一个 3D 的动画这种，最开始的时候你是拿的有这样一个想法或者拿到一个这样的任务，你一般是怎么开始用 AI 去开始这个工作？

**[Speaker 0]**: 对，我一般用 agent mode，因为我感觉 plan mode 的话它很多东西它不能调用，它干脆……看看你现在你做调研的方式。这也是分不同的内容吧，因为有些内容比如说你做 coding 方面的一些内容，可能就可以调用一些比较成熟的一些 coding 的框架。像我之前视频里提到的那个 superpowers 啊，或者 GSD 啊，它里面都有专门跟用户讨论的这么一个环节的。它是跟用户讨论，然后来理解问题，帮用户把一个很抽象的问题拆解成一个可执行的一系列小问题，然后来搞清楚用户具体想要做成什么样子，如果用户不清楚的话。如果是用这种方式的话，可能 plan mode 不太能做吧。因为我一般都是用 agent mode 的，我比较少用 plan mode，只是用语言上来跟他说现在我们是在讨论。而且这样比较好的是，一般来说现在讨论的过程当中，最好也是把讨论的内容也可以比较好的可以把它固化下来，而不是讨论完这个内容只在这个 session 里面，下次开个 new session 这个内容又没了。所以我一般比较偏向于还是直接使用 agent mode。
