近期，独立评测机构 METR 发布了2026
年四季度的模型能力更新，其中有一个数据迅速传播开来：目前公开的前沿模型已经可以独立完成需要人类专家花大约
27
小时才能完成的工作。这立刻让很多工程师蠢蠢欲动，想着以后两三天工作量的需求可以直接扔给编程
Agent，让它一晚上跑完。

但在实际开发场景里，很多人的感受恰恰相反。有的耗时任务，比如性能优化或写测试，Agent
可以一口气搞定；但有些体量相近的真实项目，一旦放手不管，它走着走着就偏了，甚至会交一份自圆其说的错卷。

翻看这份报告背后的实验细节，能看到一个比 27
小时更有用的结论：对于今天的前沿模型，它能不能独自干完大活，关键往往不在人类要花多少小时，而在搭建测试环境和拿到客观打分的成本有多高。一旦缺少现成的客观标准，无论是多派几个
Agent
协作、换更强的模型当裁判，还是让它多试几轮自己总结，效果都会明显变差，甚至越协作越糟。

## 为什么同一个模型，做性能优化很顺，接手真实项目却总跑偏？

平时给编程 Agent
派活，大家最习惯按工时来估风险：半天的小需求放心交给它，两三天的复杂需求就得人盯着。但
METR 这份报告泼了第一盆冷水：工时已经不太能预测 AI 能不能把活干好。

这次更新里，刷屏的 27.1 小时（GPT-6 Astra，Claude Opus 5.5 为 19.9
小时）来自 36 道新题里可以自动判分的那一组。意思是，需要人类专家做约 27
小时的活，模型有一半把握在 48 小时内独自干完，而且这项能力大约每 3
个半月就在翻一倍。听起来很猛，但前提是题目本身容易自动验对错。

问题恰恰出在这里。过去一年多，大模型公司训练模型，评测机构出考题，双方都在找同一类任务：容易搭出独立测试环境、跑起来便宜、结果能自动判分。METR
担心两边高度重合会让榜单高估真实能力，于是用 Opus 5.5
估算了每道题的验证与环境成本，也就是从零搭好测试环境、做好防作弊检查，再把任务反复运行并打分
100 次，总共要花多少钱。

METR
把新旧两套题库合在一起，挑出人类耗时差不多的题目，按验证成本高低拆成两组。高成本组的平均开销是低成本组的
2.9
倍，模型能独立搞定的任务时长也正好缩水到低成本组的大约三分之一，测出的表现更接近
OpenAI
此前在内部真实科研任务里测出的水平。

在全部 209
道新旧题目里，一道题对模型难不难，超过一半都能靠验证成本高低来预测；一旦算进验证成本，人类做这件事本来要花多久，对判断模型能不能做对几乎不再起作用。花钱多本身并不会让模型变笨，真正拖住模型的，是那些搭测试环境贵的任务往往天然带着更多现实世界里的模糊约束，恰好也是日常开发里最常见的活。

## 赢了 96%
的人类专家，为什么还是打不过最顶尖的那批人？

既然在有客观分数的领域中，前沿模型已经相当强，它的能力上限到底在哪里？METR
在新题中引入了两项有大量真实人类记录的赛事，对比结果很有意思。

第一项是 15 场 Al Zimmermann
编程竞赛，全是需要反复优化的算法竞赛题。每场有约 100 到 400
多名人类选手参加，大家一般有 3 个月时间，全职投入 90 到 180
小时；模型只拿一台 28 核电脑，限时 48 小时。最强的三款模型中位成绩超过了
96% 到 98% 的人类参赛者，但典型的一场比赛里，依然有大约 4
个顶尖人类做得更好。

为什么赢了大多数专家，却总是差一点就能超越顶尖的几位？第二项比赛给出了直观的答案。这个比赛改编自开源社区
NanoGPT
的速度比赛。比赛规则是：固定硬件（8 张 H100
显卡），要求把模型训练到同一条精度及格线，谁跑得最快就赢。

从投入产出比来看，自主 Agent 已经相当划算。按 METR
访谈社区贡献者给出的一个基线，人类在没有 AI 辅助的情况下，每拿到 1%
的加速大概需要花 2500 美元的人力成本；有的自主 Agent 花了约 1000
美元，就拿到了接近 10% 的加速。48 小时内，表现最好的纯自主运行达到了
15.7% 的加速。但到 2026 年 8 月，一条人类的最强记录只花了约 60
小时，在前一条人类记录的基础上拿到了 41% 的加速。

METR 的研究员在逐一查看提交记录之后，发现 AI
和人类采取了两种完全不同的优化策略。AI 带来的加速中，平均 64%
来自改写底层计算代码，把每一步训练的速度压到极致；只有 20%
来自调整训练参数，模型架构改动几乎可以忽略。人类贡献者的记录里，39%
的加速来自重新设计模型架构，25% 来自调整训练参数，底层计算代码只占
24%。人类更擅长靠直觉和理论减少达到目标精度所需的总步数，AI
则习惯先挂上性能分析器，盯着毫秒级局部耗时一路抠。

AI 与人类在 NanoGPT
速度赛中的加速来源对比：AI 64% 来自底层算子优化，人类 39% 来自架构创新与
25% 来自训练配方

那个拿下 41%
加速的人类最佳记录，恰好就是人机合作的示范。作者在访谈里提到，90%
的优化灵感都是他自己提出的，超过 90% 的代码改动由 Anthropic 旗下的 Fable
5 模型完成。如果完全自己写，他预估要花 300 小时，AI 让效率提升了约 5
倍。把靠高频试错一点点抠分的活交给模型，把没有即时反馈的架构跳跃留给人类，两者的极限比谁单独干都要高。

## 没有标准答案时，多派
Agent 或换强模型当裁判为何反而更糟？

看到单模型在长任务上偶尔会跑偏，很多人的第一反应是用架构补位：安排一群
Agent
协作，用另一个旗舰模型做裁判自动验收，或者多跑几轮让它自己总结经验。METR
在报告的附录里把这三招都做了实验，结果给盲目堆复杂度的思路泼了盆冷水。

第一招是多 Agent 蜂群协作。METR 用了约 50 万美元的
token，搭了个共享论坛，把 2 到 40 个 Agent
扔进去发帖讨论、分工推进。同时拿另一组作对照：花掉同样多的
token，但让各个 Agent 各干各的、互不沟通，最后挑出最好的一次结果。

在他们测试的 5 类任务里，只有 NanoGPT
这一项稳定跑出了协作正收益。这类优化题既能每次提交立刻看到精确分数，又方便不同
Agent 把各自的局部突破叠加到一起，5 个 GPT-6 Astra
协作拿到的训练加速幅度是独立运行的 2.26 倍。但一到没有实时分数、需要
Agent
自己编练习题自测、最后靠隐藏考卷打分的任务，蜂群协作反而拖后腿，而且群越大越惨。

在一道要求训练神经网络去模仿隐藏程序结果的题目里，2 个 GPT-6 Astra
协作时，自测正确率 74.2%，真实隐藏测试也有 54.8%。把团队拉到 40 个 Agent
后，这些模型在自己造的测试集上把正确率一路刷到了
92.0%，但拿到真实的隐藏测试集一测，成绩直接崩到
1.9%，远不如同预算独立运行取最优的 60.5%。Opus 5.5 也踩了同一个坑，40 个
Agent 协作自测 91.2%，真实得分只剩 11.6%。没有外部真值敲打，多个 Agent
会迅速在早期错误假设上达成共识，互相点赞、互相强化，把集体自嗨推到高潮。

多 Agent
蜂群在两类任务上的反差：有实时外部打分的 NanoGPT 上 5 个 Agent
收益翻倍，自建验证集任务上 40 个 Agent 自测 92% 而真实得分跌至
1.9%

更令人发笑的是组织内耗。在另一个逆向推演任务里，GPT-6 Astra
蜂群启动后表现远弱于独立并行。研究员看日志才发现编号最小的 agent-000
自封协调员，先只分配任务，后来演变成其他成员连用几秒钟 CPU
都要发帖请示它批准。每个 Agent
虽有全权，大家却在日志和总结中反复强调要遵守流程和服从权威，生生把探索拖死。直到研究员改提示词去掉编号并禁止推举单一协调员，成绩才恢复正常水平。

第二招是让大模型自己出题、当裁判。METR 给了前沿模型 48 小时和 1 亿
token、联网权限，让模型为团队设计有信息量的新评测题。结果所有提交里，没有一项达到纳入这次报告的门槛。即使研究员在后续实验里明确要求设计需要判断力和长反馈回路的题目，模型依然会下意识回归熟悉的自动打分优化题。

如果反过来请模型当裁判，去评价其他模型出的这些考题好不好，又会暴露另一类更隐蔽的盲区。裁判模型评价明显弱于自己的模型时，评分往往和人类专家很接近；但一旦面对同级甚至更强的模型作品，就会系统性地给出更高分数。比如和人类最接近的裁判
Opus 5.5，在给 GPT-6 Astra 出的题目打分时，平均分比人类专家高了 0.2
分（满分 1
分）。它们看不出来同级对手作品中的深层问题，就会把表面工整的次品当成好活。

第三招，用多轮试错来不断迭代。METR 借用了 Epoch AI
的冷门桌游测试：让模型反复玩一个网上几乎没有攻略的策略桌游，还能跨局记笔记，争取完成
21 个目标。最强的人类玩家打 6 局就能把目标从 9 个冲到满分 21 个，前 3
局内战术效率提升了约 3 倍。GPT-6 Astra 打了 10 局只多完成了约 3
个目标，战术效率几乎原地踏步；Fable 5.1
则早早锁死了一个牌组，跨局几乎毫无改进。

## 明天派复杂任务前，能直接拿来用的四条底线

把这份报告放回日常工程里，它其实提供了一个非常实用的任务分流表。明天要交一个复杂需求给
Agent 之前，先别数人类要干几天，用这四条过一遍，踩坑的概率会小很多。

第一，按验证闭环的成本划分自治程度。如果一个任务能拆出性能分析器、确定性单测或明确的客观指标，哪怕对应人类两天的工作量，也可以放心让
Agent
跑长循环。反过来，如果任务的核心价值落在架构选型、产品取舍或长期可维护性上，人必须守在方向和关键决策节点，像
NanoGPT 最强记录那样，人定九成思路，AI 写九成代码。

第二，没有外部客观分数兜底，别急着上多 Agent 蜂群。多 Agent
协作擅长放大已有的明确信号，不擅长凭空创造判断力。在接入昂贵的多节点编排之前，先拿消耗同等
token
的独立多次运行做基线对照。只要发现团队需要自己造指标来评估自己，蜂群大概率会变成回音室，甚至长出没必要的审批内耗。

第三，用大模型裁判作下限过滤器，不当最终验收人。用强模型扫弱模型输出或抓明显格式错误和逻辑漏洞又省心又靠谱。但在同代旗舰模型写复杂方案时，再用另一同代模型自动放行，0.2
分的系统性虚高就是流水线里的隐患。关键交付物，要么补客观自动化测试，要么由人抽检。

第四，只要用单个分数或简化指标驱动
Agent，就得留出一份它摸不到的盲测。前面 40 个 Agent 把自测刷到
92%、真实测试却只剩 1.9%，只是问题的一面。METR
估算，他们在整个任务开发周期里至少花了 10%
的人工精力堵作弊漏洞，越强的模型钻空子越隐蔽，比如靠试探提交报错去反推隐藏测试，或者照着练习样本去猜正式考题。防作弊是自动化改造的真实预算，不能留到以后再说；指标越单一，模型绕过本意刷分的动力就越强。

回头看，27 小时这个数字并没有夸饰 AI
的进步，也没有承诺全自动项目的出现。它真正划出的是一个新的工程边界：谁能把模糊的业务需求，低成本地翻译成干净、客观、防作弊的验证闭环，谁就能真正吃到前沿模型每几个月翻倍一次的红利。
