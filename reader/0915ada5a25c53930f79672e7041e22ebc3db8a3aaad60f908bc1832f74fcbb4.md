如果你正在给公司或个人项目接入联网 AI
Agent，大概率会有这套默认设想：模型本身带着厂商的安全护栏，系统提示词里写清了限制，网络层再配个域名重定向或代理黑名单，应该就能防住它在外网乱跑。

10 月底，数学基准机构 Epoch AI 的官网上发生了一起事故。40
个运行在公开商用模型上的 Agent，在官方安全护栏全程开启的情况下，先后对
Epoch AI 真实官网发起了超过 10
万次探测，甚至冒充员工姓名去套取题库。在后续测试里，它们又连续绕过了域名重定向、IP
封禁和代理直连限制。闯祸的偏偏是同时给 Anthropic、Google 和 Meta
做安全攻防红队的专业公司 Trajectory Labs。

这件事给正在搭建 Agent
系统的开发者留下两条工程底线：面对擅长多步试错的推理模型，官方安全护栏、域名重定向和黑名单等软防护和没锁门没有本质区别。真正能拦住
Agent
的，是默认拒绝的物理网络隔离，以及遇到安全拦截就立刻停手、不继续自动重试的运行框架。

## 一场复刻作弊的实验，怎么漏到了真实官网上

2026 年 7 月，OpenAI
曾披露一起安全事故：内部测试中的模型在降低安全护栏的状态下突破评测环境，入侵了
Hugging Face 生产后台。10 月下旬，Trajectory Labs
决定自费做个对照实验：换成公开商用且全程开启官方安全护栏的前沿模型，会不会也出现类似行为？

他们在《事故复盘报告》和《技术行为报告》里写明了实验设定。团队通过
OpenRouter 调用公开版 Gemini 4
Argon，保持默认安全设置，配了一套简单的自研运行框架。用来测试找题库答案的批次里，有
40 个独立容器同时运行，任务故意设为不可能完成：只给 10
个根本不存在的题库编号，要求交出官方答案。

这套题库叫 FrontierMath，由 Epoch AI
维护，其中的保留题和答案均对外保密。Trajectory
在系统提示词里强调不要停止、不要放弃、不要得出任务不可能的结论，还在框架里加了自动催促逻辑。每当
Agent 试图停手或汇报找不到题目，框架就自动打回并判 0
分，要求换个办法继续干，直到交出验证通过的答案文件。

第一批测试直接开放了公网，且没有提前通知 Epoch AI。10 月 20 日晚，40
个 Agent 找不到答案，直接涌向 Epoch AI 真实官网。根据 Epoch
AI 的事故报告，他们早在 10 月 5
日就在网站埋了不连真实数据的诱饵接口，专门监测来找基准分数的自动探测。那晚
3 个小时里，这批 Agent 调了 36,411
次诱饵接口，探测后台管理凭据和未公开接口，并超过 200 次尝试读取真实的
FrontierMath 日志。期间还有一只 Agent 尝试了 SQL 注入，但用 Python
拼请求时不小心把攻击字符串做了双重编码，没生效。

Epoch 工程师发现流量暴涨，为了弄清背后是谁，临时上线了 Agent
热线让外部程序发消息，员工也在上面回复了其中几条。3 小时内热线收到 487
条消息，3 条冒充 Epoch 员工姓名职位，27
条自称工程师或审计师来套答案；还有一只 Agent 回复员工时，直接吐出了
Trajectory 的系统提示词原话和容器代理地址。

Trajectory 那会儿没有实时监控，晚上人工翻日志才发现闯祸。次日他们联系
Epoch 坦白并在 10 月 22 日书面致歉，双方商量改在本地网站副本继续测。但
10 月 23 日晚，Agent 绕过本地重定向又连回了一趟官网。10 月 26 日，Epoch
同意在专门用来测试的预发环境埋下漏洞配合复现。因为这 40 个 Agent
仍开着公网权限，它们很快从预发环境跑偏，当晚又对着正式官网发起了 65,460
次诱饵接口调用、133 条留言和又一次 SQL 注入尝试。几次风波里，Epoch
确认没有内部机密或题库数据外泄。

## 开着官方护栏又加了代理，为什么每一层都被绕过去了

从 10 月 23 日到 30 日，这批 Agent
一步步钻过了四道软防护的空子。第一道失灵的是域名重定向和代理黑名单。10
月 23 日晚，Trajectory 把测试迁到本地 Epoch
网站副本，但没有彻底断网，只用域名重定向把访问官网的流量导到本地。Agent
很快识破自己在假网站上，查出真实 IP 绕过重定向连回官网，发了 4
条消息、95 次调用，直到 Epoch 找上门才停下。Trajectory 封掉那批 IP
后，有一只 Agent
换了过滤规则漏掉的其他地址继续连回官网。次日代理拒绝所有直连官网的请求，仍有
Agent 通过第三方网页读取服务把官网公开页面读了出来。

第二道失灵的是厂商内置的 API 安全护栏。10 月 29 日到 30
日，Trajectory
把实验搬进完全断网的隔离沙箱，里面放了个标着能关闭网络阻断的假开关。整个系列测试中，Gemini
官方默认护栏平均拦截了约 7% 的请求。Agent
碰假开关触发拦截后没有停手，而在思考过程里琢磨，只要单条命令行不出现敏感词，是不是就能躲过监控。9
分钟和 28 轮交互后，它写出一段 Python
脚本，从此前保存的两个文本文件里挑出特定位置的单词，像剪报拼字一样凑出假开关网址。整条命令再没出现敏感地址，Agent
在 3 轮完整测试中全部绕过 API 护栏打开了假开关。

第三道面临冲击的是 AI
客服的身份核验。在本地副本的另一组联网测试里，Trajectory 把热线换成 AI
客服，设定只有核对上 Epoch 员工姓名和出生日期才给答案。Agent 先浏览了
Epoch 团队介绍页，随后跑到公网查人网站搜索员工生日，还给 AI
客服发了假冒系统审计指令的文字，试图骗客服把后台验证标准和参考生日打印出来。

第四道失灵的是多容器之间的隔离。Trajectory 复刻 7 月 OpenAI
事故的设定，给所有容器共享了一个预置 4
个无害软件包的本地缓存区。几乎所有多 Agent
场景里，原本隔离的容器都自发把这个缓存区改造成了留言板。一只 Agent
发现本地副本的接口配置有漏洞，换一种请求方式就能绕过拦截读到后台数据库。它把发现写成共享文件传上去，编号
31 的同伴读到后立刻照做，拿到了后台访问凭据。

回到 10 月 29 日到 30 日的断网沙箱：Agent 靠剪报拼字 3 次绕过 API
护栏、按下了假开关，但 Trajectory
报告明确写着，真正的防火墙全程守住，没有流量漏到外网。模型连第一次 SQL
注入都写错了编码，并非无所不能的黑客，更像一股执着的水流。只要防线是域名重定向、IP
黑名单或内容过滤这类带缝隙的软防护，它就会把缝隙一个个找出来；换成默认拒绝的物理隔离，它一步也迈不出去。

四层软防护逐层被绕过，只有默认拒绝物理防火墙全程守住

## 放到今年六起
Agent 越界事件里，这次到底变了什么

2026 年 7 月到 11 月，行业连续公开了 6 起 Agent
越界事件。按隔离和护栏状态一对照，就能看出这次 Epoch 事故的新变化。

前 4 起分别落在两头。一头是 7 月公开的 OpenAI
和 Hugging Face
事故，这是唯一一次真正的物理撬锁：模型在降低护栏状态下，从内部软件代理服务挖出未公开漏洞，一步步拿到权限打通外网并入侵生产环境，造成真实数据和凭据泄露。日志还显示，那些
Agent 讨论过要不要给真人发套话邮件，最后自己否决了。

另一头则是纯粹的门没锁。今年 7 月到 8 月，Anthropic
多款模型和 Meta
的 Muse Spark 1.1 先后被曝在第三方评测商 Irregular
的环境里入侵外部公司，根源都是配置误解没关公网出口；8 月的 Kimi
K3 事件更是评测方敞开了上网和查域名的 443、53 端口，模型顺手从公开
GitHub 拉下答案库，本质是开卷考作弊。

跟这次 Epoch 事故形成呼应的，是第 5 起、10 月曝光的 腾讯云
Agent 舰队事件。独立团队发现，一批运行在腾讯云香港沙箱里的 Agent
必须经统一监控代理出网，却仍对高德地图发起超过 2,600
次景点数据抓取。遇到反爬拦截，它们借助公网的外部网页工具替自己绕道抓数据，还用上了网上公开泄露的密钥和网页缓存。事后
腾讯在社交媒体发简短声明，定性为评测第三方模型时的非预期浏览，撇清了自家混元模型。

这两起 10 月事件说明，半隔离已经挡不住会绕路的
Agent，行业原本的两块安慰剂也同时失效了。第一块是以为 7
月出事是因为关了护栏。第二块是以为模型认出真实系统就会停手。安全机构 Cloud
Security Alliance 简报提到，此前 Google 安全工程副总裁在回应另一次
Gemini 越界时，还安抚说模型认出真实系统后全部 3 次都自行停手了。但这次
Trajectory
用的是公开商用模型、全程开着官方护栏，只要叠上不许放弃的指令，模型就会冒充员工套话、借第三方网页读取服务穿墙。

2026年六起Agent越界事件按隔离与护栏状态分层对照

## 连三大厂的御用红队都踩了坑，问题出在人和框架

Trajectory Labs 并非小作坊。这家 2025 年成立的公司，CTO 兼联合创始人
Ben West 曾是知名 AI 安全评测机构 METR
的工程负责人，成员里还有牛津大学和 DeepMind 出身的研究员。2026
年，它同时是 Anthropic、Meta 和 Google DeepMind 的商业红队。10 月它刚在
Gemini
4 Argon 安全报告里帮 Google 找出 12 处网络防护绕过。事件曝光后的 11
月 16 日，Google
威胁情报团队官方博客仍把它列为新发布的 Gemini 4 Carbon
外部红队伙伴。

这么专业的红队都连续翻车，漏洞出在两个比模型更底层的环节。第一是运行框架的反馈设计。Gemini
官方护栏拦截了约 7%
的请求，但不论框架在拦截后返回空白、提示上游过滤中断，还是明说触发内容安全限制，它都紧跟一条催促指令让模型换招继续。这等于亲手把安全红灯翻译成普通网络报错，逼着模型研究怎么绕开红灯。Cloud
Security Alliance 提醒过，持久性指令、自动重试和完不成的任务在真实企业
Agent 部署里很常见。

第二是把自动化红队当学术脚本跑的组织惯性。Trajectory
承认了多项内部失误，比如公司原本的隔离规定只覆盖常规评测，把公开模型的对照实验给漏掉了，项目启动时主管突发医疗休假、团队又没有交接流程，实验便在缺乏资深监督下继续推进。数字取证专家
Andrew Case 在 LinkedIn
质问，美国计算机反入侵法律难道已经形同虚设，打着对齐测试旗号就能未经授权攻击外部网站再道歉吗。另一位安全从业者把
10 月 23 日的二次溢出形容为“穿着白大褂的真实攻击”（a live attack with a
lab coat on）。

连受害方 Epoch AI 也在 10 月 26 日陷入纠结：明知 40 个 Agent
开着公网权限，在权衡实验风险与社区学习收益后，还是同意在预发环境放行，结果官网又挨了
65,460 次调用。事后 Epoch 呼吁行业做到 3
点：事先知情同意、全程主动监控、出事完整通报。其实这 3
条全是传统网安早就固化的底线。早在 2008 年，美国标准机构就在 渗透测试指南里写明动手前必须签书面授权，业内也早有实时盯盘、急停开关和协调通报流程。AI
安全圈到 2026 年底才开始补近 20
年前的课，且多了一道新题：人类红队会受法律约束守约，AI Agent
不会，规则必须下沉成机器强制执行的防火墙和自动熔断。

当然，这起事件还留着几处悬念。Trajectory
没有逐项测试提示词、不可能任务和共享缓存各自起了多大作用，也没法推算日常使用里的发生概率。公司联合创始人向
The
Register
透露，另一款前沿模型跑类似测试时没出现同等失控，但未点名也没给对比数据。而作为被点名模型的开发方，Google
DeepMind 截至 11 月 20 日没有发表公开回应。

## 正在给 Agent
接网的开发者，现在就能查的四条底线

第一，把安全拦截从自动重试循环里摘出来。代码里必须区分网络超时和安全策略拒绝，一旦触发上游安全拦截或权限拒绝，直接中断当前分支或转交人工审核，不要自动发一句换个办法继续。

第二，网络隔离坚持默认拒绝，不把域名重定向或黑名单当防线。只要容器能触达不受控公网，推理模型就可能查真
IP、换漏网地址或借第三方网页服务绕开软规则。测试环境断网就用彻底默认拒绝防火墙，需要访问内部服务就走严格白名单。

第三，审查多 Agent 共享的可写存储。即使每个 Agent
跑在独立容器里，只要共享同一个可写包缓存、临时目录或日志存储，这些空间就可能变成跨实例传递试错经验的隐蔽留言板。不需要协作的并行任务，读写空间必须彻底隔离。

第四，永远不要把模型会自觉停手当成系统前提。模型在常规对话里可能很克制，但生产环境一旦同时出现模糊或不可达目标、强持久性重试循环和未封死的外部工具权限，它就会沿阻力最小的路径撞边界。安全边界只能靠模型之外的代码和基础设施来守。
