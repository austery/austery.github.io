你可能听说过 UiPath，一家做 RPA 的公司。RPA
这门生意说白了：教电脑模仿人的鼠标键盘，替人跑那些跨系统的重复活，比如把发票从邮箱抄进财务系统。流程本身很死板，要靠人用专门的开发工具一点点搭出来，所以这家公司十几年靠两样东西收钱：按人头收费的开发工具，和流程跑起来之后的运行许可。

2026 年 8 月 19 日，UiPath 发布了 Maestro
Flow，一种新的流程文件格式加运行入口。公告里最扎眼的一条规则：Claude
Code、Cursor、Copilot、Codex 这些 AI
编程助手生成的流程文件，不用改一个字，直接进它的生产平台运行。

要体会这条规则的分量，得先知道一件事：在 RPA
世界里，写流程一直是收钱的大头。你想让电脑替你跑一条流程，先得有人用
UiPath
的开发工具把这条流程写出来，这工具按人头收年费，一间办公室一个开发者就是一份钱。这条收费线撑了它十几年。现在它宣布：写流程这步免费送人，AI
写多少条都不收钱，只在流程跑起来之后按次数收钱。

一家靠卖开发工具吃饭的公司，把写流程这步免费送给了别人家的
AI，看起来像亲手拆掉自己的第一根收入支柱。这篇文章讲这步棋的完整来路：它以前靠什么收钱，AI
撞掉了哪一段，它怎么一步步走到这里，以及为什么细算之下这笔账是通的。

生成免费后，收费点从工坊门口的建造环节搬到车流密集的运行环节

## 旧世界：从一张发票讲起

一家公司的应付账款专员每天花三小时录发票。传统 RPA
时代，这种活儿有一套固定做法。先在员工电脑上装个录制工具，静默跑两周，记下屏幕截图、鼠标点了哪里、键盘敲了什么。后台把这些记录聚成一张任务路径图，结论是录发票这个任务重复率最高，最划算，先自动化它。

然后咨询顾问进场，通常是四大或系统集成商里拿 UiPath
认证的开发者。他们在 Studio 这个类似 Visual Studio
的开发环境里拖流程图：盯收件箱、下载 PDF 附件、提取字段、切到 SAP
界面逐项填数、点保存。做出来的东西是一个 .xaml
文件，说白了是一份操作界面的脚本：找到编号 btnSave
的按钮，点它。用来定位界面元素的标签叫 selector。流程做完发布到服务端的
Orchestrator，由按 license 收费的 robot 在虚拟机里半夜重放这些点击。SAP
一升级，按钮改个名、页面挪个位置，selector
就断链，流程凌晨报错停下。以前这种故障只能等工程师第二天上班修，后来平台加了叫
Healing Agent 的 AI 自动修复。

传统自动化由录制发现、顾问拖图、机器人夜间重放三段工序组成

这套做法留下两个老毛病，记住它们，后面新引擎解决的正是这两个。第一个毛病出在等待：流程走到财务经理审批这一步，robot
要么占着 license
白等三天，要么开发者把流程硬拆成两段，前半段写完队列就退出，后半段定时去查审批结果，中间的数据对不对得上，全靠人在数据库里手工拼。审批本来是企业里最普通的环节，在旧架构里反而最容易出事。第二个毛病出在恢复：半夜跑到一半崩了，中间进度没存档，只能从头再来一遍。

收钱的路子，前面其实都露过脸了：Studio 按开发者人头收年费，robot 按
license
收。最肥的其实是第三样：咨询顾问帮企业把这套系统用起来的活儿，也就是前面说的拖流程图、修断链。这笔钱大头归咨询公司，不进
UiPath 的口袋。它自己财报里服务收入只占
3.9%，但正是这一圈顾问，把软件带进了一家家大企业。整个盘子最新一个季度（截至今年
4 月底）是 4.184 亿美元。

我们六月写过一篇文章，说自动化里值钱的部分正在从界面操作脚本挪到业务规则本身。当时
UiPath
产品线铺得最全，模块之间却各说各话。这次发布，算是把话统一起来了。

## 威胁来了，反应顺理成章

威胁说来也简单。coding agent 出现之后，在 Studio
里拖流程图这件事本身，AI
就能干：给它一段需求描述，整条自动化脚本直接写出来。写流程分文不花，靠开发者席位和顾问时薪撑起来的生意，一下没了收费的依据。UiPath
的 ARR 增速也一路掉到 12% 上下，停在那里。

它的应对分三步，每一步单看都是一家 RPA 公司的正常防守。2025 年 4
月，发布 Maestro
编排引擎，让它调度的不再只有 robot，还有 AI agent
和真人的审批环节，冲的就是前面那两个毛病。2026 年 5 月，发布 UiPath
for Coding Agents，让 Claude Code 和 Codex
带着企业的合规要求接进平台。2026 年 7 月底，RPA with Coding Agents
正式可用，coding agent 能直接产出传统的 .xaml 项目。

到这一步为止，故事仍然是防守：既然流程图注定由 AI 来写，就让 AI
来写，好歹产物还在自家的格式里。

## 反直觉的一步：把生成免费送出去

8 月 19 日的发布换了打法。Maestro Flow 定义了一种新的流程文件
.flow，一份写明了输入输出的 JSON
节点图。关键设计是同一份文件，三条路子改它都行：业务人员在网页画布上拖，工程师在
VS Code 里写，coding agent
用官方命令行工具直接生成。中间没有格式转换，Claude Code
生成的就是能上生产的文件本身，人随时打开画布，对着同一份文件检查、细调。

放开生成的同时，平台把生产环境要有的几道关口补上了一半。流程发布前，平台强制校验结构和语法错误；命令行能把组织的安全策略拉下来，检查
agent
节点合不合规；每次改完流程，可以拿内置的测试集跑一遍回归；审批直接做成流程里的一个节点，推到
Slack 或 Teams 里等人点。

收钱的地方也挪了。按官方公布的定价方式，工具侧不按人头收费，你用自己的
Claude Code
订阅生成流程文件本身不另付钱；流程在生产环境里每跑一次，收一个平台的计费单位。产品负责人的原话说得直白：企业现在不缺
agent，缺的是让 agent 干活的那套调度。

直觉上这是把自家的开发工具白白送人。席位时代要是还在，这一步等于把售票厅拆了。看起来像投降。

## 收费站为什么搬家

创始人 Daniel Dines 三月在财报电话会上算过这笔账，原话翻译过来是：造软件的成本越低，能安全地治理、编排、扩展这些软件的平台就越值钱；造东西越便宜，造出来的东西就越多，这不会减少企业对编排的需要，只会增加。

翻译成生意上的话：写流程趋近免费之后，能收钱的地方没有消失，只是从建造挪到了运行。生成免费谈不上让利，它是把收费站搬到公路上，赌路上的车会越来越多。

不是每家公司都能这么算。同样面对
AI，微软就做不出这个选择，因为两家压箱底的东西完全不同。微软的旧收入是
agent 时代的入口：M365 的企业租户，和搜索广告位。微软把 agent
当成办公套件的加价项来卖，结果付费渗透率只有
3.3%；真正按用量计费、直接交付成品的
Cowork，放在默认关闭的实验开关后面，因为按用量诚实定价，等于给按人头收的订阅放血。同一家的
GitHub Copilot
直接卖给开发者，定价贴合价值，两千万用户心甘情愿在用。一个产品两千万人在用，另一个渗透率
3.3%，差别不在技术，在各自背后的账本。

UiPath
的情况正好反过来。它手里既没有租户，也没有流量入口，原本的钱来自开发者席位和一圈咨询伙伴。这两样东西恰恰在
coding agent
普及之后变成大路货。旧收费站本来就要拆，守也守不住；自己动手拆，把收钱全押在运行这一层，反而顺。

由此可以提炼一个判断办法，拿去套任何一家老牌软件公司：看它的旧收入在
agent 时代是入口还是大路货。是入口的公司会设卡防守，把 AI
做成旧账本上的加价项；旧收入是大路货的公司，才敢真按用量收钱，把钱收到运行这一层。Automation
Anywhere 五月发布了一套几乎一样的编排治理框架，但没在外部 coding agent
集成上迈出对等的一步，差别就出在这条线上。

账算得通不代表没有风险，输赢条件也要摆出来。第一，顾问这摊活儿的大头长期在咨询公司手里，coding
agent 先压缩的就是这批顾问的工作量，而过去正是他们把 UiPath
带进一家家大公司。伙伴渠道先萎缩，按用量的新收入又没跟上，转型就会断档。第二，现在支撑这个故事的数据全是公司自己说的：AI
产品年化收入接近 2 亿美元，10 万美元级客户里六成已经用了 AI
产品，用的人平均花费约是没用的人的 3 倍，带 AI
的扩张订单平均金额约是不带的 6
倍。数字健康，但只统计了四五个季度，还没有第三方验证过。

## 引擎真的能收到钱吗

收费站要能收钱，公路本身得是真的。这套引擎干的事，正好对着上面那两个毛病。

等审批的毛病，靠持久执行解决。流程每走一步，引擎把这一步的结果记进一本流水日志。走到审批节点，引擎把整个流程的状态存下来，进程直接退出，一点计算资源都不占。三天后审批在
Slack
里点了通过，引擎把流水日志重放一遍，之前的状态全部还原，从断点接着往下跑。在写流程的人看来，代码就像从头到尾一口气跑完的，等待和恢复都归引擎管。

半夜崩溃的毛病，是同一套机制顺手解决的。进程挂了，引擎重放到崩溃前的最后一步，从那里继续。每个节点可以设重试策略，还可以设补偿动作：十步的流程，第十步失败，自动回滚第七步做过的事。加上发布前的强制校验、测试集回归、流程里内建的审批节点，等待、恢复、审批、审计这四样，平台全包了。

流程在审批关卡前落盘等待，通过后从断点续跑，故障处有补偿回滚

这里有个很妙的对称。coding agent
的那套环境，是确定性的壳包住非确定性的模型：行动前靠上下文文档、测试、lint
约束，行动后靠日志和审查兜底，靠这些容忍模型的不稳定。Maestro
正好反过来：确定性的骨架包住非确定性的节点。流程怎么走、怎么重试、怎么补偿，写死在
.flow 里；节点里装的，才是 agent
和人的判断。这也解释了为什么拿一个裸的 coding agent
去编排业务流程，状态、恢复、审批、审计全得自己从零搭；它按实例收钱的底气也在这里：收的正是让流程在生产环境里活下来要付的成本。

边界也要说清。流程文件本身的变更审批、多环境流转和版本晋级，官方文档还没交代，这块治理目前是空的。

## 判决书

这步棋的输赢不需要信仰，有可以证伪的指标。

最要紧的看一处：UiPath 未来两三个财年的净新增 ARR 构成。AI
和编排产品占的比例持续上升，净留存率站稳 109%
以上，伙伴渠道又没先塌，这步棋就算走通了。反过来，席位和顾问渠道加速萎缩，2
亿美元的 AI
年化收入又长不成新的顶梁柱，编排越值钱就只是一句财报话术。

还有一个外部变量。哪天 Anthropic 或 OpenAI
把生成流程和自家运行时打包卖，UiPath
这套靠开放格式吃饭的中间生意，上游就可能顺手截走，而微软已经在自家体系里把这条路闭环了。

最后把那个判断办法留给你。你自己的公司，或者你在评估的任何一家公司，旧收入在
agent
时代是入口还是大路货。是入口，别指望它革自己的命；是大路货，看它敢不敢把收费站搬到公路上。UiPath
已经把第一步棋摆在了桌面上。
