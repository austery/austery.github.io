做个人项目、独立产品或者小团队业务，大家往往都有一种心理安慰：我只是一个小网站，没什么用户隐私，账上也没多少钱，黑客费尽心机来搞我有什么用呢？

过去十几年来，这层心理防线在多数情况下确实有用。安全圈管这叫靠渺小隐身。以前发动一次有针对性的入侵，需要熟练的黑客花几天踩点、读代码、写脚本，人力摆在那，打一个没有油水的小网站连人工费都赚不回来。大公司才是重点目标，小项目只要不把数据库密码设成
123456，多数能平安度日。

但 2026
年秋天，几家安全公司发现了一批黑客忘了设密码的攻击后台，暴露了一个现实：这层隐身护甲已经破了。黑客用开源
AI 工具，把一次自动入侵的成本拉到了 5 到 25
美元，就算你的网站本身一文不值，你服务器里的 AI
密钥和本地算力，现在本身就是可以直接变现的通用货币。

## 为什么 5
美元一次的草台班子，专打以前没人碰的小目标

要想理解为什么小项目不再安全，得先看看今天的 AI
攻击工具长什么样。

在过去的半年中，GitHub 上出现了大约 45 个开源的 AI
自动化渗透测试工具，其中最流行的是 ARTEX、Cairn 和
PentAGI，排名前五的几款合计拿到了 6
万多个星标。这些工具将上百种传统黑客工具集成起来，形成面向大模型的接口。只要提供一个目标网址，它们就会启动多个子代理自动进行扫描、发现漏洞、编写代码并尝试入侵。ARTEX
的作者在 10 月初下架了 GitHub 仓库，但当时已经有 12,000
多个分支，下架挡不住扩散。美国联邦调查局在 11 月 13 日的专项通报中提到，仅公网暴露的
ARTEX 控制台就有 1,600 多个。

这些工具真的有那么厉害吗？并不。安全机构 NorForge 分析了 20
多个黑客自己忘了设密码的 Cairn 面板，覆盖了 1,100 多个实际攻击项目，在调查报告里给出了真实的命中率：平均成功率只有大约
10%，就算攻进去了，平均也要折腾将近 23 个小时。

真实后台日志里到处都是草台班子式的翻车现场。云安全公司 Wiz 在追踪分析中看到，ARTEX
两分钟内对着微软高度加固的登录接口连发 60
多次没有数字签名的假凭证，就像拿没盖章的假门禁卡连刷 60
次。更离谱的是另一家机构 Gambit Security 在调查里记录的事故：黑客用三款开源工具
5 天扫描 105 家在线商业站点，攻破至少 27 家公司并偷走 60
多万条未过期信用卡记录；可是在入侵一家自行车零售商后，AI
代理执行清理脚本时通配符写得太宽，顺手把受害者数据库里的 180
张表连带备份表全删光了。甚至连黑客自己的运维都一塌糊涂，不少暴露面板压根没设密码，反遭同行劫持偷走密钥。

Wiz
直接指出，这些工具没有发明任何新技术，能打进来的目标全靠弱口令、泄露密钥、没打补丁的旧插件这类老缺口。

那为什么这种粗糙、成功率只有 10%
的攻击，反而让小团队更危险？算一笔账就明白了：NorForge
测算出，用低价模型跑一次 Cairn 的自动化攻击，平均成本只要约 5
美元；Gambit 统计攻破 27 家公司的后台，平均每个目标只需 25.46
美元的扫描和攻击成本。过去雇熟练黑客盯一个中小网站按天计酬，划不来就不干；现在把单次尝试的价格压到一顿快餐钱，机器可以
24 小时不眠不休地撒网。对黑客来说，完全不需要每次都成功，只要每扫 10
家能撞中 1
家，这门生意就能稳定赚钱。小网站以前赖以生存的门槛，就这样被一顿快餐钱抹平了。

小项目的隐身护盾如何消失：人工黑客按天计费只盯大目标，而
5 美元 AI 自动化流水线靠 10% 成功率即可 24 小时批量扫网盈利

## 你的项目没油水，但你的
API 密钥能直接养活攻击机

看到这里，很多个人开发者会想：我只是做个技术博客、开源演示站或内部小工具，没信用卡没付费用户，黑客花
5 美元攻进来能捞什么？

答案就在你的环境变量和本地服务里。2026 年，大模型的算力和 API
额度本身就成了黑客最爱抢的资产。

Google 在 11 月的专项追踪报告里披露，盗刷云端大模型额度已经发展成成熟的地下黑产。黑客只要通过泄露密钥或钓鱼拿到一个云账号，就会立刻开启大模型接口或租用高端显卡，一天能刷出超过
10 万美元账单，最严重的案例在受害者察觉前累计损失达到 100
万美元。这些偷来的额度会流向地下中转站，有的平台甚至以每月 60
美元兜售所谓无限量前沿模型套餐。

2026
年夏天以后，黑客把偷来的算力不仅倒卖换钱，还会直接拿来喂给自家的攻击代理。6
月，安全公司 Sysdig
首次在真实网络中观察到黑客把公网不设密码的本地模型服务 Ollama
接入自动扫描流程。同年秋天，亚马逊安全团队用陷阱服务器抓到
ARTEX 跑通了完整循环：它专门扫描公网暴露的 One API、LiteLLM 和 Ollama
等模型中转服务，把偷来的 API
密钥测完额度后，直接塞进自家配置文件里，用来支付下一轮扫网的账单。

很多开发者图方便，把自己的 Ollama
或中转网关架在测试服务器或家里，端口直接暴露在公网且不带密码，甚至把测试用的
API
密钥扔在公开仓库里。对黑客来说，这等于一台随时能薅羊毛的矿机，哪怕上面一个业务数据都没有。

有人可能会说，这些厂商不是都有内容安全护栏，不会帮别人写攻击性代码吗？但实际上，这种护栏对开源攻击工具来说基本无效。安全公司
Elastic 在 11 月 13 日对其源码的审计里分析了五个流行框架，发现没有一个框架会检查用户有没有获得授权，反而内置了规避内容安全护栏的策略，比如
Cairn 碰到某个模型拒答后，会自动等 5
秒换另一个模型继续尝试。联邦调查局的报告也提到，活跃的 ARTEX
实例主要调用的是价格低廉、安全护栏宽松的 DeepSeek Flash
系列。同时，开源大模型在普通笔记本上不到 10
分钟就能移除安全护栏，因此单靠大厂封号和安全护栏已经很难遏制这种以偷养偷的机器。

以偷养偷的自动化攻击闭环：开源攻击框架扫描公网暴露的
AI 网关与云账号，窃取 API 密钥后经地下中转站或直接回灌自身，以 5 到 25
美元的低成本驱动下一轮批量攻击

## 从装插件到写代码，两个新入口正在贴近普通开发者

即使你把模型服务藏在内网，日常只是建站装开源插件、写代码用 AI
编程助手，2026 年秋天也出现了两个直接贴近日常开发习惯的新变化。

第一个变化是开源软件发布安全补丁后，留给你慢慢升级的时间几乎没有了。以前大家装了一个
WordPress
插件或者开源组件，看到更新提示过一两周有空再升级，觉得黑客没那么快能研究出利用方法。但是
Google 在 11 月 16 日的季度威胁报告里提到，他们在一台公网测试服务器上发现了俄语试点程序
exploit_agent。它持续盯着主流开源网站软件，一旦官方发了补丁，就自动拉取补丁前后代码做对比，让大模型看修补了什么漏洞，自动生成攻击脚本，不经人工介入就去扫描网上还没升级的站点。

当然，没必要过分夸大这个单一程序的作用。它配置文件里的俄语注释自己都标着试点项目，报告里贴出的代码片段也只是一个简单的检查
WordPress 插件 Spectra 里网址是否匹配的示例。云安全联盟的独立审计也指出，报告没有公布该程序的成功率。但这条路线在现实世界中已被验证可行：2026
年 8 月底 PaperCut 打印软件公开漏洞，安全公司 GreyNoise 就记录到黑客用
OpenAI 的 Codex 编排工具驱动 DeepSeek 模型，从零开始仅用 70
分钟就对比补丁编写了攻击代码，不到 4
小时攻破第一台真实服务器，两天内拿下 395 家机构的 440
个系统。补丁本身正成为自动化扫网的新起点。

第二个变化发生在你每天打开的本地开发环境里。Google
在同一份季度报告里还顺带披露了一起案例：朝鲜黑客组织 MIDNIGHT NEPTUNE
潜入欧美加密机构的内网代码库后，没有去改业务代码，而是悄悄修改了项目里的
.claude/settings.json。其他同事只要在本地启动 Claude Code
打开仓库，配置里的钩子就会自动触发下载后门木马。这件事目前还只有 Google
单一来源、没有公开完整技术细节，但它最棘手的地方在于完全没利用软件漏洞，靠的就是开发者对仓库配置文件的默认信任。

## 小团队和个人开发者，今天就能堵上的四个口子

说到底，个人开发者和小团队没办法养一个全天候的安全组，也不必为此焦虑。现在的自动化工具仍然很不成熟，成功率在
10%
左右，主要捡的是基础安全缺陷的漏。花半小时把下面这四个口子堵上，就能拦下大部分
5 美元扫网的机器。

立刻给自建 AI 服务上锁，把所有 API
密钥设好消费上限。检查你租的云主机或内网穿透服务，确认本地的
Ollama、LiteLLM、One API
等中转接口没有不设密码暴露在公网。去大模型厂商后台，给每个 API
密钥设好月度消费上限，尽量用最小权限和短期临时凭证替代长期静态密钥，免得一个测试项目漏网拖出天价算力账单。

把管理后台藏起来，公网入口套一层网页防火墙。PaperCut 那场 70
分钟造出攻击代码的战役里，开启了 Cloudflare
网页防火墙的目标依然直接挡住了攻击。个人和小团队的后台管理面、旧插件接口尽量收进内网或走
VPN
访问；必须露在公网的站点套上一层基础网页防火墙，遇到高危开源组件补丁一时来不及升级，也能先在入口拦住绝大多数按模板扫描的机器。

把仓库中的 AI
工具配置文件当作可执行代码来审查。.claude/settings.json、.cursorrules
等文件现在可以决定 AI
在本地电脑上的行为，审查级别需要与构建脚本一样高。在从陌生开源仓库拉取代码并执行时，不要为了图方便而默认启用全自动批准执行。

最后，为重要数据准备离线或只读备份。传统防黑客主要防的是数据被窃或被勒索，现在多了一种更荒诞的风险：一个笨手笨脚的
AI 代理在清理痕迹时顺手把你 180
张表连带在线备份一起删光。把备份权限和线上数据库隔开，比事后后悔管用得多。

小项目太小所以没人打的时代确实结束了。好消息是，这些全天候扫网的机器只会选最好捏的软柿子，你不用把自己武装成铜墙铁壁，只要比旁边那批裸奔的服务器多上两把锁，5
美元一次的流水线就会自动滑过去找下一个目标。
