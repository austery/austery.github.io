大家好，這裡是最佳夥伴，我是大飛。

想像一下，你的 AI 助理在直播開始前五分鐘悄悄告訴你，直播設備出現了問題，甚至還主動提出幫忙解決。這不是科幻小說裡的場景，而是去年十月 OpenAI 開發者日上真實發生的事情。

涉事人員身份不明，是 ChatGPT 和 Codex 的負責人。就在 DevDay 直播開始前，他的私人代理人檢測到 GPT 生產環境中存在異常，立即聯繫了 TBD，許多人認為 TBD 是 OpenAI 下一代消費級 AI 產品的關鍵架構師。在 DevDay 的部落格網站上，他們全面討論了生態系統、後應用時代以及對人工智慧安全性的思考。這次採訪是在同一天錄製的，就在幾個小時前，他的團隊一次推出了 20 多款產品。前一天晚上，團隊在由公司圖書館改建的作戰室通宵工作。因此，這種對話狀態下的資訊密度是前所未有的。

在今天的影片中，我們將深入分析這次採訪。

### 編程方式的轉變與智能體規模循環

首先從工程師們最關心的問題開始：你現在還寫程式碼嗎？

TBD 的回答是，嚴格來說，確實有大量的程式碼正在被編寫，但不是他寫的。對於了解趨勢、分析業務和評估版本效能等任務，所需的程式碼大多由 Codex 產生。他偶爾會做一些整合練習，只在周末抽出一些空閒時間來手動解決一些 LeetCode 問題。作為一名前谷歌工程師，編寫程式碼是他職業身份的一部分，但如今，人類不再是程式碼的主要生產者。

那麼，他每天並行運行多少個代理程式？TBD 表示該數字會動態變化。以前，他會運行很多代理，但在 AutoGPT 等模型取得突破後，一個更大的代理就可以處理很多事情。這就形成了一個循環：隨著他不斷推進不同的前沿研究，他構建了越來越大的智能體團隊，然後模型取得了下一個突破，突然間一個更大的智能體處理了一切並自主學習，迫使他再次縮減智能體團隊。擴張，收縮，然後再擴張——這就是節奏。

當被問及這是否是循環工程和圖工程的某種演變時，因為許多人都在努力解決代理循環和圖配置問題，TBD 表示，設定和調整循環很困難，而且通常不清楚如何配置它們才能獲得良好的結果。這或許曾經令人興奮，但這絕對不是我們未來工作的方式。未來將會像 Dots 所做的那樣：一個極其聰明的人工智慧，全天候工作，了解你的喜好，並從回饋中學習。你不想去想「我需要以精確的方式循環執行這個操作」；你只是想要一個能夠學習的系統。這一點很明確：所有這些需要大量配置的東西都只是一個過渡階段；最終用戶完全不需要了解這些資訊。

### Dots 的定位與後應用時代

關於 Dots 與 ChatGPT 或 Codex 等現有工具之間的關係，T 表示，歸根結底，它們都是一回事：打破技術的束縛，擁有持久的、主動的智能，知道自己需要做什麼，並且可以通過任何客戶端或屏幕供您使用。你不應該被筆記型電腦或手機束縛；它應該在你需要它的時候出現，在你不需要它的時候消失。

他說他迫不及待地想看到那一天到來，因為帶著像筆記型電腦一樣笨重的「磚頭」意味著你被科技束縛，而不是科技為你服務。有人說這就像電影《她》中的世界觀——他看過這部電影，但他表示，他更傾向於 30 或 40 年前的科幻作品。例如，《神經漫遊者》或最初的《星際爭霸戰》。《星際爭霸戰》中的科技非常實用；你直接與電腦對話，它會為你做事。你可以和你的飛船對話，它還會移動。這正在成為現實，我們正在進入那個時代。

T 也分享了某些產品決策背後的邏輯。OpenAI 目前擁有許多產品，例如 Codex、ChatGPT、GPTs 和 Dots；團隊正在合併 Codex 和 GPT 以降低複雜性，因為使用者的回饋非常明確。人們喜歡這些模型的功能，但有時他們想要聊天介面，因為它更快、更令人愉快。最終，Dots 的所有功能都將直接整合到 GPT 中，從而提高 OpenAI 用戶的基本要求。Dots 本身沒有模型選擇器，也沒有配置；你只要跟它說話就行了。您唯一需要配置的就是您希望透過哪些管道與之互動。

面試官提出了一個關鍵問題：過去兩年工作方式發生了如此大的變化，未來五年情況會穩定下來嗎？

T 堅決地說不；情況還會繼續發生劇烈變化。儘管如今的技術已經將語音和多模態輸入輸出結合起來，但它仍然很笨拙，而且這種情況還會持續下去，直到有一天它不再笨拙為止。到那時，你會驚訝地發現你可以直接和它對話，而它會完美地記住一切。

當我想集思廣益時，我只需在協作面板上潦草地寫下一些東西；這是 ChatGPT Space，一個供人類和智能體協作的共享白板。它將超越對話，超越你今天擁有的眾多客戶，而且由於這一切尚未真正開始運行，我們正走向一場巨大的變革。

### 生態系統、插件共享經濟與長期記憶

然後我又提出了一個問題，這也是許多從業者都在思考的問題：在 OpenAI 於 DevDay 上發布的所有功能中，你覺得哪一項最吸引你？你認為有哪些事情被大家忽略了，但未來會變得非常重要？

你說過，被忽視的黑馬是生態系統，以及對開放一切的堅定承諾。您提到「GPT-in-way」已經有 16 個合作夥伴；這個想法實際上始於去年，當時你與 Poe 和 OpenCode 的創始人交談，認為你肯定能夠使用 GPT 登入並使用你的 GPT 配額——這幾乎就像一個簡單的虛擬握手，意思是「放手吧，我們相信你不會做任何壞事」。它越來越受歡迎，最終獲得了官方支持。

另一方面，整個技術基礎設施（包括插件擴展和發現）的開放，使得每個人都能將自己的產品分發給大約 12 億用戶並從中受益；DevDay 上沒有提到的另一個重點是共享經濟。熱門插件將獲得收益分成；你接著問道，例如，如果有人在 GPT 中使用 Notion 或 Figma 插件，Notion 和 Figma 能否從中獲利？

您已確認，所有 OpenAI 訂閱用戶都將獲得一定量的使用量。當用戶將此配額用於使用 GPT 的插件或其他產品時，OpenAI 的合作夥伴將獲得補償。

那麼，插件是如何被發現的呢？你的答案很簡單：做一個好的插件就行了；該系統會查看用戶留存率、插件的成功程度和質量，然後開始在對話中向用戶推薦該插件；當然，如果插件不夠好，就不會被推薦。所以關鍵不在於使用老舊的 SEO 策略——關鍵字堆砌，而是找到讓人們持續使用並留下來的方法。

說到這個專案的起源，您提到這是 OpenAI 第二次嘗試做類似的事情。之前曾有一個應用市場；你一開始談論的是 Codex Cloud，那已經是去年的事了。當時 CodexCloud 中使用的動畫成為了後來 GBOT 的靈感來源，但真正的時間都花在了背後的研究上。他們花了兩年多的時間進行長期研究，記憶系統和連貫性也花了差不多同樣長的時間才形成。

後續的許多結果都直接輸入到了 ChatGPT 中，使用者非常喜歡 ChatGPT 能夠記住這麼多關於他們的資訊。人們曾向他講述過類似的故事，說在他們的日常生活中，ChatGPT 甚至記得他們舉辦過燒烤派對、喝過青檸雞尾酒，並且猜到他們手上的燙傷是由青檸造成的。所以，ChatGPT 的記憶體使用效果非常良好。所有這些，都建立在 CodexHarness 之上，再加上全天候高效運行的能力，最終成就了 DS。

另一件重要的事情是確保安全。這就是為什麼 D 與 Astro 同時發布的原因，因為 Astro 是 OpenAI 最安全、最符合規範的模型。

### 人類在 AI 時代的角色與理想工作方式

在這裡，他問了一個他問每位嘉賓都會問的問題：“你認為人腦在哪些方面還會繼續發揮作用？”“當人工智慧承擔越來越多的任務時，你覺得自己在哪些方面仍然是必要的？”

TP 表示，這很大程度上取決於我們如何構建這項技術。O 的設計理念是以人為本，將人工智慧建構成人類的延伸，保留你的意志和品味。只要這種情況持續下去，它就會賦予你力量，大大增強你的創造力和品味。我們可能不再需要程式設計師了，但我們將擁有比以往任何時候都多的建造者。有些東西永遠是人類的本能，例如人們渴望學習，渴望了解其他人正在創造什麼。他說，他不僅是在這裡說話，也是在和 LY 說話，而且這種情況在很長很長一段時間內都將保持不變。

Loni 也指出了工程界的另一個焦慮：上下文切換增多，人們感到孤獨，整天與人工智慧交談，而不是進行真正的人際對話。

T 說他考慮過這個問題，而且一直在思考這個問題；減少配置疲勞是其中的一部分。他和他的團隊花了大量時間思考這個問題。對他來說，理想的工作方式是讓 AI 真正出現在物理空間中，就像他目前與 LINE 的對話一樣——你可以觀察、聆聽想法，無論你在紙上寫下什麼，它都會在後台開始構建，然後你又有了新的想法，它又開始構建其他東西。你甚至可以將它投影到螢幕上，直接與它對話，讓它透過與人類的對話自然進化。這樣一來，工程師們就不用再盯著螢幕琢磨如何寫提示訊息而感到疲憊了；它變得非常自然。這是他們努力的方向，雖然他們今天還沒有完全實現，但他相信他們將來一定會實現。

隨之而來的另一個問題是，既然現在人工智慧能做的事情變多了，那麼人們就面臨更大的壓力，需要做更多的事情。大家都在催促“快點”，同時運行 30 個代理程式——為什麼你不創建更多任務呢？

T 表示，S3M 也做出了這樣的承諾：希望減少噪音，讓使用者將注意力集中在他們真正想做的事情上。所有這些事情，無論重要與否，都在爭奪你的注意力；人工智慧旨在降低這種影響，幫助你保持專注。他分享了一個觀察結果：每當他休息一週徹底放鬆身心時，他就開始以不同的、更具創造性的方式思考。他期待將這種理念融入日常生活；或許我們需要減少會議次數，或許我們不必做那麼多事，這樣我們就能更好地休息了。

### 演示現場的異常檢測與推理

更高級別的人工智慧不應該只是每秒多寫一條提示，所以 L，你問了 TBO 一個大家都在討論的問題：「最近有什麼特別酷的人工智慧應用案例嗎？那種讓你驚嘆『哇，太棒了』的那種。」

TB 笑著說，現場演示差點出問題，所以他可以分享一個故事：他的 D 在演示開始前五分鐘檢測到 GPT 生產環境宕機，並向他發送訊息說：「嘿，生產環境宕機了，要我幫忙修復嗎？」他回覆說：「小機器人，我覺得我們還沒到那個階段，但謝謝你的嘗試修復嗎？」

總之，最讓他驚訝的不是它檢測到了故障，而是 D 理解了演示、生產系統和即將到來的直播之間的聯繫。對於 D 來說，它能夠知道有一個名為演示的重要活動、一個製作系統和一個現場直播演示，並且演示很可能會使用這個製作系統，因此這兩者是相關的。「所以，我應該在五分鐘後聯繫一下老闆，因為他們可能想知道。」TBO 認為這種推理能力非常出色；D 雖然可以訪問一些生產系統，但仍然在人工監督下運行。

他們仍在研究專家模型，並在獨立的硬體上運行該模型，進行額外的監控，有些甚至直接在 Mac 上運行。T 也提到了一點人們可能沒有意識到的：該安全套接字並非在使用者的機器上運作；它可以連接任意數量的設備，每個設備都有自己的運算能力。你甚至可以將自己的筆記型電腦連接到它上面，未來的用戶可能一次連接十台設備。這時，T 用了一個比喻，說這有點像章魚。

### 招聘標準、組織文化與自主權

主持人將話題轉向了人，指出 OpenAI 正在招募很多人，並詢問面試中哪些技能越來越受歡迎？

他指出，打字速度這項技能顯然正在退化，因為它已經不太實用了。顯而易見的是，良好的品味、從使用者角度思考的能力以及同理心正在不斷提高。他們在招募過程中發現，該公司現在擁有超過 120 位 YC 創辦人，使其就像巨型新創公司。因此，那種創造重要事物的熱情和渴望，再加上對「好」的理解，比以往任何時候都更重要。

T 一直相信產品經理會在這個時代蓬勃發展，因為他們工作的本質是決定要建造什麼，幫助其他人建立它，然後詢問它是否足夠好，並不斷迭代。

如今角色之間的界線越來越模糊；以前一名員工可能只從事設計或工程工作，但現在他們可能身兼數職。他問 T 是否懷念當工程師的日子。那種進入心流狀態、打造產品，並看著它從無到有最終成型的美妙感覺？

T 說他有一段時間很懷念那種狀態，但現在有了 GPT 的速度，特別是能夠透過語音控制它，他可以重新進入那種高度創造性的狀態，一種無盡的心流狀態。雖然與過去的方式不同，但他不再懷念過去的日子了。

至於給剛入行的年輕人的建議，T 表示，下一個 T 已經在 OpenAI 工作了，他的名字叫艾哈邁德·易卜拉欣。T 很喜歡和這個年輕人一起工作。艾哈邁德被聘用時還是一名應屆畢業生，現在他負責 OpenAI 的所有計算集群和應用程式——這是一項巨大的責任——而且他還構建了 Codex 基礎設施的很大一部分。他與眾不同之處在於他非常友善、善於合作、總是能解決真正重要的問題，而且不以自我為中心。T 說他就像一塊海綿，學習速度驚人，以他從未見過的速度吸收所有最新技術。短短幾個月，阿查德的進步令人難以置信。現在，TBO 完全信任他，將 OpenAI 最具挑戰性的發射任務都交給了他。

然後他被問及在 OpenAI 的工作經歷；從表面上看，這就像源源不斷的產品發布——有點混亂，但極具爆發力。

T 表示，許多人正在進行許多令人興奮的自下而上的工作，例如 Decisions API。還有一些團隊發現 Luna 模型非常好，因此他們應用了一些約束抽樣，並以不同的形式將其發佈為 Response API。但如果你深入了解，你會發現這是一個由 Slack 頻道拼湊而成的產品，最初是由大約四個人在周末開發的，然後作為內部工具對外開放。隨著人們使用它，他們越來越興奮，開始參與其中，最終，他們將其發展壯大，並最終發布了它。

正是這種令人難以置信的自下而上的能量，使人們自發性地承擔各種角色，並引導他們的工作朝著富有成效的結果發展。因此，在 T 看來，一個非常獨特的面向是擁有極大的自主權。如果 TB 想重置，他就會重置；如果他想就 X 發表什麼意見，他就會說。T 說，既然你擁有很大的自主權，你就必須對這種自主權負責。你必須相信人們能夠做出正確的選擇，在出錯時迅速糾正錯誤，或從錯誤中學習。

那麼，他有沒有犯過什麼錯誤呢？T 笑著說：「當然。」例如，他有時本可以激勵團隊建立更簡單的產品，並不斷追求簡潔。此外，他在 Codex 早期也造成了一些崩潰，甚至在加入 OpenAI 的第三天就搞垮了生產環境；幸運的是，他最終還是被錄用了，當然，他也吸取了教訓。

Lani 開玩笑地問道，大家預計下個月會有多少次重置？T 說這取決於我們弄壞東西的次數；OpenAI 的理念是先打破常規，然後再慶祝。

### 未來趨勢、二階效應與安全投入

然後採訪進入了最後一個環節，拉尼問道：「你認為人們還沒有考慮到未來哪些方面？什麼才能改變人們看不清真相的現狀？」

T 表示有三件事：
1. 第一，網絡上的大部分行為將由人工智慧代理完成；
2. 其次，車型將以驚人的速度變得更便宜、更快；
3. 第三，最終所有模式都將無縫整合在一起。

就這三件事。他經常看到外面的人們在建造什麼，然後心想：「這仍然沒有抓住重點。」如果你努力想像一年之內一切都會比現在好十倍，你就會以完全不同的方式去建設它。

在未來大部分流量都來自代理商的情況下，會產生哪些二階效應？T 說有很多。首先，如果你想讓你的產品在代理時代取得成功，你必須針對一定規模的流量進行建構。所以他們與 Notion 的合作非常密切。Notion 建構了 MCP 之後，所有能夠完成實際工作的代理人都可以使用它，Notion 的流量也隨之激增。這顯然給系統帶來了很大的壓力，所以你必須弄清楚其中的經濟效益。另一方面，他認為，在創造真正利用所有方式為人類帶來愉悅的新體驗方面，投入的資金還不夠。

然後，他提出了一個引人深思的問題：在過去的一年裡，你對任何事情的看法有改變嗎？

T 表示，他最初預計這些車型需要一到兩年的時間才能達到如今的性能水準。他也沒想到自己會如此依賴語音，或者如此習慣於口述和直接打電話給代理人來做這麼多事情。此外，在招募方面，他沒有意識到年輕一代擁有如此驚人的天賦和活力，而且他們會率先接受所有這些變化，然後努力學習如何管理它們。

然後，話題轉向了人工智慧安全性和產業發展速度。你問 TBO，鑑於過去一年來大家都在調整發展步伐，你如何看待人工智慧領域及其對人類的潛在風險？

TBO 表示，對他來說，「放慢腳步」只是另一種說法，意思是你需要提前投資——而且比人們認為你應該投資的更多。例如，投資於模型校準和安全護欄。樓主正在將越來越多的運算資源用於輔助監控。雖然絕大多數運算資源都用於主要系統（即執行工作的代理），但也有大量的運算資源用於監控這些主要系統，以確保它們不會採取高風險行動，或在它們可能受到提示注入攻擊時中斷它們。他們在 API 方面最大的投資實際上是安全堆疊。因此，放慢開發速度意味著確保你的系統非常強大。

雖然 OP 還沒有發布 o1 之後的下一個能力層級，但他們發布了一個類似水平但效率更高的版本，他們對此感到非常滿意，TBO 也為此感到自豪。

然後，你問 TBO 的最後一個問題是：你對目前的應用程式還有哪些不滿？

TBO 表示，該模型的功能已接近完成，但不足以讓應用程式幾乎完全消失。他迫不及待地想要盡快達到那種本質的簡單性，他說，即使是他也對模型選擇器和推理強度感到疲憊不堪。究竟該用哪一個，或者它們實際上能做什麼——你幾乎需要一個博士學位才能弄明白，他說他只想盡快消除所有這些問題。

好了，採訪到此結束。倪和 T 的對話從工程師日常工作的變化開始，涵蓋了產品形式、生態系統開放性、安全責任和文化理念，最終達成了一個簡單的願景：讓技術回歸其服務於人的本質。
