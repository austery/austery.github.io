### 全民 Build 时代：Attention 与 Infer 的交集

[Speaker 0]: 大家好，非常荣幸今天借助 AI Engineer 和超线性学院这个机会跟大家一块儿分享一下我们在做 AI 转型中看到的一些趋势以及我们的一些想法吧，跟大家一块来抛砖引玉、探讨一下。

[Speaker 3]: 好，那我来分享一下，把画面交给吴总。能看到吗？

[Speaker 0]: 可以看到。

[Speaker 0]: 大家早上好，周六的早上非常荣幸有这个机会跟大家来一块儿做一个分享。本身 AI Engineer 的话其实也是我一直以来最关注的一个社群的活动。因为最早 AI Engineer 在美国举办的时候，虽然不能亲临现场，但是从最早的几期我们都在去看，也是我们最早去学习 AI、去跟业界朋友探讨一个我觉得非常非常有价值的平台。所以在里边我们也学了很多东西。那今天借这个机会，其实我们也是想把我们锐动 AI 看到的一些内容跟大家做一个简单的分享跟探讨。

锐动 AI 的定位，其实我们给自己一个定位是在做一个全民 build 时代的一个 token 基础设施的这样一个定位。所以其实我们一直很关注的就是在这个 AI 变革的年代，尤其是 AI 对软件行业的冲击的年代，大家到底应该关注些什么东西。我今天分享内容我起了个题目叫《在全民 build 时代的一个 Attention and Infer 的交集》。我们都知道这轮 AI 变革的核心论文就是 Attention Is All You Need，那其实我们在这里面稍稍加了一点点，那就是在今天面向开发者，我们未来也要构建我们自己的 attention 机制，同时要构建我们的 infer 机制，这是我今天想分享的内容。

具体定义这件事情的话，其实我们最近看到了很多的趋势，我不知道大家有没有关注。如果大家在关注一些社区的变化的话，会看到很多的趋势。比如说 OpenCraft 这个社区里非常有名、非常火的软件，它基本上把过去十年、二十年、三十年在我们的商业软件里边最强大的、最稳固的一些商业软件，基本上都用 open source 的方式给重构掉了，借助 AI 的能力，包括像 Photoshop，包括像 Office，包括像其他的一些全都重构掉了。当然我觉得其实是一个尝试，其实也代表了一种趋势。可能未来的软件，传统这么多年去做买 license、卖订阅这种方式是不是还能存在，可能就会打一个很大的疑问了。那这个基本上对这么多年的软件行业存在的商业模式就会产生一个新的重构了。

另外一个，比如说最近很火的 Open Interpreter 这套 open source 的工具，基本上把软件的分析甚至一些逆向能力全部交给他。当然这些能力不是说今天靠 Open Interpreter 才出现的，但是其实很多能力能够让每一个使用这种前沿 coding 工具的人都能够去具备这样的能力。

还有一些像 Generative Office，基本上像这样的软件，它的接口已经从原来面向人类用户转向了面向 agent。所以整个行业我们看到一些非常大的变化在不知不觉中发生了。

我们回来看，因为我自己做了好多年的软件工程，尤其企业软件开发，做二十多年的职业软件开发，所以其实我们过去做一套软件是很麻烦的。它是一个工厂的逻辑，是一个大的协同分工的逻辑：你看到这个需求，你有产品经理去做需求分析，你要组织项目经理，你要组织架构师、开发者，你要组织测试团队，你要组织甚至客户的交付团队，一整套的内容全完成。但是在今天，可能我想在座的所有开发者，今天你在做大部分软件的时候，都是你一个人完成的：你一个人既是产品经理又是开发者，或者说你是产品经理加架构师，你的 agent 集群是你的开发者。所以这个需求变化非常非常大。

那这带来了两个趋势：

第一个的话就是门槛一定是降低了。我们经常会看到很多非专业的开发人员，比如原来是一些歌手、演员，或者各个角色，他都可以自己去做 web coding，自己去构建软件了，所以这个门槛在降低。

另外一方面的话，其实我们也会发现，现在开源社区的软件非常多，代码非常多，但是真正高质量的、有影响力的，还是能快速地获得大家的认可，我相信大家也都是有感受的。所以这个变化发展得很快。

其实我们怎么理解这个变化？我们也回顾了一下，其实这件事情历史上已经发生过了。我们就看过去的传媒。编程语言它也是语言，它也是内容的一个部分。其实内容产业在整个互联网发展过程中已经经历过一次非常非常深刻的变化。我们看到若干年前在纸媒的那个年代，本质上纸媒承载的是文字的内容、图片的内容，过去它的商业模式其实是靠卖 copy 的：我一份报纸多少钱，我一份杂志多少钱，是这样去做售卖的；主导方也都是一些大型的机构，报社、杂志社或者是电视台。

但是其实后来到了自媒体时代，大家发现：第一，创作门槛降低了，不用专业机构，每个人都能自己创作，都能发出自己的意见；第二，商业模式变了，因为供给足够丰富之后，没有人再去说我卖一个 video、卖一个什么东西、卖一个 copy，大家卖的本身就是你能不能吸引更多的注意力，你能不能把注意力变成流量、变成其他的方式去做变现。核心就是你创作的内容能不能被别人看见。

今天我觉得软件业可能逐渐也在往这个趋势去做转型了。另外一个非常透彻的像 B 站这样的平台，其实就是一个完整的、端到端的、面向个人 builder 的一个完整的生态平台。从他个人的制作到平台连接到持续的回报，这个是非常非常成熟的。当然其他的一些平台也是类似的。

所以我们觉得未来的软件行业，不排除说从今天单纯买 license、买订阅这种商业软件，变成说真正是一个社群化的、注意力机制驱动的商业模式。这种模式的话对我们大量的个人开发者来讲，我觉得是一个非常非常利好的状态。因为你借助这些平台——虽然现在还没有这样的平台，但我相信很快会有这样的平台——借助这样的平台，你不需要像大的软件公司或者大的平台一样需要大量的资金去宣发，可能你就能很快地构建一个自己的闭环的商业模式。

当然这里边其实也带来了一些挑战。刚才说了，因为我相信今天来参与的可能大部分都是以专业的开发者为主。但其实我们看到统计数据，在新增项目、代码量上是非常非常多、指数级增长的。某种意义代表说，软件或者代码本身的供给变得非常非常丰富了。那在这个时候，稀缺性就开始变了：过去的稀缺性是功能的实现，那今天的稀缺性可能就变了，变成说……

[Speaker 3]: 你的产品或者你的项目能不能更好地被别人发现？被别人发现之后呢，能不能被别人信任？能不能被别人去持续……你能不能持续地交付、持续地迭代、持续给别人贡献有用的结果？所以这个价值链已经在转换了。

功能的实现可能变成一个标配的能力，谁都能实现，不能靠功能的实现去赢得用户了，那可能更多的是你在功能实现的基础上要附加其他的东西。所以这个变化我相信大家一定要深刻认识到。

可能我跟很多开发者聊，大家其实有个共同感受，说 OK，今天有 AI，我交付代码速度、交付代码质量都变得非常非常快。但是很多尤其是自己尝试做一些 OPC 的一些朋友发现，说 OK，我变现的速度未必有很快的增长。所以这个商业模式的构建，大家一定要重新去思考这件事情。

然后呢，我们也看到了一些趋势吧，我觉得也是给大家一块去做一些探讨。

那第一个的话呢，其实大家不要关注一些特别和我们特别通用的那种需求，大家一定要看一些很 niche 的、很小的一些需求。因为原来的软件也受制于它的生产能力，所以它生产的软件一定解决的是很多共性的问题，出现一千次、一万次、十万次这样的问题，这样的话呢，他的商业回报才会 OK，因为他投入的生产成本很高，所以他一定要是做一些很普适性的、解决一些很普适的问题。但今天可能不一样了，那些解决很普适问题的，我相信是一些大厂甚至中厂的赛道。但是对于我们的个人开发者或者小的团队来讲，那可能我们真的要 focus 在一些小的场景上。但是因为今天的 AI coding 的能力给我们的加持，让我们的供给成本会不断地降低，所以我们有机会在一些很小的场景把它打磨得非常好，并且解决得很好，获得一部分很稳固的应用，但这用户体量可能不会特别大，成本也不会特别高，但我觉得是一些很值得做的一些事情，尤其是作为起步。

第二个的话呢，其实我们在做的很多平台上的软件，或者我们的作品吧——不一定是软件，可能是整体的一个作品——那可能都不是一次性的工作了，可能它都是一些这种交互性的、持续性的工作。在这个过程中的话呢，我们其实怎么能够跟我们的观众或者叫我们这个项目的受众能够互动起来，是一个非常重要的过程，它就不再是一次性交付的过程了。比如说我们相当于一个链接，这个是我们写的一个，当时去研究 strata 这个推理引擎的时候，我们一边在研究它，一边在用它，我们一边也在去学习它，就把里面的一些……它怎么去实现，它到底怎么像魔法一样把一个很低显存的，加上内存加上 SSD，就能跑起来一个很大尺寸的模型，并且性能还不错。然后把里面的机制给它深挖出来，发现这个机制我们就把它做成一个小小的互动平台，发现学 LLM 的一些基础原理、学推理引擎的一些基础原理的很多基础知识就在里面了。那我们互动性地也会更新这个平台，所以类似这样的东西呢，我觉得可能形式都会发生一些新的变化了。

第三个的话，我觉得对很多开发者来讲，对我个人、对于其他很多开发者来讲，可能都是一件比较挑战的事情：我们从开发功能变成经营自己的作品，这个思路上的转换可能是一个非常非常大的变化。因为过去开发功能的话呢，我们更多的是在思考说：哎，我有一个问题，我怎么解决这个问题？把功能给它做出来就好了。但是负责一款产品的时候呢，可能这个问题就会复杂得多。那可能第一步，在你写所有的代码、在你做所有的事情之前，你可能就要面临第一个问题：就是我到底选择做什么？我解决什么问题？有可能你这个问题选得不对，你后面做得再好可能都没有意义了。那包括你做完之后你怎么去接触用户，怎么样获得用户的感知？那包括你能不能持续地去获得用户的反馈，用来改进你的这个作品？

我们之前在社区里面也看到一些很好的开发者，他做很流程化的东西，他发出去之后呢，他通过一些社群或者一些社媒的渠道收集很多用户的意见，然后再把用户意见直接放到他的 web coding 的流程里面，让一个 agent 专门根据这些意见直接去提新的 issue，然后在整个的流程就能完全地滚起来了。所以这里边技术上不是难度，核心是大家思路上可能要思考，从过去单纯的功能实现，变成涵盖从产品经理到开发到测试到整个运转流程的所有环节可能都考虑进来，这样全面地去搭建你的流程。对，所以其实这里边你只有把你的作品经营好了，你才可能有获得直接的收费或者商业回报的可能，因为大家竞争越来越激烈。

所以第一部分其实我是想跟大家说的话呢，这个可能也是因为我一直在做技术，那很多的开发者，我觉得在这个时代大家思路上一定要转换，如果你还想从事这个行业，那你一定要从一个 coder 到 builder 的一个转换。
