### 2026年下半年的AI入口争夺战与灵光2.0

2026下半年，全球科技巨头们正在开启一场新的AI入口争夺战。硅谷的Grokbot、Muse、OpenAI Dots、Anthropic Duet，再到创业公司Instinct，个人助理（Personal Assistant）形态的AI产品纷纷出炉。AI在企业端爆发之后，个人消费端是更大的市场，那这也是为什么这是所有巨头的下一个战场。

而在中国，PA类的产品之战也开始了。但是中国市场和硅谷的生态会非常不一样。中国有着巨头们的super app（超级应用）生态，这意味着生态内的Agent打通支付、办公出行等环节会更加容易；但是在AI产品竞争更大的大陆市场，这类产品如何商业化也是重要的挑战。

这期视频播客，我们与刚发布灵光2.0的蚂蚁灵光CTO莫林剑（花名：林怿）聊了聊，他对Agent产品进化背后的思考。

一年前，灵光1.0主打的是一句话生成闪应用，让没有编程能力的普通人也能够创造自己的工具，这是一个很有想象力的方向。但是上线之后，团队也逐渐发现，用户能够创造一个应用，并不意味着这个应用真的解决了问题，创造本身也未必是一个高频需求。所以到了2.0，灵光试图把产品的重心从帮助用户创造工具转向帮助用户真正地完成目标——不只是回答一次问题，而是能够记住你的需求，持续跟踪任务，在合适的时候主动提醒，甚至在获得授权的情况下替你做事。

“提个挑战的问题：灵光1.0不如Chatbot的留存率的，这个留存率有没有给你们带来什么样的一些思考？”

“但这中间我觉得有一个比较大的反思，就是应该去关注到底这个东西最终对用户产生了多少价值。对于Agent到底能够做什么，以及它的高价值的场景在什么样的地方。如果纯粹就办公这个场景，它肯定没有生活大。”

“那你觉得什么样会是一个频率比较高的？”

“那就是每天心里可能牵挂的一些东西，比如说有孩子可能会想着娃的事情，跟钱有关的那些事，可能要出去玩。”

但与此同时，这场个人AI助手之战也带来了很多值得讨论的问题：用户真的愿意为一个AI私人助理付费吗？如果AI可以替我们完成购物，原本依赖流量和广告的平台怎么办？当AI掌握了越来越多的个人信息，我们又该如何建立信任，确保它不会做错事呢？

“你觉得用户会为这种私人秘书去付费吗？”

“背后当然是看它的核心是创造了什么增量价值。比如说它如果真的是能够给我孩子提高10分，我为什么不付费呢？我为教育花了多少钱。”

“比如说我们看到亚马逊就把Muse给挡在门外了。”

“对。”

“亚马逊作为平台方，还有比如说用户，还有Agent第三方，也就是Meta，他们是冲突的吗？”

“商业利益肯定是有关系的。”

“是不是有可能我们会看到国内的Agent会最先落地？因为super app（超级应用）里面已经有这些生态在。”

“大家都在一个大的生态里面你要去协作，它当然是比外部的，尤其是像蚂蚁内部的，这方面就会方便很多。”

哈喽大家好，欢迎来到《硅谷101》，我是陈茜。那这期节目，我们来聊聊个人AI助手之战背后的产品升级、技术进展还有商业利益平衡，来看看能够让普通人都能用到的高频高价值AI产品如何能够来到我们身边。

### 从灵光1.0到2.0：从工具创造到目标交付

>> 林怿，欢迎做客《硅谷101》。

>> 你好，陈老师。

>> 因为我知道你们刚发布了灵光2.0。

>> 对。

>> 距离灵光1.0的发布已经过去一年了，能不能跟我们说一下，为什么在这个节点要发布2.0？

>> 2.0我们其实已经酝酿蛮久了。1.0给大家印象最深的可能是做闪应用，但其实背后我们一直都是想怎么能够帮助用户更好地把事情给办好。不管是问答也好，还是应用也好，其实它都解决的是片面的一个问题。用户其实像旅行这种任务，它其实是会跨时间周期的。我们大概是从今年六七月份就在酝酿相关的一些工作了，这个时间点对我们来说其实是一个自然的结果，业界也有很多类似的一些产品出来。

>> 所以灵光2.0它的受众用户还是比较to C一点的，大众一点的，然后可以帮大家去做事情、解决问题的。

>> 对。

>> 那是不是有点对标Muse？

>> 我们当然不是说看到Muse以后才开始做。坦白说，那也来不及，我们很早就开始做那个事情了。第一，确实它就是一个面向to C的，而且我们非常希望它是一个普通人能用的。

我可以讲一下自己的。我其实很早之前就拿类似Codex来管理我的生活了，很多都是拿Codex去做办公的事情。比如说给我的孩子去做错题的纠正，把那个错题拍进去：你帮我看一下这里错了哪些地方，针对性地出一个新题，错了以后再继续，就像人工的RL那样去做。但是这个过程坦白说，普通人是用不起来的，其实有点复杂。我妻子也用不起来，更难想象说是我妈或者说是老年人能够把这个事情用起来。

>> 没有办法用自然语言，就一句话。

>> 一句话搞不定。

>> 搞不定。

>> 对，你得理解它，因为它本来就是给开发者用的。

>> 对。

>> 但是类似的能力，我觉得其实它是有泛化性的。比如拿我妈妈来举例子，她就是血压高，她也要管理自己血压。她现在怎么做？就拿一个小本子在那个上面去记着，每天的血压多少，每天记着。对，但是血压记下来只是第一步，它最关键的其实是你要去分析趋势，可能是要建议的，血压高了她应该做什么事情。这些事情其实用Codex，或者说用类似Agent来管理其实是非常合适的，但是她根本不可能把这个东西用起来。我们看到了这么强大的一个能力，但是我妈妈用不起来。那她需不需要这个能力呢？她肯定需要。我们就希望把它做成一个普通人能用的，但是又有强大的能力。

>> 这个也是不是看到了今年年初，比如说小龙虾OpenClaw，还有之后Hermes起来的那一阵？但是那一阵也是普通人用不起来，然后那个时候其实好多人有焦虑，就算装上了小龙虾，也不知道该去怎么用。

>> 对，我觉得它更多是一个启发，好像这个交互方式对我们其实是很有参考意义的。但其实背后真正推动我们的，我理解，其实我们的主线是没有变过的，都是希望怎么帮助用户把一件事情更好地完成。我们是希望从一个手段查信息、然后做一个应用，走向直接让用户跟我们去做一个目标的交互。他把目标说清楚，把那个约束说清楚，我们过程当中能够帮他主动地去做。这个是我们很自然地往上升级的一个结果。但是这过程当中是吸收了很多类似这些产品的启发的。

### Agent的技术进展与局限性

>> 要做到一个让所有人都能用起来的Agent产品，你觉得过去一年有哪些技术上的进展让我们可以做到目前Agent的能力了？

>> 技术上其实首先肯定是模型能力这块。我们在去年这个时候，可能大家还是会集中在编程、数学推理，现在这种长程的任务执行得到极大的进步，这些它肯定是条件之一。

第二，其实我觉得你很难说这里面有很多高深的技术，就是harness这一层，但它对于这么一个Agent的落地，我认为是非常关键的。

>> 对。

>> 模型其实它有自己的局限性。它的能力越强，但它有些东西是跨越不过去的。比如说我们现在还是个概率模型，它不能保证自己是百分之百正确的，很多事情必须是工程去兜底的。包括像一些新鲜的事物，因为模型的训练它可能是至少以月为周期，这些新鲜的东西其实也是要靠外围的记忆或者等等类似这些去补充的。

还有一些其他的，生态上或者说是MCP协议，其实都帮助这些事情在往前去走。比如说成本或者这些也很关键。

>> 对。

>> 不然也支撑不起去做这么多事情。

>> 您提到的这几点都非常重要，待会儿我们可以稍微地展开来聊聊。首先我还是想要回顾一下你们灵光1.0的诞生。从灵光1.0开始研发到2.0期间，你们对市场给你们的反馈有一些什么经验可以习得的？

>> 我们产品不是说从一个已有的业务去做加法，我们大概的想法还是希望切着那个技术前沿去做事情。比如说去判断半年或者说一年以后技术可能会往哪里去发展，围绕这个能力去构建相应的产品。我们去年开始做的时候，很大的一个趋势肯定是coding这块，类似这些能力它是不是能够帮助到我们的目标，去帮助人完成事情？很自然的一个点就是写程序，帮人去写闪应用。你从一句话能够写应用，它的门槛就被打得足够低了，普通人也能够用得起来。

### 反思留存率与闪应用激励计划

>> 提个挑战的问题：我们也看到数据说灵光1.0推出来了之后，它的三日留存率当时是在20%出头，不如chatbot的留存率。有没有给你们带来什么样的一些思考？在设计2.0的时候，这些思考怎么在产品形态上给你们带来一些新的想法？

>> 一方面是要看这些数字，另一方面我觉得还是应该看内核的那块，就是说真正有用的、会反复使用的那个应用，它是不是在增长，它有没有被反复使用。但坦白说，闪应用的制作其实它并不是那么高频的东西，很多人还是偏向于用的。所以我们后来为什么做灵光圈或者等等，不是每个人都有那么多的主意他是想要去制作的。

但是这中间我觉得有一个比较大的反思，就是应该去关注到底这个东西最终对用户产生了多少价值。

>> 对。

>> 它不是应该看这个数字，它做出来的应用不代表它的价值，应该是用户真正把它用起来、真正解决用户问题的那些才是那个价值。所以回到2.0的话，我觉得一方面是我们去看什么东西，或者说是怎么去判断它的价值，我觉得这方面我们会延续的，我们不会只是去看它的那个数字了，有多少人创建。这中间有太多太多其他的一些因素去干扰，核心还是希望看它有没有帮助用户真正地去完成事情，帮他去提供那个增量的价值。

>> 我看Muse它现在的留存率可能是20%出头的留存率，这个数字在你看来觉得比你预期中的要高、要低？

>> 如果是我的话，我可能会想看它那批会创建那个目标类似这样的一些人，就深度使用它产品的这个人数到底有没有持续地增长和留存。它的大盘是有其他因素在的，跟我们闪应用当时可能有点像，因为它是爆火，爆火必然会带入大量的那种用户。它的产品如果真的说是过来人就被吸住了，当然是最理想的，但也会有很多其他的干扰因素在的。所以我觉得也应该这样去看待它，比如说它有三到五个目标的真正他很关心的这批人，这批人他到底是不是持续地在增长，有没有持续在留存。站在我的视角来说，我可能也会这样去看待我们上线以后的那个情况。

>> 但我看它其实最近应该是超过了1000万的用户，应该是增长非常非常快了，但是它新增的那个速率其实是在下降的。这个是必然的是吗？

>> 我觉得可能是会遇到的，跟能力的进化可能也是有相关的。但对我们来说，我觉得还是有一点应该是共同的，还是应该回到那个最核心的用户价值这一块。

>> 我看灵光1.0的时候，你们当时是给了一亿元的闪应用激励计划。你觉得一亿元当时这个花得值吗？如果值的话，2.0会推出相应的激励计划吗？如果不值的话，你觉得其中的经验教训是什么？

>> 培养习惯上它肯定是有价值的，就是让更多人去了解它，去做出第一个自己的应用。

>> 相当于市场教育。

>> 有点这种市场教育的价值，我觉得这方面其实是比较明确的。第二个其实我们激励的那个对象也不只是创建本身，它也激励做好的产品这一块。当时是和灵光圈强绑定的，希望大家把自己的东西给做出来。不仅是做是第一步，做出来以后你能够做出好的东西来，好的东西以后你能分享，得到大家的认可，更多的人能够基于结果去做一些修改。

这里面其实能看到，真正能做出非常非常精品的，其实门槛还是比较高的。我觉得综合的能力或者之类的可能是还有进步的空间。大家做出那种简单的来和解决自己身边随手的解决问题这种，其实还是OK的。

### 市场教育与GUI加对话的交互范式

>> 你觉得现在通用Agent还需要市场教育吗？比如说我们看到Meta它其实也用了一些激励的方式，就是说我——但是它是送token，比如说我用我的邀请码邀请了你，这样的话我们俩都可以有多少多少token的免费额度。其实也是在——

>> 应该是一种分裂。

>> 对，社交裂变的这种方式，但也是在底层用token的补贴。但是ChatGPT它当时就没有用任何的go to market方式。为什么你觉得chatbot当时不需要，但是Agent现在还需要？Agent需要的原因是因为市场教育做得还不够，还是说Agent现在能力还不到说让大家自发地想去用？

>> 我觉得它有可能多方面的因素。Meta这么做，他肯定有抢市场的那个在里面。它和ChatGPT当年可能时间点也不一样，当年ChatGPT其实是独树一帜。

>> 对，没有竞争那时候。

>> 没有竞争，对，这情况是不一样的。Meta的话，它肯定是面临那个激烈的市场竞争的，所以它用裂变这种方式去做市场营销，我觉得是无可厚非的，跟那个市场也有关系。

另一方面，因为人已经被培养成用chatbot这种习惯了。他用Personal Agent，他要把自己的目标告诉它，而不是说我给它一个问题。他不应该是问说“南疆的天气怎么样”，而是说“我要去南疆玩，你帮我那个什么”。就这个习惯其实还是需要去培养的，就是要让用户能够知道他是可以这样用的。我觉得这里还是会有一些习惯的转移。但后者我觉得是更符合人性的，他只要说出自己的目的就可以了。

>> 完全改变用户习惯这件事情没有那么容易，对不对？因为在互联网以及移动互联网期间，我们已经——用户的习惯被培养成我要打开一个APP，然后我用点点点的操作，然后去完成一件事情。但是我现在的用户习惯要变成我就用自然语言，我告诉我的PA（个人智能体）我要做什么，然后它自动去帮我完成。但是这两个交互范式的改变，它其实会是一个10X效率的提升，或者是变得更加便捷。你觉得有10X吗？

>> 我是这么认为，我认为不会是一个取代，我认为这两者就应该融合，就应该是更好地融合才对。

>> 你觉得之前的范式也不会消失？

>> 我觉得不会消失，而且这两者会更好。举个例子就是GUI（图形界面）这种操作方式，它有非常非常大的一个天然优势。一方面像你前面说的，很多人被教育了；第二个，它是封装了步骤在里面的。你比如说一件复杂的事情，你在上面点，第一步我勾选那个目的地，第二步选什么或者之类，这种方式其实一看就懂，而且它是封装了最佳流程在里面的。

如果说是纯对话或者之类的话，它要是知道它一句话把所有的东西都说完整当然是好的了，但是这个太自由，人可能也不一定知道下一步自己应该把什么东西给表达出来。所以我觉得GUI这个方式它是一个很好的封装，就是一种最佳流程。或者说一个重复性的行程，其实你点可能比你说话更方便。我点一下这件事情给做完了，我点一下总比我说这句话会更方便。

>> 对。

>> 所以我觉得是不会消失的，这两者一定会更好地融合的。然后我们在这方面其实是有蛮多探索的。我们做那个1.0的时候，其实当时的对话就是GUI加对话结合的方式，就是那种用最好的方式去和用户交互，然后用最好的——希望用最好的方式能够把一个信息呈现给用户。就信息效率最高的方式，有时候就是一图胜千言，有时候你做一个交互的动画比你说一万句话都好用，就是类似这种。我觉得2.0里面也是一样的，因为自然语言它不一定是最有效率的沟通方式。

>> 对。

>> 而且很多的东西它没法用语言表达出来。

>> 对，是这样的。

>> 比如说我描述这个空间是什么样子，我用一句话咋说呀？

>> 写张800字的论文。

>> 对，我拍张照片是最好的对不对？

>> 对。

>> 所以我觉得这个不会是这样的，它一定是多种输入——

>> 多模态。

>> 多模态的输入，或者非结构化的输入，然后它的输出应该是结构化的。

### 高频高价值场景：生活账单、旅行规划与私人秘书

>> 通用的Agent带来最多价值的是什么？比如说，我们说一下灵光2.0，你们看到大家觉得最有价值的一些场景是在什么样的地方？

>> 因为我们接入了像支付宝生态的一些能力，我一个朋友他让它分析一下他账单里面花的冤枉钱有哪一些，能不能省钱。分析的结果是他的退款金额比消费的金额高5倍，就是买的东西退款的金额比消费的高5倍，买了6件衣服退了5件留下一件，然后给他分析的结果说他是个冲动型消费者，他就说戳中他了。
