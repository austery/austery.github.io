### 元工具链（Meta Harness）与工程记忆落地

**Alex**: 我不知道我们之前是否在节目里聊过这个概念，但我觉得大家一定会对我们在 Tenex 采用的工程工作流非常感兴趣——也就是所谓的“**元工具链**”（Meta Harness）。正是这套工作流，支撑我们在处理复杂且耗时漫长的长程任务时，依然能交付高价值的成果。CJ，你要不要向大家详细拆解一下我们的整套流程？

<details>
<summary>Original English</summary>

**Alex**: I think one thing you'd also, I don't know if we've talked about this before, but like the, this idea of like the meta harness, which is like the, the engineering workflows at Tenex that we use that has allowed us to do, I think like really meaningful work on long running tasks. Do you want to just talk through like what our process is? Cause I feel like people would find that interesting.

</details>

**CJ**: 好的。我们最初做的事情，其实是试图对一系列技能（Skills）进行沉淀和标准化。我想现阶段大多数软件工程团队或多或少都在做类似的探索。

而在我们团队内部，这项探索逐步演化为一套存在于代码仓库中的**高结构化规范文档**，以及一套围绕它构建的专属 **CLI 命令行工具**。各类 AI 模型正是通过调用这套 CLI，来实质性地驱动各项工程任务的推进——无论是生成实现方案、绘制架构可视化图表，还是为客户生成项目汇报文档。从本质上讲，它把除实际编写代码之外的所有外围流程节点，都变成了可以在我们团队内部跨成员自动、标准化执行的机制。

具体而言，我们包含几个关键支柱：

首先是一份大型的**权威规划文档**（Canonical Plan Document）。它拥有严谨的骨架结构，不过随着底层模型能力的不断进化，我们在具体格式的硬性约束上反而进行了一定程度的松绑。

一旦规划文档确立，你就开始步入实际构建阶段。我们对智能体在执行任务时**如何记录决策轨迹、记录正在进行的操作、实时追踪任务状态**有着非常明确且强硬的约定。

<details>
<summary>Original English</summary>

**CJ**: Yeah. So we basically started trying to kind of standardize a set of skills. Um, I think most engineering orgs have done something similar by this point. Um, and for us that grew into what is actually like a very structured set of documentation within a repo and then a CLI that's around it that kind of the models are using to actually drive the work that's being done, whether it's creating a plan, a visualization, you know, creating some readout for a client, effectively like building all the pieces of the process around actually writing the code to just happen more automatically and standard across our team. So we have a couple of things, Like one is this like big canonical plan document that has some similar structure, but I'd say as the models have gotten better, we've actually reduced the enforcements there in the structure. Kind of similarly across all of these. But once you have your plan, you actually build it out.
