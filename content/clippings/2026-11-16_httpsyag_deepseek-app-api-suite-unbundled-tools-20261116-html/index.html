给 Agent 接 DeepSeek 新出的全家桶 API，真正好用的是那几个独立接口

关键字 ai-tooling api deepseek tool-interface cost-optimization

摘要

DeepSeek 发布了全套应用接口，将官方客户端的周边功能（如联网搜索、文档识别等）拆分成了独立工具接口，供开发者调用。文章指出，内置全家桶开关限制了自定义工具的混用和模型参数的控制，而独立工具接口的优势在于其低价（如搜索接口每千次仅收 5 元人民币）和解耦性，使得开发者可以绕开内置模式的限制，将底层工具作为自定义工具接入智能体，从而降低成本。同时，官方对外部服务提出了高水位安全审核要求，并明确了安全审核算力将计入总输出词元账单的机制。

以前，很多人都认为 DeepSeek 的官方网页版和手机端比开发者的 API 更实用。这是因为官方客户端提供了联网搜索、阅读网页链接、解析几十页长的文档以及语音朗读等周边功能，而开发者的 API 只能进行纯文本对话。2026 年 11 月 13 日，DeepSeek 发布了全套应用接口公告，将这些官方客户端中的周边功能作为 API 一次全部开放，并开源了一个可以立即使用的网页前端项目 chat-demo。

这次开放的接口提供了两种截然不同的调用方式：一种是内置全家桶开关，调用轻量模型 deepseek-flash 聊天时直接在请求里打开联网搜索或读文档的开关，DeepSeek 服务端就会自动在后台搜网页、读链接，最后把整理好的现成回答返回给你；另一种是独立工具接口，DeepSeek 把底层的网页搜索、网页抓取、文档识别、语音识别和语音合成单独拆成了 5 个接口，就算不调用 DeepSeek 的大模型，也能把这些接口单独拿来当搜索引擎、网页转 Markdown 爬虫或文档识别器用。很多开发者的第一反应是去用省事的第一种内置全家桶开关。但只要翻开 DeepSeek 的技术文档、动手往自己的智能体代码里接一次就会发现，这套内置开关是个连自定义工具都不允许混用的封闭黑盒，常规的智能体接不进去。真正给所有开发者带来实惠的，是 DeepSeek 单独拆出来低价售卖的独立工具接口。

为什么省事的对话内置开关，反而接不进常规的

Agent？

开发者看到第一种内置全家桶开关只需在对话请求里加个参数就能自动联网和读文档，第一反应就是把现有的智能体代码加上这个开关，少写几行工具调用的胶水代码。而且早些时候 OpenAI 的 Responses API 和 Anthropic 的 Messages API 也都推出了类似的服务器端内置搜索工具，为什么海外大厂的内置工具可以接进智能体，DeepSeek 的内置全家桶开关反而接不进去呢？

这背后的原因是，OpenAI 对 Responses API 的定位是提供一个通用的云端运行平台，它可以在这个平台上保存对话历史状态，并且把官方内置的搜索工具和代码沙盒跟开发者自己的业务函数（下称自定义工具）混在一起调用。但 DeepSeek 虽然兼容了 Responses API 的请求格式，却没有提供一个通用的云端运行平台。DeepSeek 的 API 文档明确说它不支持保存会话历史状态，也直接忽略了代码沙盒、向量检索等传入参数。研发人员走了一条更省事的捷径：把自家官方网页版内部用强化学习训练好的固定后端流水线直接暴露出来，而且仅支持轻量模型 deepseek-flash。这样直接暴露内部流水线的设计，就带来了三个直接限制。

第一个限制是开启内置开关后禁止混用自定义工具。平时做智能体应用，往往需要用到各种自定义工具，比如查询内部数据库、读写本地文件等等。但是，DeepSeek 的搭建对话机器人的指南里面明确提到，如果你开启了内置的联网搜索、读取网页链接、高水位安全审核、会话标题生成中任何一个功能，那么这个请求就不能同时指定任何自定义工具，否则就会返回一个 400 错误码。这就让内置的全家桶开关没办法接入任何需要执行外部动作的业务系统。

第二个限制是锁死模型参数与输出格式。开启这些开关后，请求中指定的采样温度、核采样率、停止词和思考预算等控制参数全部静默失效。如果业务代码依赖模型返回 JSON 结构化格式，或者需要助手消息前缀续写，开启联网或安全审核开关后同样会直接报错。就连给模型传入当天日期和所在城市的方式，也必须严格照搬 DeepSeek 官方网页版的内部协议。平时写应用，开发者习惯把当天日期写进顶层的系统提示词里；但如果每天日期一变就改系统提示词，此前攒下的历史对话前缀缓存就会全部失效。为了保住前缀缓存命中率，DeepSeek 要求开发者必须在每条用户消息之前，紧挨着塞入一条固定格式的 latest_reminder 角色消息来传递日期和地点，放错位置同样会报错。

第三个限制是网页正文加密与上下文清理。为了防止外部开发者把内置工具当成免费爬虫，内置搜索和深度思考搜索返回的结果块里，网页内容全部加密成了密文，客户端拿不到明文。到了下一轮对话，这些搜索结果还会从模型的上下文记忆里清除，只留下上一轮的回答文本。内置读链接工具返回的网页正文字段干脆恒为空字符串，加密后的内容藏在签名字段里，多轮对话时必须由客户端把整块签名原样传回服务端做内部拼接。这套防线决定了内置全家桶开关只适合配合官方开源的 chat-demo 前端，原样克隆一个纯聊天网站。

不绑大模型的独立工具接口，是怎么把搜索和解析价格压下来的？

既然内置全家桶开关是个封闭黑盒，普通智能体开发者能从这次更新里拿到什么实惠？答案藏在公告后半截。正因为内置全家桶开关无法与自定义工具共存，连 OpenAI 官方的编程助手 Codex 接进来都用不了那套内置搜索。为了解决这个冲突，DeepSeek 在同一天把底层的网页搜索、网页抓取、文档识别、语音识别和语音合成，全部做成了不绑定大模型对话、可以单独调用的独立工具接口。在官方同步更新的 Codex 一键配置脚本里，研发团队就是直接为模型默认开启了独立联网搜索通道，让 Codex 绕开内置模式，直接调用底层的搜索与抓取接口。

这种把底层工具拆出来单卖的做法，走到了海外大厂的反面。在 OpenAI 和 Anthropic 的体系里，联网搜索固定焊死在大模型推理流程中。你不调用 GPT 或 Claude，就没法单独使用它们的搜索能力，而且每搜索 1000 次要交 10 美元的工具调用费，检索内容拼入上下文后还要另付模型词元费。DeepSeek 的独立工具接口则不需要调用它的大模型。哪怕你的智能体用 GPT 或 Claude 当主脑，也能直接拿 DeepSeek 的密钥去调它的搜索和抓取接口。对比下方的价格就能看出，它的搜索与网页抓取每千次仅收 5 元人民币，搜索失败或结果为空还不扣费，单价不到海外大厂的十分之一。

而更省钱的一点是，DeepSeek 的自建搜索引擎有一个全文返回的特性。在网页搜索与抓取指南中，DeepSeek 首次披露了其独立搜索接口是由 DeepSeek 自己研发的搜索引擎提供支持。这个引擎针对智能体做了优化，在进行搜索时不仅可以提供关键词，还可以额外提供用户的原始提问来帮助引擎理解意图。每个搜索结果不仅有相关性分数、网站权威度和简短摘要，还有一个围绕原始提问提取的 800 字左右高密度摘要。此外，如果在搜索请求中包含 need_content 参数，还会返回每个搜索结果的 Markdown 格式完整正文。不论单条查询返回默认数量还是最多 50 篇结果，开启全文返回都不会增加单次搜索的价格，仍然只收半毛钱人民币。相比之下，第三方的搜索工具 Firecrawl 则会根据返回的网页数量逐页收取积分，搜一次再抓十几个网页的全文，成本要高出十倍以上。

除此之外，独立的文档识别接口也支持直接上传 PDF、Word、PPT 和常见的图片，提供纯文字直接提取和逐页保留排版的识别两种模式，每识别 1000 页只需要 1.5 元人民币。如果开发者把纯文本、代码或表格文件通过文件接口上传并内联拼进对话上下文中，也是完全免收工具解析费的。

DeepSeek 独立搜索接口将搜索与网页全文抓取解耦并以 5 元千次的价格大幅低于海外内置搜索与第三方检索工具

官方反复警告的合规下移，在账单和代码里是怎么落地的？

在了解工具能力和价格后，许多开发者还注意到一个细节。此次公告以醒目篇幅提醒，面向外部提供服务的开发者应启用高水位安全审核参数，并自行承担算法备案和内容审核的主体责任。不少人好奇，这究竟只是例行的法务免责声明，还是真的会反映在工程代码和接口账单上？

查阅开放平台的服务条款可以发现，关于平台只提供中立的接口、下游开发者需要自己进行大模型的登记备案和内容安全审核的规定，早在 2026 年 4 月 22 日就已经修订写入，并在几天后正式生效。为什么这次公告如此着重强调这一点？因为以前的接口只能支持纯文本对话，一旦放开了全网实时搜索、任意网页抓取和开箱即用的前端源码，任何人都可以在几分钟内构建一个带有实时联网能力的对话网站。平台希望出售这些组件，同时不替下游应用承担监管风险或补贴内容审核所需的算力。为此，官方在模型的内容安全指南中制定了一套职责与账单切分规则，将内容安全审核作为一个由开发者自费买单的收费项目。

第一笔开销是审核算力按模型输出单价收费。开发者按建议把安全审核开关调到高水位后，服务端审查输入和输出所消耗的算力会折算成安全词元，直接计入总输出词元账单，按 deepseek-flash 每百万输出词元 4 元人民币的单价收费。第二笔开销是触发违规拦截照样扣费。如果用户的提问未通过审核，接口直接返回 400 风险错误，但输入词元依然按缓存命中单价扣费；如果内置读链接工具抓回了目标网页，随后因未通过审核而返回禁止访问的错误块，这半毛钱的抓取费同样照收不误。

第三处工程细节落在流式输出的前端清屏要求上。流式输出时，文字是一个词一个词蹦出来的。如果生成中途触发了安全拦截，比如模型吐到一半的内容或用户上传的图片未通过审核，服务端无法撤回已经发出的文本块。这时服务端会停止生成并在末尾下发拒答信号，前面已生成的全部词元照常计费，同时官方要求客户端在收到拒答信号后必须自行清除界面上已展示的内容。翻看一下开源的 chat-demo 源码就能看到，前端接收流式回复的代码里专门写了拦截逻辑，一旦捕获到拒答状态，就立刻把界面上的思考过程和回答正文清空并替换成提示文案。

DeepSeek 应用全家桶 API 分为受限的内置对话模式与面向智能体开发者的独立工具接口两条路径

手头有项目的开发者，现在怎么接这套接口最划算？

看清了内置全家桶开关的绑定限制、独立工具接口的低价红利，以及安全审核的自费清屏机制后，手头有项目的开发者可以根据业务形态，按三条路径来做取舍。如果你正在开发自己的智能体或给工作流配工具，哪怕主力模型用的是 GPT 或 Claude，最划算的做法都是绕开对话接口里的内置全家桶开关。你可以申请一个 DeepSeek 密钥，只把独立搜索、网页抓取和文档识别这三个独立工具接口封装成普通的自定义工具函数。这样做既不会撞上封禁自定义工具的报错限制，又能凭借远低于市面同类服务的检索与识别单价，把原本昂贵的第三方工具账单降下九成以上。

如果你日常用 Claude Code 或 Codex 敲码，可以直接升级官方刚更新的接入配置。DeepSeek 已经在底层帮这两把刀躲过了内置开关的限制：Codex 的最新配置脚本默认用独立搜索和抓取接口，而 DeepSeek 的 Anthropic 兼容接口也在服务端做了专门适配，让 Claude Code 触发内置联网搜索时可以直接调通底层搜索引擎。

如果你只是想快速做个面向国内用户的纯聊天网页，而且不打算挂自己的业务工具，可以用 deepseek-flash 内置的全家桶开关加上 chat-demo 前端。但上线前要接受两个限制：模型采样参数固定、不能混用自定义工具；以及开启高水位安全审核、把安全词元计入成本，还要在前端收到拒答信号后自动清屏。

这套独立工具接口刚在 11 月 13 日上线，目前公开的技术文档和实测主要验证了它的接口形态和计费规则。它在长尾英文技术资料、反爬严密的垂直社区以及高并发峰值下的实际召回质量与稳定性，还有待大规模生产流量和第三方基准测试的检验。
