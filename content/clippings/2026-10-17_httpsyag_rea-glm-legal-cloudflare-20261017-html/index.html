一周三件事：REA 把逆向工程交给 agent、智谱发布法律模型 GLM-Legal、Cloudflare 把 agent 基础设施做成原语

关键字 agent-engineering reverse-engineering ai-tooling legal-ai cloudflare

摘要

文章关注了AI Agent工程领域一周内三项进展：开源项目REA将传统逆向工程工具接入代码助手，智谱发布了面向法律领域的AI模型GLM-Legal，以及Cloudflare将网页抓取和搜索能力做成代理的基础设施原语。核心观点是，这些进展正在将原本需要专业技能或独立服务器的垂直能力沉淀为通用开发者平台上的现成组件，但面对加固代码、长链条真实案件等复杂场景，仍存在安全限制和性能瓶颈。

最近一周，在AI Agent的工程方面，有三件事情值得关注：开源项目REA让我们可以用一行命令把传统的逆向工程工具接入到日常的代码助手里；智谱发布了一个面向法律领域的AI模型GLM-Legal，并在真实的律师事务所业务流程上做了评测；Cloudflare集中更新了网页搜索、网页抓取和代码助手的运行环境等多种能力。

这三件事看似分散，但指向同一个方向：Agent 所需的核心能力正在被沉淀为标准构件——从依赖专家手艺、专用人力或独立服务器的垂直场景，变成通用开发者平台上的现成零件。

REA

把逆向工程的门槛降到一行命令

拿到一个能跑的app，却拿不到写它的源码，想搞清楚它怎么工作、演示功能靠什么公式计算、为什么对外传数据，传统方法是反汇编机器码，一步步恢复可读函数。这个倒推软件逻辑的过程叫逆向工程。

REA 全称 Reverse Engineer Anything，是一个把传统逆向工具接给代码助手调用的开源项目（项目仓库）。它本身不训练新模型，而是一个基于 MCP 的工具服务端和命令行工具，开发者执行一行 npx rea-agents setup，就能把它接入现有的代码助手。

在官方演示里，有一款 1996 年的 Windows 游戏 DX-Ball，只留下了残缺的伪代码。作者用这些零散信息补全并生成了 C 语言函数，通过了原程序的 3205 个 x86 测试用例，编译出的 63 个函数与当年的二进制字节完全一致。其他演示还有分析手机验证码的轮换算法（为什么每 30 秒变一次）、桌面笔记软件的剪贴板接口，以及早期飞行射击游戏子弹的发射角度公式。

REA 本身并没有取代传统意义上的反汇编器和逆向工程引擎，而是作为代码助手和逆向工具之间的中介。如果需要更深入地分析本地二进制文件，仍然需要使用专业的逆向工具，比如美国国家安全局 2019 年开源的反编译器 Ghidra、从上世纪 90 年代起通行的 IDA，或是 2011 年出现的 Hopper。它会针对不同的分析对象使用不同的工具组合，比如用无头版的 JADX 和 Apktool 分析安卓 App，用 Binwalk 分析固件，对 JavaScript 和 .Net 程序则直接使用静态分析。官方文档还展示了它能分析的更多目标，包括 Go 的二进制程序、WebAssembly 程序、崩溃日志和网络抓包记录。

REA 处在代码助手与底层逆向工具之间的中转位置：左侧是 Claude Code 等代码助手，中间是 REA 的 MCP 服务端，右侧是 Ghidra、IDA、JADX 等传统逆向工具，开发者只需一行命令即可接入。

这些专业工具的交互界面复杂，分析结果也很庞大，使用者往往需要从大量反汇编指令和内存跳转中找出关键逻辑。REA 的改进之处在于，它将这些底层工具输出的大量底层信息进行了整理，形成了模型可以理解并逐步调用的结构化调用链。过去需要人工翻阅反编译结果、逐行猜测变量用途的过程，现在转变为开发者用自然语言提出需求，代码助手自行规划工具调用的步骤，逐层剥离逻辑并归纳结论。

这个项目的代码库创建于 2026 年 4 月，前几个月关注度一般。直到 2026 年 10 月初，集成了 Android 无头分析的 4.1.0 版本发布之后，才迎来爆发。npm 官方显示发布日期是 10 月 6 日（中文社区多按北京时间记为 10 月 7 日）。新版本发布后，它在 Hacker News 的讨论区获得 783 点评分，GitHub 星标在约 5 到 6 天内从数万迅速升至 14 万量级，截至 10 月 12 日实测已超过 15 万，而官方页面自报的 11 万星标则反映出数据更新的滞后。

当我们将分析能力委托给通用模型时，模型服务商设置的安全护栏成为另一个关键限制。在实际测试中，直接要求主流模型逆向商业软件往往会导致拒答或中途停止。例如，据媒体报道，有博主用 Claude 分析商业视频剪辑软件剪映时，遇到了卡顿和限制。REA 在本地分析目标，但代码助手会接收分析结果；使用远程模型时，本地执行不意味着这些结果都留在机器上，结果仍受模型服务商数据政策的约束。具体哪些请求会被判定为恶意逆向，其边界由服务商的策略决定。REA 的官方免责声明也明确指出，该工具不应用于规避模型提供商的安全限制。

不过和社交网络上”闭源软件全面沦陷”的夸张说法不同，多个技术验证都显示当前工具存在明确的边界。安全研究者指出，REA 目前不支持真正的动态调试，对没有保护或者轻度混淆的程序可以较快解析，但对 VMProtect 等虚拟机加固保护就很难。据媒体转述，法国安全团队 Quarkslab 曾用 Claude Opus 5 分析几个层层加固的 AArch64 二进制、寻找隐藏字符串，没有一个样本被真正破解；遇到阻碍时，agent 会绕路，甚至提交看似正确但实际编造的报告。

同时，现代互联网应用的核心业务逻辑通常运行在云端服务器上，客户端反编译可以分析客户端内部逻辑，但无法触及服务端的具体实现。从法律合规的角度来看，如果一个代码助手在阅读反编译代码的同时还编写新代码，可能会破坏旨在防范侵权的净室开发原则。官方 README 和免责声明列出的用途包括合法研究、教学、互操作性、软件保存，以及分析自有或获授权的软件；不支持绕过反作弊或复制专有软件。这里要区分两类材料：关于强加壳的局限性和模型拒答，来自独立技术团队与媒体的实测；而 DX-Ball 字节一致性这类案例，来自官方项目文档的自述。

GLM-Legal：达前沿还是第七名

2026 年 10 月 12 日，智谱在官方博客发布了一个面向专业法律工作的模型 GLM-Legal。该模型不是从头训练的旗舰系列，而是在智谱 2026 年 8 月发布的轻量级基座 GLM-5.3-Flash 之上进行了二次预训练和高效后训练。官方公布的基座规格为 3200 亿总参数量和 180 亿激活参数量，支持 100 万 token 的上下文窗口。

官方介绍这个模型先扩展了高质量的法律语料，加强案件事实、法律规则和判决结论之间的演绎关系，然后在数万个真实的法律环境中通过强化学习来优化，让调用执行框架和模型一起迭代。现在还在公测中，API 需要申请，官方没有公布定价，但未来计划接入桌面代理平台 AutoClaw（发布时还未来得及集成）。

为了理解 GLM-Legal 的水平如何，我们需要把它放在行业背景下进行观察。GLM-Legal 的成绩是在法律 AI 公司 Harvey 于 2026 年 5 月发布的智能体基准 Harvey LAB 上测得的。这个基准覆盖了 24 个执业领域的真实律所工作流程，包括合同审查、尽职调查和撰写法律备忘录等长链路任务。它的设计非常严格：一道题有多个评分项，模型必须全部满足才能算通过，没有部分分；测试中模型可以调用搜索和文件阅读等工具，且有两个判定模型进行审核。

官方声称 GLM-Legal 在这个基准上的全通过率为 19.2%，比未经微调的通用基座模型高出 12.5 个百分点，并且在专业合同和案件分析测试中达到了前沿闭源模型的水平。但独立评测平台 Vals AI 在同一基准的留出集上进行了测试，得到的评测通过率为 19.17%，在 79 个模型配置中排名第七（榜单）。榜单前 6 个模型的得分均高于 GLM-Legal，其中 Meta 的基准模型 Muse Spark 1.2 以 25.42% 的通过率位列榜首。在运行开销方面，虽然官方尚未公布商用 API 价格，但根据 Vals AI 的独立实测，GLM-Legal 的单次测试花费约为 0.15 美元，远低于前沿通用模型动辄 10 美元以上的单次测算费用。不过，其单次平均推理时间达到了 1 小时 12 分钟。总的来说，它相比基座模型有了显著提升，但与榜首仍有相当差距，因此官方所说的达到前沿水平需要结合榜单进行客观审视。

这种技术路线体现了行业内部的分歧。我们在《OpenAI进军法律市场，却选了最轻的一种做法》中也提到过，OpenAI 在 2026 年 9 月发布的解决方案没有改动模型的底模权重，而是使用包含 2.3 亿 URL 的外部法律检索索引和定制提示词来构建服务。法律领域的模型开发经历了从头预训练、全参数微调、后训练强化学习到轻量外挂配置的演变。

GLM-Legal 采取了不同的技术策略。它没有像 OpenAI 那样只依赖外部的搜索和提示工程而不对权重进行更改，而是更改模型权重，在一个相对较小的通用模型上加入法律领域的数据，并利用强化学习进行微调。这一方法更接近 Harvey 之前采取的垂直领域优化方法，旨在通过更少的参数和推理成本实现特定专业领域的性能提升。需要注意的是，训练细节和 19.2% 的通过率都来自智谱官方，而第七名的结果则来自 Vals AI 对留出集的评估。至于 GLM-Legal 本身的具体参数量（3200 亿只是基座大小）和权重是否开源，官方没有公布，所以我们无法确定它是开源的还是闭源的。

Cloudflare 把 agent

的眼睛和手做成平台原语

在过去的一周中，网络基础设施提供商 Cloudflare 针对 AI 代理的工程实现发布了一系列更新。这些更新不仅包括零散的接口修复，还涉及内容获取、检索入口、功能发现和运行时环境的平台化抽象。

让代理获取网页内容是这批更新的核心支柱。在这个方向上，Cloudflare 推出了两项能力，它们本质上是同一套HTML 转Markdown 转换管线在不同场景的两端。

一端是站点侧的 Markdown for Agents：当请求头里声明需要 Markdown 时，Cloudflare 的边缘网络就把网页转换成Markdown返回给你。在这次更新中，单页解压后的处理上限从2 MiB提升到了6 MiB（6,291,456字节）。同时，它移除了用来估算 token 的响应头和 Content-Length 头部，依赖这些字段的客户端需要改代码自行计算。

另一方面，代理端的 web_fetch 工具（Agents SDK 0.28.0 beta）在执行任务时可主动抓取指定 URL，并使用完全相同的转换引擎将 HTML、PDF 或文档清洗为 Markdown。若目标站点本身已支持直接输出 Markdown，该工具可直接获取原始文档。对于外部网页内容，web_fetch 会在其外层添加非信任内容标记，并在文档中说明这不能保证绝对防止提示词注入攻击。二者的逻辑互为镜像：前者在站点侧提供 Markdown，后者让代理按需抓取指定 URL 并获取 Markdown，减少代理自行处理复杂 HTML 的工作。

与内容读取相配套的另一个关键能力是检索工具 web_search。它基于 Cloudflare Web Search API，底层由 ceramic.ai、Exa 和 Linkup 联合驱动，需要在 Agents SDK 0.27.0 以上版本。代理在输入检索词后，即可得到结构化的网页标题、链接与摘要，并通过系统提示引导与 web_fetch 结合以抓取全文。搜索与抓取这两个原语成对配合，构成了代理在互联网上自主搜集最新信息的完整闭环。

除了搜集外部信息以外，Cloudflare 也解决了代理如何调用云端能力的问题。在 MCP 里，他们开始提供专门的技能包。外部代码助手可以通过 Skills over MCP 扩展动态列出 Cloudflare 技能并读取其内容，把平台能力变成代理可以自动发现和直接调用的东西。

在执行与运行方面，SDK 0.28.0 引入了实验性的 OpenCodeHarness，使得我们可以将开源代码助手 OpenCode 2.0 直接在 Cloudflare 标准的 Durable Object 运行时中运行，使用内置的 SQLite 来持久化会话状态，并在无服务器实例被回收时使用生命周期作业进行重新激活以继续执行任务。这让我们可以在轻量级的边缘有状态计算上实现代码助手，而无需使用独立的虚拟机或复杂的常驻后端。

Cloudflare 在边缘同时铺两条通路：内容层把 HTML 就地转成 Markdown，能力层把平台 API 做成可经 MCP 发现的 skills。

对于打算使用这套工具的开发者来说，需要注意SDK的版本要求：搜索工具需要Agents SDK 0.27.0以上版本，内容抓取和OpenCodeHarness则需要使用0.28.0版本。

Cloudflare的这一系列变化展现了云厂商正在将代理的基础设施进行标准化。在《2026年做一个Manus，哪些地基不用再手搓了》中，我们用Amazon Bedrock AgentCore为例介绍了代理需要采购的五大基础设施：隔离的计算环境、会话粘性、长期记忆、凭证管理和运行可观测性。AgentCore主要侧重于为代理提供坚固的计算底座和长效状态保持环境；而Cloudflare的更新则主要集中在能力交互层，主要为代理装上浏览检索的眼睛和抓取内容的手，以及提供一个轻量级的代码助手运行架子。

这与我们在 《Muse 出了事下载还在涨》 里提到的常驻代理相呼应。Meta 做的常驻代理 Muse 自带远程云电脑，替用户管登录和长期记忆。Cloudflare 现在给的搜索、抓取和轻量运行环境，是拼凑类似系统的零件，而不是现成的云电脑代理。涉及敏感操作时，仍需另外配置隔离环境和用户凭据托管。

小结：三件事各自把什么做成了现成件，又各自卡在哪

这三件事都发生在最近一周，各自把以前需要专门技能、专业团队或独立服务器才能完成的一段，变成了别人可以直接使用的东西。

REA 让开发者用一行命令，把 Ghidra、JADX 这类工具接进日常代码助手，用自然语言调用反编译。但对 VMP 等高强度虚拟化保护，现有实测显示仍难以处理；客户端逆向也看不到云端服务器上真正跑的业务逻辑，代码助手接收分析结果时还会受服务商安全策略的限制。

智谱的 GLM-Legal 基于轻量级基座加入法律知识，并进行了法律环境中的强化学习；Vals AI 记录的单次测试成本约为 0.15 美元。但在涵盖数十个领域的严格基准测试中，它的全通过率仅位列第七，前面有六个模型更强；单次平均耗时仍超过一小时，真实案件处理能力仍需实战检验。

Cloudflare 利用边缘网络的网页抓取能力，将网页内容直接转换为 Markdown，为代码助手提供了现成的搜索与抓取功能，并支持开源 agent 直接在边缘有状态运行时中运行。然而，它仅提供搜集信息和执行调用的组件，若想要构建一个能够长期处理敏感数据和替用户进行操作的完整代理，仍需另外配置长期隔离环境和账号凭据托管。

用现成工具搭架子变容易了。只是面对加固加壳的代码、长链条的真实案件，或者需要接管敏感权限的生产场景，能走多远，碰到的依然是原来那些还没解决的硬限制。
