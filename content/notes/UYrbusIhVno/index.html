授权、YOLO 模式与隔离

但是我有个问题问老修，就是你在 GLM 的话，你怎么给他授权呢？就是我按照小苏给我建议，直接在 Claude Code 里面装了这个 GLM，对吧？然后装完之后，但是每一次经常他会要求我授权，就会经常打断那些任务。对，就这种 OK OK……问呢，唉，这是 YOLO 模式。这是个好问题，就是这个 YOLO 模式你可能不知道，因为 Claude Code 是一个 CLI，对，就是他有一个叫……其实就是 Bypass Permissions，就是所有的东西都授权。

那我建议的是，你找一个安全的磁盘，里面开一个安全的目录，然后这里完全授权给他，然后让他在里面随便找。但是比如说，我想让他读取我硬盘上的文件，或者读取我那个 drive 里的文件，这个时候就必须要跨过这个目录去授权。像这种情况下，那有没有风险呢？或者说能不能授这个权呢？

我觉得这个是任务的边界，我觉得不是模型或者是说权限的边界啊。就比如说你真的要跑任务，你隔离一台单独的电脑，其实当然是很爽了，但是跟你的本机，我们叫所谓什么上下文，对吧，他就断掉了。对。那很多时候其实边界是任务的边界。你可能在本机放个文件，你要跑，但是你跑的是固定的几个 skill，或者固定的一些程序，对吧？那其实也能够隔离掉大部分的风险。

我的做法是，我用一台虚拟机，这台虚拟机在我的主电脑上，那这台虚拟机肯定跟我的主电脑是隔离的。但是我的主电脑可以共享一个关键的目录，就比如说这个目录叫做 downloads，这是我下载的一些东西。那下载的东西一般都不是很重要的，网上下的嘛，肯定有 copy 的，你随便干。但是我会把一些重要的、共通的上下文的文档啊，或者什么东西，就放到 download 里面，然后这台虚拟机可以去读我的 download。如果我需要什么东西，我就往那 download 扔，就完了。那这样子的话，就可以达到一个基本上比较安全。

企业与小企业主视角：切换的摩擦
