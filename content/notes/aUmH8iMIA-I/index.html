摘要

微軟執行長薩蒂亞·納德拉在對話中指出，當程式碼產生變得廉價時，驗證成為核心挑戰。他提出「決策引擎」作為 AI 時代的基礎原語，並強調軟體工廠的轉變在於規範與意圖的重要性。此外，他針對 AI 帶來的職位變革、企業自主權以及混合智能（混合雲端與本地模型）等議題分享了微軟的策略與觀察。

大家好，這裡是最佳夥伴，我是大飛。微軟執行長薩蒂亞·納德拉最近做客「務實工程師」播客節目，與主持人格爾蓋伊·奧羅斯進行了一小時的對話。這次討論直接提出了一個問題：當程式碼產生變得廉價時，軟體工程還剩下什麼？納德拉在談話中發表了一番意味深長的評論，他說：「在一個代碼生成成本已經很低的時代，難點在於驗證。」你可以記住這句話，因為我們之後還會反覆提到它。

首先，這次對話的特別之處在於：納德拉是極少數從軟體工程師一路晉升為大型科技公司執行長的人之一。他早期曾在 Sun Microsystems 工作，並於 2014 年接管微軟，成為微軟的第三任 CEO。Orosz 以前也在微軟工作過，所以這是一個老同事的重聚。這次聊天沒有絲毫客套，許多問題都非常尖銳，例如為什麼微軟錯過了雲端/行動變革的最初浪潮？例如，自願離職計劃是否實際上是裁員的前奏。嘉賓如此重量級，提問又如此直率，從中可以獲得許多寶貴的見解。

微軟與開源

這段對話要從 12 年前說起；納德拉在 2014 年上任時，微軟仍然是一家非常封閉的公司。外界對微軟的印象仍然停留在 20 世紀 90 年代的 Windows 時代，但在納德拉接管之後，微軟發生了徹底的轉變：他們推出了 VS Code，收購了 GitHub，並用 Git 完全取代了內部的 TFS。TypeScript 也是開源的。當時奧羅斯正在微軟倫敦辦公室，他說連他自己都感到驚訝：為什麼微軟要全心投入開源？

納德拉的解釋非常坦率：他說，一旦某種敘事和公眾印象形成，改變它們就需要付出巨大的努力。事實上，甚至在他擔任 CEO 之前，微軟對 Linux 的程式碼貢獻就已經相當顯著了，只是外界並不了解而已。他們真正想要確保的是，公司內外的每個人都明白微軟對開源是認真的。因此，將 SQL 遷移到 Linux、為 Linux 做出貢獻以及開源 TypeScript 都是這項承諾的一部分。

他還補充了一個有趣的觀點：如果你真正計算每家公司從開源軟體中獲得了多少，以及他們回饋了多少，那麼微軟的排名將會名列前茅，甚至可能位居第一。相反，一些從開源軟體中獲益最多的公司卻貢獻甚微。當然，他也承認抱怨是沒用的；這就是世界的運作方式。敘述和事實往往是兩回事。

對於開發者社群而言，更大的影響力實際上並非開源本身，而是 VS Code——它不僅是開源的，而且是免費的。納德拉回憶起使用 Visual Studio 2003 的經歷，這款軟體至今仍然是一款非常出色的軟體，微軟最終向全球開發者免費贈送了一款開源編輯器——它在五到十年內變得無處不在。這是故意的嗎？納德拉表示完全正確。當時由 Erich Gamma 領導的團隊有意與社區共同開發它。對納德拉來說，這是他第一次真正接觸到「開放式開發」的含義——團隊每天觀察社群的回饋來決定開發什麼，而不是只聽從副總裁的意見。他認為這種文化轉變甚至比開源本身更重要。他甚至認為微軟應該更深刻地吸取這些教訓，並進一步運用。

人工智慧與產品形態

隨後，對話轉向了人工智慧，人工智慧領域存在著引人入勝的競爭；微軟很早就進入了人工智慧領域——你可能會問，進入的程度如何？Copilot 出現時，ChatGPT 甚至還沒有發布；大約是 GPT-3 時代。用納德拉的話來說，程式碼自動完成功能的出現就像魔法一樣，而且整整一年裡，都沒有真正的競爭對手。納德拉本人表示，在 IntelliSense 進行多年研究後，他們突然意識到這種新方法確實有效。看到這些結果後，他對「尺度定律」的信念得到了根本性的加強；轉折點是 2023 年 Cursor 的出現，它源自於 VS Code，感覺很熟悉，但它的代理模式才是它真正的亮點。然後，在 2025 年，克勞德·科德橫空出世。

納德拉的描述非常務實——他指出，新創公司，甚至大型科技公司的人，都可以在短短六個月內重新發明 IDE。他直接問納德拉：微軟擁有開發者的基因，那為什麼你會錯過如此突然的轉變？這是我第一次覺得你沒有未雨綢繆。納德拉沒有迴避這個問題；他承認 Anthropic 做得非常出色，將命令列介面變成了一個可以完全接受任務、將程式碼從輸入轉換為輸出的真正產品。

然後，他發表了我認為是整個談話中最重要的一番話。以模型為基礎的產品開發有一條鐵律：當模型能力呈現非線性成長時，產品形式必須快速適應。他表示，人工智慧優先的產品開發在這方面是殘酷無情的。你的一切都圍繞著現有模型構建，同時做好準備，當下一代模型展現出新功能時，對一切進行徹底改造。他最初的話很直白：不要愛上你已經建立的東西。

他還補充了一個有趣的觀察結果，他說他已經開始重新使用 IDE，因為在決策引擎模型出現之後，IDE 的功能更像是嵌入在軟體中的智慧功能。因此他得出結論，變革不會總是朝著一個方向發展，而是多種形式並存，每一種形式都能幫助你發揮模型的功能。

決策引擎

在這裡，我們需要解釋他反覆提到的「決策引擎」，因為這是理解整個對話的關鍵。在納德拉看來，決策引擎是一種全新的原始技術；二哥和他們自己的決策引擎團隊都在推動這個理念。他打了個比方，說這有點像 Excel 巨集——巨集為電子表格帶來的變化可能類似於將智慧作為一種基本元素嵌入程式碼中發生的情況。

他舉了微軟內部的一個例子：Xbox 團隊有一個管理社群回饋的系統，當收到回饋時，系統必須做出一系列判斷。在這種情況下，他不希望大型語言模型每次都重新產生程式碼；他只是想讓它做出決定。因此，嵌入像決策引擎這樣的原語（它有自己的機率分佈）可以進行直接調用，避免重複生成，並節省大量令牌。

納德拉表示，他很喜歡迪奧的一個想法：讓決策引擎像資料庫一樣普及。他本身是一名工程師，從小就接觸關係型資料庫，關係型資料庫是他最喜歡的開發工具之一。Oroz 完美地接過了話茬，指出軟體公司的本質是業務邏輯，但深入研究後發現，大量的業務邏輯實際上都體現在資料庫儲存過程中。納德拉藉此機會總結道，決策引擎是人工智慧時代的儲存過程。

驗證與軟體工廠

好了，讓我們回到開頭的陳述：驗證才是真正的挑戰。納德拉甚至表示，他想加入馬克·魯西諾維奇、斯科特和塞爾策在微軟內部開展的培訓計畫。這是因為他承認自己從未在以程式碼為主要產出的團隊中工作過。當程式碼產生輸出時，會遵循特定的操作順序；這並非是每個人都隨意產生一堆程式碼。真正的技巧在於如何建立驗證系統，例如將每一次失敗轉換為一個用例，並確保測試本身已經真正驗證。他提到 ROS 遷移曾經是一場災難，不得不回滾；這些新的優勢和新的弊端同時存在。

這段內容中還有另一個細節讓我覺得很有趣：納德拉說，過去人們在微軟實習時會研究戴夫·卡特勒的程式碼，並查看 Malloc 的實現，但他表示，我們必須找到如今與之等效的現代實現方式。當一位執行長說他的夢想是回到一線當工程師時，這確實很有意思。

接下來，我們討論了「軟體工廠」。這個詞最近很流行，但它的意思仍然很模糊。Dara 的解釋是，一個根本性的轉變是程式碼已經從輸入變成了輸出，這使得規範和意圖比以往任何時候都更加重要。設計文件以前就很重要，但現在更重要了，團隊協調也是如此。他提到了一個反直覺的現象：現在接手一個不熟悉的程式碼庫其實比以前更容易了。因為在管理軟體工廠時，所有事情都有文件記錄；你可以直接向系統提問，就像身邊有一位耐心的導師一樣，而不是費力地去挖掘只存在於人們頭腦中的知識。

他還詳細闡述了驗證方法，指出對於智能體編程，必須將任務分解，確認每個小任務都真正完成，並在審查期間使用不同的模型系列。Dara 說他一直擔心一件事：如果整個供應鏈只使用一個模型系列，而這個模型系列存在對齊問題，那麼它的限制就會變成你的限制。他用從手工編寫彙編程式碼到使用編譯器的轉變來做類比；突然間，你可以直接從意圖到程式碼，而無需了解每個彙編細節。雖然抽象程度提高了，但團隊協作和建立產品的方式也隨之改變了。

他感興趣的一個方向是將生產環境中的執行軌跡回饋回來——有些人稱之為「自我改進軌跡」。他的版本是取得生產日誌，進行驗證、修復、部署，並確認它通過所有測試；他所追求的正是這種可驗證的閉環效應所帶來的投資報酬率。

微軟內部最生動的例子就是 O&R 網路團隊。微軟的全球網路涉及約 500 家光纖營運商，而有形資產總是難免會出現問題。管理這些事情的流行術語是「DevOps」，但實際上，它依賴電子郵件和各種臨時流程。該團隊建立了一個代理系統來處理操作，並將其與他們的程式碼庫整合在一起。因此，技術團隊的工作性質發生了變化；他們不再手工完成每一項任務，而是建造一個將操作和軟體結合的工廠，讓工廠來完成工作。

那麼，對於那些已經擁有成熟產品的團隊來說，又該怎麼辦呢？這是一個非常實際的問題；你不可能放下一切去建造一座新工廠。納德拉的回答很務實：他首先承認微軟犯了錯誤，創建了一些隨機的人工智慧項目，只是為了看起來很酷。然後他以 Windows 為例。在人工智慧模型發現更多 CVE 漏洞後，微軟不得不修復這些漏洞，這自然導致了新管道的創建。從崩潰執行追蹤到補丁，它本質上是在現有系統之上建立一種新型的軟體工廠。

在這些類型的專案中，最困難的部分通常是建置系統和 CI/CD。GitHub 的底層基礎設施是相同的，各種人工智慧代理商湧入其中完成工作。其規模遠遠超出了人類的能力範圍，需要對 GitHub 的協定和儲存系統進行根本性的調整。他喜歡這種轉變的原因在於，它不是為新團隊配備新工具，而讓其他人繼續使用舊工具，而是讓公司裡的每個人都能使用新的工具鏈和工作流程。

這次與過去的技術變革有何不同

齊澤克在這裡提出了一個很好的問題：這與當年採用 React 有什麼不同？當新技術出現時，每個人都想使用它，但它通常是透過逐步推出的新功能來實現的；沒有人會為了全面遷移而停止一切工作。納德拉的回答值得深思：他說，有時他覺得他見過類似的情況，但這一次，我們工作方式的物理機制——包括執行順序和抽象層——已經發生了變化。

他談到了自己的職業生涯；大學時，他使用過 VAX 小型電腦上的 VT 終端。後來，在 Sun 工作站上，以及加入微軟之後，世界趨於穩定；他的整個職業生涯基本上都是在整合開發環境（IDE）中編寫程式碼。新科技層出不窮，但它們只不過是新的框架或執行環境而已；核心概念保持不變，甚至行動裝置也可以被視為縮小版的個人電腦。但這次，運行時、框架和 IDE 都在變化，新的模型隨時可能出現，從而重塑整個範式。因此，他的結論是：要腳踏實地：回顧你應對變化最成功的經驗，但也要保持開放的心態，承認這次可能真的有所不同。

工程師的技能與職涯

在討論這位工程師的個人經驗時，這或許是最感動的部分。Orosz 表示，軟體工程師過去大部分時間都花在編寫程式碼上，但突然間，這部分時間正在消失。以往的科技變革總是會帶來新的工具；歷史上從未有過核心技能被剝奪的情況。那麼那些花費數十年時間成為程式大師的人呢？納德拉的回答是，仍然需要同樣的技能；操作順序和工具鏈發生了哪些變化？這並非貶低專業技能，而是為現有能力增添新的優勢。他發現，在微軟，那些對某個領域有深刻理解，同時又保持足夠好奇心去學習新的工作方式的人，正在蓬勃發展。

他在 GitHub 上結識了一群學生，他們是第一批在人工智慧時代成長的畢業生。GitHub Copilot 在他們上學時就已經存在了，所以他們根本不知道沒有它工作是什麼感覺，這讓他深感震撼。但他也非常關心一件事：職業生涯的經濟回報至關重要。微軟希望員工能夠充分利用現有技能，同時培養市場認可的新技能。

自願離職計畫與裁員疑慮

接下來是本次會議中最尖銳的問題：自願離境計畫。奧羅茲直接提出了這個問題，並指出有些人擔心，人工智慧帶來的效率提升可能會導致裁員。納德拉的回答包含多個層面。首先，他承認未來仍會有很多機會，只是形式與過去不同。其次，透過在公司內部創造更多新的機會，無論是從事 Windows 開發或 AI 培訓，都有機會學習到公司內外都認可的新技能。第三，對於一家擁有 20 萬名員工的公司（而且員工人數可能還會持續成長），資源分配方式必須有所不同。看看現在系統工程師和基礎設施人員的薪酬有多高；人工智慧訓練領域的研究人員也面臨同樣的情況。某些專業技能競爭非常激烈，價值很高。因此，該志願計劃的核心是賦予人們更大的自主權，使個人能夠選擇適合其長期職業發展的職位。

納德拉也說了一些非常人性化的話：他擔任執行長已經很久了，但他最初是從一名普通員工做起的。他不希望任何人被困在一個沒有改變的團隊中，即使這個團隊就在微軟內部。他不希望公司製造出無法掌控自己命運的焦慮感。關於「奇點」到來，只剩下一家公司，所有工作都會消失的說法——即使是那些願意改變的人也會感到害怕。

納德拉也提到了一個與職位相關的訊號：成長最快的職位之一是現場部署工程師（FDE）。客戶經理旁邊是客戶成功團隊和技術團隊，再往前走是 FDE（現場執行工程師）。這些職位的人員都應該接受與軟體工程師類似的訓練。LinkedIn 也進行了內部調整，將一些職位合併到「全端建構者」這個職位名稱下。對於那些規劃職業生涯的人來說，這是一個非常明確的信號。

早期招聘也是一個熱門話題；許多公司已經放緩甚至暫停了校園招聘，理由是那些最擅長使用人工智慧的人都是經驗豐富的專業人士。Dara 認為我們應該從更長的時間跨度來看待這一趨勢，而不僅僅是關注接下來的一年。先讓內部人員和團隊到位，然後再討論招募新員工的問題。部分放緩的原因可能是首先要建立新的軟體工程工廠，確保新的投入（不僅是代幣，還有人）一旦進入新的配置就能發揮高槓桿作用。

他所描述的這家人工智慧原生公司非常生動：它最初只有一個人，外加一筆象徵性的預算。這個人會在僱用新人之前把現有預算用完。新進員工也有預算，整個工廠也有預算。它是一步一步建成的；如果成功，它就會發展壯大，有些已經相當大了。因此，他認為現在就這一長期趨勢得出明確結論還為時過早。

開放模型與企業自主權

我認為，接下來的部分是整個對話中最具戰略意義的部分，它涉及開放模式和企業自主權，他觀察到了這個行業趨勢。許多科技公司正在轉向開放模型和自託管推理；甚至有人購買了 B200 自行部署。在更廣泛的領域，他們也透過提供開放式服務為他人服務。我問這股浪潮究竟有多大，以及它是否類似過去的開源運動。

Dara 的回答是從認知框架出發的，他認為，除非你相信存在一個掌握世界所有知識的單一模型，否則你必須反過來假設，世界上每家公司都應該有一個相應的模型。在這裡，他引用了哈耶克對經濟的描述：知識是分散的、隱性的。因為知識是經濟中隱含的，所以價格機制才如此重要。由於每家公司都需要掌握自己的知識，他提出了一個概念：每家公司都擁有人力資本和代幣資本，其中代幣資本可以是一個嵌入自身知識的開放權重模型。

你也可以這樣玩：同時使用多個封閉模型，收集它們產生的執行軌跡，並使用這些軌跡來訓練你自己的小型模型和開放權重模型，從而形成組合。他做出了一個預測：也許到他們下次談話時，人們將不再沉迷於開源與閉源之爭，而是每個人都會有自己的模式。

這個系統的起點是一個決策引擎，它決定為哪個任務使用哪個模型，包括上下文、記憶和動作空間，所有這些都必須與任何單一模型分離；否則，就完全被供應商鎖定了。它清楚地表明了一點：如果你的安全帶、模型和記憶體都緊密耦合在一起，你甚至無法退出。你真的認為自己能擁有任何東西嗎？錯誤的。該模型會吸收它所看到的一切。

Oros 表示，他接觸的中型科技公司和新創公司都在建立自己的框架、上下文層和推理系統。他起初認為工程師只是喜歡建造東西，但在聽了德拉的論點後，他意識到他們可能正在為他們的公司做一些具有戰略意義的重要事情。德拉非常強調這一點：如果你是一家銀行，那就看看軟體公司是如何在這個生態系統中佔據領先地位的。他們不會放棄控制權，所以銀行也不應該放棄控制權。

而微軟正在做的，是將這些模型的底層技術提升為一流的服務，並在平台內以託管服務的形式提供。您也可以自備 LLM 或其他開源模型；您擁有多個模型端點、一個完全獨立的上下文層，並且記憶體歸您所有。行動空間相同；插件、技能和連接器都是相互獨立的。雖然公開的基準有其價值，但您自己的私人評估更為重要，因為它們衡量的是您真正關心的結果。因此，您必須在自己的強化學習環境中觀察各種模型的實際表現，並不斷優化它們。

他描述了一個常見的客戶路徑：使用前沿模型來累積軌跡，一旦確定了確定性的工作流程並且需要優化成本，就換用快速模型，並使用現有的軌跡對其進行微調——就是這樣。

在這裡，他提供了一個非常生動的比喻。過去，銀行和保險公司會購買關聯式資料庫，部署它們，購買包含業務邏輯的軟體套件，然後編寫自己的業務邏輯來擴展它，從而保持控制權。資料庫中的資料不會落入他人之手。即使供應商停止提供更新，您仍然可以遷移到其他系統。但與今天的 AI 相比：如果你的記憶被困在模型的嵌入中，而模型公司表示他們不會再給你更新，你如何提取你的記憶？

因此，他希望企業能認真討論兩個架構決策。首先，要避免他所說的「逆資訊悖論」——不要洩漏你自身的價值。企業必須掌握自身的閉環學習，將上下文與模型解耦，採用多模型方法，並保持記憶體獨立性。他說，你應該能夠更換任何模型，同時也能持續提升自己的私人評估結果。如果做不到，你必須問自己：你還是自主經營的企業嗎？

第二點是信任架構；規模化是有效的，但規模化帶來的新功能並不會自動導致一致性。隨著能力的增強，可靠性可能會越來越差；這是一個非常危險的狀態。因此，從架構上講，我們必須將權限與智慧分開。掌握不可靠情報相當於龐大的內部風險。將這些代理人視為內部威脅進行管理；思維鏈不能是模型的內部神經語言，它必須是人類語言——可審計、可記錄、不可篡改。這個問題並非只出現在預訓練或強化學習階段；獎勵作弊也可能發生在測驗時計算過程中。因此，我們必須在運行時建立實質的安全保障措施，並保持可觀測性。

本地模型與混合智能

演講的最後兩部分也很有見地。一種是本地模式；人們經常抱怨人工智慧模型要麼在別人的雲端，要麼在沒人買得起的 B200 伺服器上，而本地部署總是很麻煩。然而，微軟正在不斷創新：新款 Surface 筆記型電腦配備了專用晶片，可以在本地運行前沿模型。納德拉的評估是，分散式計算將永遠保持分散式狀態。既然如此，為什麼不充分利用運算能力，而只關注雲端運算呢？2025 年發布的 Frontier 型號現在已經可以在筆記型電腦上運行，而 2026 年第三季度發布的型號將可以在台式機上運行；因此，Copilot Fusion 路由會根據任務選擇模型，代理群中的一些子任務會調用本地模型，而其他子任務則會調用雲端模型。

他為這個階段取了個名字：混合智能時代。雲端運算持續成長，對代幣的需求幾乎是無限的，但邊緣設備也可以成為代幣工廠；他稱之為「不按使用量計費的智慧」，因為你無需擔心使用量。

還有一個細節打破了現有的誤解。人們一直認為在筆記型電腦上運行的任何程式都必須是開源的，但 Gemini 1.5 Flash 雖然是閉源的，但實際上可以下載並在 Windows 機器上運行。他還透露了自己的模型策略：在繼續與 OpenAI 合作並使用其模型的同時，他正在從零開始創新自己的 Phi 模型系列。新的 Phi-3.5 基礎公開了所謂的最全面的預訓練配方之一，而且完全透明。他提到將多個代理分配給高級意圖，以便這些代理可以使用不同的模型系列；只依附於一個家庭的想法已經過時了。

給工程師的建議

最後，給工程師的建議是：納德拉的說法很簡單──要紮根於改變本身，真正理解改變是什麼，而不是閱讀新聞標題，不要被週期性的炒作所迷惑。雖然他開玩笑說在柏克萊說這話很諷刺，但他想改變自己誇誇其談與付諸行動的比例，加倍投入行動。無論你是職業生涯中期的 CEO 還是應屆畢業生，你都需要花更多的時間在實踐中學習，並加入真正創造產品的團隊；這比什麼都重要。他認為自己何時狀態最佳？那是他處於學習狀態的時候。那麼，我們回學校吧。

聽完整個對話，我的理解是，這個行業確實正在經歷一場徹底的變革，但在納德拉看來，還有大量的軟體工程工作等著完成。我們可以圍繞決策引擎和尚未發明的原語等新概念來建立新系統，決定哪些東西放在哪裡，如何調整它們，如何部署它們，以及如何實現持續學習。感謝收看，我們下次再見。是的。
