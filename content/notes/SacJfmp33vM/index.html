硬件共享的隐形代价：云端多租户 GPU 侧信道威胁

在现代云基础设施中，大型语言模型（Large Language Model: 基于海量参数构建的深度学习模型）通常部署在昂贵的高性能计算卡上（如 NVIDIA H100）。为了最大化硬件利用率并降低服务成本，云服务商普遍引入多租户共享机制，将单一物理 GPU 切分给多个不同的客户共同使用。表面上看，虚拟化层与硬件分区提供了相互隔离的执行边界；然而，物理硬件上的共享资源却为恶意的“邻居”打开了一扇隐蔽的侧信道大门。攻击者完全不需要传统的系统漏洞利用（Exploit），也无需获取目标系统的 root 访问权限，仅需以普通租户身份在同一物理卡上运行轻量级测量代码，通过捕捉共享硬件访问的时序波动，便能推断出同机邻居的模型架构、解码速率乃至生成内容的特征。

在揭示具体的攻击向量前，安全研究团队 Stealthium 指出，虽然业界对共享计算资源的虚拟化隔离抱有高度信任，但这种安全假设正受到底层物理特性的严重挑战。

MIG 硬件切分下的资源隐患：二级缓存争用

在 NVIDIA 架构中，多实例 GPU（Multi-Instance GPU: 将单个 GPU 划分为多达七个独立硬件实例的技术，简称 MIG）被广泛宣传为具备完全硬件级隔离能力的方案。在 MIG 配置下，每个实例被分配了独立的计算单元（Streaming Multiprocessors）和专有的显存（VRAM），硬件上实现了显存地址空间的严格屏障。例如在实验环境中，受害者运行的大模型被分配在拥有 48GB VRAM 的主要计算分片上，而攻击者仅占有一个最小规格的切片（10GB VRAM）。尽管在计算核心、显存总线配额和带宽上实现了精细的分离，甚至 L2 缓存（Level 2 Cache: GPU 核心与显存之间的高速共享缓冲层）也在逻辑上划分了切片，但底层物理互连和访问仲裁仍存在跨分片的关联。

当受害者实例在全负荷处理矩阵计算时，其密集的显存读写操作不可避免地会在共享总线与交叉开关网络上产生物理争用。攻击者只需在自己的实例内不断分配微小缓冲区，并测量其访问延迟的微秒级变化：

  • 微时序测量周期：攻击者以约每 5 微秒一次的频次执行探针读取。
  • 物理延迟偏置：虽然正常读写与受害模型活跃时的中位数延迟差异仅有约 3 微秒，但这一极其细微的时间扰动已足以形成具有统计意义的侧信道信号。
  • 无特权穿透：该测量仅访问攻击者自身的显存空间，未触碰任何受害者数据地址，却能准确反映整个芯片级内存子系统的负载波动。

这一现象印证了此前学术界（如 USENIX Security 会议论文）关于跨切片硬件干扰的研究，证明 MIG 虽能防止内存越界读写，但无法抹平微架构层面的执行时序痕迹。

频谱分析与层数反推：97% 精度的模型指纹重构

通过捕获这 3 微秒级别的细微显存读写延迟扰动，攻击者可以在时域与频域上完整还原出大语言模型的自回归解码节奏。由于大模型在自回归生成时以 Token（词元: 模型处理与生成的最小文本单元）为步长运行，每生成一个 Token 都会经历完整的注意力计算与前馈网络推理，这在硬件时序图谱上呈现出极其清晰的周期性“心跳”脉冲。

在此基础上，时序数据在频域的特征分解揭示了更深层次的内部构造：

  • 主频与谐波特征：实测显示，自回归计算会在约 881 Hz 处激发出基波频率，同时伴随多个清晰的高次谐波。
  • 层数特征映射：单个 Token 的生成周期内，显存压力波峰直观反映了 Transformer 的网络深度。例如在某个实测模型中，每个生成周期精确出现 39 个连续的子峰值，直接暴露了该模型由 39 个隐藏层 堆叠而成。
  • 解码速率还原：Token 解码速度的反推准确率达到了惊人的 99.3%，这意味着邻居租户何时开始请求、回答耗时多久、输出了多少个 Token，均处于全透明状态。

为了在海量候选模型中自动匹配，攻击团队设计了一种无需复杂机器学习训练的极简分类算法。该算法仅需不足 30 行核心逻辑，通过计算测试时序与已知模型架构（支持最高达 48 层）的皮尔逊相关性，即可以 97% 的极高准确率 锁定受害者正在调用的模型架构与精确层数。即便是对于完全未在预设库中注册的闭源或私有模型，算法也能凭借其层数指纹直接缩小分析范围。

内容级嗅探：推测解码与任务分类破解

单纯获取模型结构和 Token 数量并不足以还原具体的语义活动。然而，现代推理框架为追求极致性能所引入的优化机制，却反向泄露了具体的交互内容。推测解码（Speculative Decoding: 一种利用小型草稿模型快速预测多个词元、再由大型目标模型一次性并行验证的高性能推理技术）在此处成为了信息泄漏的放大器。在 vLLM 等开源高性能推理服务引擎中，推测解码机制决定了每次验证被接受的 Token 数量完全依赖于生成文本的预测难度。

当受害者处理不同类型的生成任务时，推测解码的接受率展现出本质区别：

  • 结构化文本的高接受率：代码（Code）、JSON 或标准查询语法（Search）具备极强的确定性，草稿模型预测准确率高，目标模型一次验证通过的 Token 数量较多。
  • 自由文本的低接受率：发散性较强的人类自然语言（Prose/散文）随机性极高，接受率显著下滑，迫使目标模型频繁回退并重新顺序生成。

这种由于接受率变化导致的计算时间步差异，在硬件监控上形成了明显的功耗与时延“阶梯”。在测试包括 Dense 模型、混合专家模型（Mixture of Experts: 激活子网络稀疏计算的架构，简称 MoE）、BF16 以及 FP8 量化在内的 11 种不同配置后，攻击者建立起高鲁棒性的任务分类器：每 0.5 秒提取过去 5 秒的运行特征进行判定，在 40 个半秒决策窗口中，多达 31 个窗口给出完全正确的分类，仅需极短时间即可断定受害者是在输出格式化数据还是在生成自由叙述。

NVLink 互连拓展：跨芯片网络中的时序泄漏

如果说 MIG 是在单颗物理晶圆内进行的切分，那么多卡并行集群中的高速互连总线则构成了更大范围的侧信道媒介。在标准的 8 卡 H100 节点中，所有 GPU 均挂载在 NVLink（NVIDIA 研发的高带宽双向专有互连总线协议）交换网络上。当受害用户的模型采用 张量并行（Tensor Parallelism: 将单层矩阵切分并分配给多个 GPU 协同计算的技术）跨越 GPU 0 与 GPU 1 运行时，攻击者仅需租用同一台服务器中完全处于空闲或轻量工作状态的 GPU 2 即可发起渗透。

由于多卡共享 NVLink 交换矩阵，跨卡访问显存的物理路径与仲裁逻辑直接暴露了时延指纹：

  • 空闲时延基线：正常情况下，GPU 2 跨总线访问 GPU 0 显存的基线时延约为 890 纳秒。
  • 业务拥塞峰值：当 GPU 0 与 GPU 1 之间启动密集的前向/反向通信与张量同步时，该链路访问延迟剧烈飙升，可达 300 微秒以上。
  • 信噪比与识别率：与单芯片 MIG 相比，NVLink 路径上的网络抖动导致信噪比有所下降，无法直接看清每一个物理层脉冲，但宏观时序特征依然非常清晰。在五种不同模型的测试集上，针对受害模型的分类识别率仍维持在 79.2% 的极高水准（远超随机猜测基线 20%）。

更为危险的是，该信道具备实时的流式嗅探能力。攻击者可以实时监听每一次内核发射（Kernel Launch），甚至在受害模型的端到端完整回答输出（耗时约 600 毫秒、输出不足 50 个 Token）完毕之前，便已通过前半段的传输模式捕获了其执行指纹。

云端 AI 基础设施防御反思：重构运行时安全边界

面对物理共享硬件层面的信息泄露，传统的“容器隔离”和“虚拟化壁垒”理念已经不足以提供完备的保护。为了抵御这类隐蔽的微架构嗅探，基础设施提供商与模型运营方必须重新审视系统级防御契约：

  • 慎审调度与物理共置策略：云调度器在分配 GPU 实例时，对于处理高敏业务（如企业级核心资产模型或隐私数据处理）的租户，必须避免与不可信租户共享同一块物理 GPU（无论是否开启 MIG）。
  • 权衡架构隔离与性能代价：必须明确技术特性的取舍。MIG 虽然提供了一定程度的片上隔离，但阻断了单实例内部跨节点的张量并行；而跨多卡张量并行虽然提升了推理吞吐，但通过 NVLink 交换机引入了更大范围的全局侧信道暴露。运营方必须在互联性能与攻击面扩大之间建立量化的风险评估机制。
  • 主动式微架构异常监控：防御者不能再将 GPU 视作黑盒设备。正如 Stealthium 在其安全监控实践中所展示的，监控系统必须主动分析各 GPU 实例上的内核执行特征与内存访问模式。一旦捕获到具有周期性、异常短时隙读写等侧信道探测特征的作业，应立即触发警报并将其隔离或动态迁移。

共享硬件的执行时序是物理规律的必然投射。只有在硬件设计、集群调度与运行时行为监测三方协同建立动态防护，才能从根本上保障云端大模型服务的数据与知识产权安全。
