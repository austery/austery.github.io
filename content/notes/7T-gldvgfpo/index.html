意图传达重构：从命令式提示到声明式契约

在人工智能发展的过去数年中，虽然底层模型基准测试、调度框架与上下文窗口不断迭代，但构建智能系统的核心瓶颈始终未变：如何精准、低摩擦地将人类大脑中的意图与需求对齐给超级智能。早期在开源大模型社区（如 EleutherAI）中备受推崇的“提示词工程技巧”，本质上是在强行弥补模型理解能力的不足；但随着模型推理能力的几何级跃升，微观层面的语法雕琢与命令式提示（Imperative Prompting）正迅速过时。

现代 Agent 架构的核心演进方向是从“指导每一步操作细节（How）”转向“严格规约最终目标状态（What）”。如果我们将工作流限定在一步步教导模型点击哪个按钮、编写哪些局部代码，那么只要模型能力稍微提升或底层工具调用发生变更，整套指令系统便会彻底脆化失效。声明式契约（Declarative Contract: 仅规定系统必须满足的约束、验收标准与终止状态，将执行路径与工具决策权完全让渡给模型推理器）将目标与实现解耦：更强大的模型能以更少步数、更高质量达成契约，而轻量模型则可自动退化执行分支，从而实现了系统架构的长期鲁棒性。

OpenProse 架构：基于 Markdown 的声明式契约与执行环境

基于上述声明式哲学构建的 OpenProse（OpenProse: 一种使用结构化 Markdown 定义多智能体程序与契约状态的编排规范），将自然语言直接提升为可执行的工程制品。在传统的软件工程中，系统状态通过类型检查与单元测试进行约束；而在 Agent 系统中，状态约束则被升格为 运行时契约（Runtime Contract）。开发者或系统代理仅需在命令行界面（CLI）中通过简单的 prose run 或调用写入函数声明目标，例如指定待生成的组件功能、文档完备性标准及测试覆盖要求。

在这一底层体系中，Agent 系统具备了自愈（Self-healing）能力与模型无关性。以代码工程场景为例：当一个 Agent 负责构建全栈 Web 应用时，如果它写出的前端代码存在 TypeScript 类型冲突或编译错误，系统并不会依赖人类工程师介入调试，而是依托声明式契约中的不变条件（Invariants），由代码宿主环境或 CI/CD 流水线自动反馈反压（Backpressure）。Agent 面对编译报错直接重新审视契约，在沙箱环境中自主修改并重跑，直至满足所有预设验收契约才提交 Pull Request。这彻底改变了传统工作流对步骤脚本（Playbooks）的高度依赖。

Web 端工作流与自动化生成：契约驱动的人机协作界面

为了降低人类直接编写高严格度 Markdown 规约的门槛，系统在 Web 端构建了交互式运行时界面。对于普通用户而言，手动手写符合语法规范的抽象契约往往并不现实；因此，交互界面的首要功能是将用户的非结构化模糊诉求转化为标准化、可审计的 OpenProse 程序规范。用户无需关心语法细节，只需提供核心预期，系统内部的规划智能体便会自洽生成对应的目标规范与检查项。

在这一架构中，Agent 扮演着高度自治的任务调度器角色。以自动化研报生成或社媒内容流水线为例，系统可以注入诸如“具有怀疑精神的技术分析师”等角色性格特征（Persona），但更关键的是它在后台生成的结构化任务流：任务的启动、阶段流转、状态保存与产出物校验全部透明可见。执行过程具备严苛的可审计性（Auditability）——每次运行均被完整记录，用户可随时回溯每一步推理所依据的契约规则，从而在享受高自主性带来的效率红利的同时，彻底规避传统“黑盒提示词”不可控的系统性风险。

破解自我确认闭环：子代理架构与独立评估者设计

在传统的单体 Agent 或长会话交互中，系统极易陷入自我确认偏误（Self-Confidence Bias: 同一个大语言模型在生成代码或文本后，倾向于高估自身产出质量并盲目忽略潜在缺陷）。当模型被要求自我复核时，它往往会沿用生成时的逻辑盲区，输出“代码完全正确”的虚假评估报告。为从系统层面上根除这一致命缺陷，声明式编排强制引入了会话隔离与子代理分权机制。

通过在运行时动态分派独立的子智能体（Sub-agents: 专职于特定技能、工具集合与上下文边界的轻量化代理实例），架构在物理层面上切断了错误假定的传播链条：

  • 生成端与评估端绝对解耦：负责实现业务逻辑的 Agent 绝不负责最终的验收裁决；
  • 瞬态隔离会话：验证节点会重置上下文上下文窗口，仅装载待测产出物与预设契约；
  • 确定性环境硬反馈：针对代码、接口、数据格式等刚性要求，通过真实 CLI 工具、单元测试与编译器报错提供物理反压，完全排除幻觉干扰；
  • 语义裁判对抗：针对风格、基调等软性要求，调度专门的审查子代理进行对抗性评分。

这种设计将 Agent 从自说自话的脆弱循环中解放出来，赋予系统真正的生产级确定性。

OpenProse Kernel：面向机器解析的轻量化 Markdown 原语

在技术底层，支持整套编排体系平稳运行的枢纽是 OpenProse Kernel（OpenProse 内核: 极简的系统引导规约，用于向通用基础模型注入契约解析、状态机流转与执行协议）。令人意外的是，这一内核并未采用高复杂度的二进制中间表示或晦涩的 DSL，而是一段经过精妙压缩与进化的纯 Markdown 文本。为了规避不同基础模型在理解非结构化指令时的歧义，团队通过遗传演化算法在内部基准上持续裁减核心，保留了最紧凑、最具约束力的语法骨架。

许多开发者初次接触 Kernel 时会误以为它是写给人类工程师阅读的文档，但实际上它完全面向机器。它利用 Markdown 天生的树状标题与列表结构作为状态机的词法单元，向宿主 Agent 解释如何挂载工具、何时声明任务完成、以及如何处理执行失败时的上下文退避。这种极度透明的设计消除了传统编排框架对黑盒 SDK 的强依赖，任何支持基础 Bash 环境和子代理调度的框架（乃至受控虚拟机沙盒）均可实现“即插即用”，成为跨平台驱动复杂工作流的通用底层协议。

组合式多智能体 DAG：从探索性对话迈向确定性生产工程

在应用场景的界定上，必须清晰区分探索性对话与工业级自动化流水线。当用户处于原型调研或思维发散阶段时，普通的单轮或多轮 Chat 界面是最高效的工具；但当业务进入高重复度、高可靠性与可审计性（Repeatable, Reliable, Auditable）的生产落地阶段时，传统的无序对话即宣告失效。正如现代声明式框架（如用于结构化微调与提示优化的 DSPy）要求工程师必须明确知晓系统输出目标一样，OpenProse 要求团队以工程契约为基石，构建系统化的工作流拓扑。

通过将一系列细粒度的声明式契约链接为有向无环图（Directed Acyclic Graph, DAG），开发者可以像搭建乐高积木一样组合多智能体系统：

  • 前置条件与中间检查点（Checkpoints）：每个子节点对应独立的验收契约，仅在前置契约被物理验证后才触发下游计算；
  • 语义缓存与增量重算：借助前置状态依赖比对，当上游状态未发生实质变化时复用结果，大幅降低 Token 消耗并加速流水线；
  • 全流程代码即规范（Spec-Driven Development）：无需繁复的胶水代码，仅凭百余行 Markdown 规约，便可完整调度包含“网络调研子代理”、“专业写作子代理”与“严谨校对子代理”的复杂团队，实现跨越数小时的长时间自主迭代。

这种规范驱动的开发范式，正迅速超越传统纯软件工程的狭隘边界，在金融量化模型审查、合规审计、运维保障及产品管理等广泛的知识密集型领域展现出变革性的工业价值。
