后训练循环：环境即评估

在我看来，后训练循环大致围绕环境展开，因为环境是一种用来指定你想让模型做什么的语言。

它们封装了你可能拥有的数据、你希望 agent 所处的场景、它与该环境交互的方式，以及如何对"好"打分，判断什么好什么坏。

通常你拿环境做的第一件事就是 evals。我想很多人对进入后训练可能有些紧张，他们会想："哦，这看起来工作量很大，有一整套新的工具链。如果我已经在用前沿模型，并希望从中得到好结果，或者已经得到了好结果，或者我想先看看在 harness 层面或 prompt 优化上能做什么呢？"这都没问题。我们并不一定要求人们把一切都扔掉。我认为在很多情况下，人们会发现，也是我们在客户那里看到的，对他们最有效的系统是两者并用。你要能够做出这些决定：在哪里训练合适，在哪里使用通过某个 API 提供的前沿模型合适。所以评估对此非常关键。evals 是打开后训练大门的东西。环境和 evals 本质上是同一件事。

但一旦你有了 evals，你就拥有了与做后训练本来就需要的同一种逻辑单元。所以无论你在做什么，构建 evals 对你的产品卫生都是有益的。如果你想决定用 GPT 还是 Claude，或者决定某个任务需要 Opus、Sonnet 还是 Mythos，如果你想在智能与美元之间做最优取舍，evals 是非常好的方式。但 evals 还会解锁这个飞轮。

就现代后训练而言，我认为历史上人们把先 SFT 再 RL 作为主要的前沿模型配方，不过 on policy distillation 确实已经进入了很多工作流。我想也有些人对 self-distillation 这类算法非常热衷。我们可以聊聊它什么时候有意义、什么时候没有。但有一个领域，做完整的 on-policy distillation 确实有意义，那就是训练专家模型的时候：你有多个不同的事情希望模型擅长。人们发现，如果你有一堆各不相同的环境，希望一个模型在所有这些上都很强，一个不错的做法是在同一个基础模型之上训练各自独立的 RL 专家，然后把这些教师蒸馏到同一个 checkpoint 里。这通常会更可靠。

然后，有了这些之后，你要部署训练好的模型，它可能是做了全权重训练的完整基础模型，也可能是一个 Lora adapter，你要大规模地提供服务。而这整个过程的价值在于，它不是你只做一次的事情。我想也有人会说："如果前沿模型会变得更好，我为什么还要做后训练？"嗯，你的模型也应该变得更好。一切都会变得更好。重点是拥有能让一切都变得更好的飞轮。所以你真正想要的，不只是像今天这样做一次后训练，而是能有这种迭代式的模型精炼过程，让训练算力只占你整体推理预算中相当小的一部分，并摊销掉，这样随着你从真实世界获得更多信号，你的模型总是越来越好。而从真实世界获取这种信号并不简单。如何把真实世界反馈中的信息带进你的环境，在很大程度上还是个开放问题。这是工程问题，也是研究问题，但这正是我们大家来这个会议要思考和学习的事情。我会在演讲中稍微谈一下我们是怎么想的。但真正的目标是思考这些工具长什么样？你究竟怎么做？有哪些部分？以及我们怎么构建它？

Verifiers V1：任务集、harness 与 runtime

环境作为 evals。什么是环境？我认为把环境分解为任务（task）和 harness 是有用的。这预示着我们过去几个月在 verifiers 中做的一些重构。如果你们有人以前用过 verifiers 库，可能熟悉 multi-turn environment 模式或 tool environment 模式，也就是由环境拥有一个循环，你可以往里插入各种工具。这在很长一段时间里对入门非常好，尤其是在早些时候，人们大多只是想从单轮升级到多轮工具使用。但随着我们对不同模式迭代、以各种方式扩展，我们发现自己在重复大量工作，比如为 CLI agent 添加模式，或为 MCP 添加模式。我们想退一步重新思考：环境应该怎么运作？它真正包含的是 harness 的概念，同时也有任务的概念。我认为这之所以微妙而棘手，也是我们过去 6 个月经过多次迭代的一个设计问题，原因在于有些东西不清楚该归属哪里。有些东西可能既属于 harness 也属于任务。有些工具，在某些情况下是我希望要做的这个任务使用某个工具，在另一些情况下是 harness 自带某些工具。skills、系统提示词，以及在组装你的 agent 或模型将要运行的完整世界时的许多其他拼图碎片也是如此。但最终，我们把所有这些都称为环境的一部分。

目标是有某种验证的概念：你把模型插入包含 harness 的环境中，给它一个任务，它做一次 rollout，然后你验证它做了什么。这同一个过程既适用于离线评估（只是为了弄清哪个模型更好），也适用于强化学习 RL，也适用于为 SFT 生成数据。我认为很多时候人们把 SFT 看作是想上传一个数据集的事，但实际上他们常做的是拼凑出本质上就是环境的东西，在里面做 rollout，离线保存，放成一种格式并上传，再转成另一种格式，然后接入训练器。而我们的做法是说："你完全可以把这些都省掉，把它当作在环境中做 rollout 的问题来处理，只不过这种情况下有一个教师。"教师可以是另一个模型，也可以是从另一个数据集回放。但归根结底是收集 rollout 并在这些 rollout 上训练。
